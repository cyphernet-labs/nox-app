# План клиентского трека — приложение поверх живого сервера

> **Живой трекер.** Подключение Flutter-приложения к client-серверу этапа 1 ([этап 1 завершён](roadmap-stage1.md)) по переходным требованиям контракта §9 ([protocol/contract-draft.md](protocol/contract-draft.md)). Ведётся фичами Spec Kit, нумерация продолжает ряд (последняя — 024). Статусы: `☐` не начата · `◐` в работе · `☑` смёржена.
>
> Создан: 2026-08-27. Ключевой принцип §9: **переходные требования выполняются до DI-флипа 016** — чтобы при флипе репозитории и UI не менялись. Аутентификации нет (этап 1 сервера); фазы 025–026 идут целиком на моках, UI-поведение не меняется (голдены — регрессионная сетка).

## Порядок и зависимости

```
025 wire-alignment ──→ 026 outbox ──→ 027 ws-transport ──→ 028 di-flip
        (моки, UI не меняется)         (транспорт без флипа)   (живой сервер)
```

Каждая фаза заканчивается зелёным `make gate` + `make golden-verify`; 027–028 дополнительно проверяются вручную против локального `noxd` (сборка и смоуки — `client_backend/README.md`).

## Фаза 025 — `client-wire-alignment` ☐

**Цель:** данные приложения говорят на языке контракта, оставаясь на моках.

Скоуп (§9: 1, 2, 4, 5, 7):

- `seq` в моделях сообщения (домен + Sembast + мок-генераторы); сортировка треда и «догрузить старше» — по `seq`/`before_seq` c `has_more` вместо `page/page_size/total`.
- Wire-DTO переписаны 1:1 (`message_id`, unix-секунды, объект `body`, вложение `{file_id, name, size, mime, expires_at}`); поля, которых нет на проводе (`status`, `is_system`, `unread_count`), уходят из wire-слоя; парсинг проверяется фикстурами из **живых кадров `noxd`**.
- Персистентный курсор `since` устройства; `expires_at` в моделях вложения (домен + Sembast) — гейтинг Save.
- `limits` рукопожатия сохраняются в data-слое (шов для композера/пикера); `RepositoryException` расширяется кодами провода §2.1.

**DoD:** гейт + голдены зелёные без изменений UI-поведения; контрактные JSON-фикстуры сериализуются/парсятся дословно; тред пагинируется по `seq` на моках.

## Фаза 026 — `client-outbox` ☐

**Цель:** отправка переживает рестарт и повторяется без дублей.

Скоуп (§9: 3, 6, 8):

- Очередь исходящих переезжает из `ChatThreadBloc` в data-слой (Sembast), работает для всех команд, переживает перезапуск.
- `client_message_id` (UUID) назначается при постановке и персистится с записью очереди; повтор после реконнекта/рестарта — с тем же ключом.
- `MessageRemoteDataSource` приводится к форме контракта: без `authorId`/`authorLabel`, с `client_message_id` и `attachment: {file_id}`.

**DoD:** убить приложение с непустой очередью → рестарт → отправка уходит с прежним `client_message_id`, дублей нет (интеграционный тест на моках).

## Фаза 027 — `client-ws-transport` ☐

**Цель:** живое соединение с конвертом v0 и фазами сессии — ещё без подмены репозиториев.

Скоуп (шапка §9):

- WebSocket-клиент: конверт (`srv`/cmd/reply/event), `session.hello` c `since`, replay с правилом «догнан» (`seq ≥ cursor`), дедупликация по `seq`.
- Фазы сессии `нет сокета → connecting → catching-up → live` как отдельное понятие от «есть ли интернет»; реконнект с экспоненциальным backoff и джиттером, сброс по успеху; keepalive ~25 с.
- Три потребителя `ConnectivityService.watchOnline()` (chats list, thread, chat card) переводятся на фазы сессии; слив очереди — по входу в `live`.
- Блюпринты `04`/`14`/`15`/`16` обновляются с TBD-заглушек на реальную модель (Принцип III).

**DoD:** транспорт-слой против локального `noxd`: hello, replay после обрыва, фазы видны в UI (offline-баннер/«догоняем»); репозитории всё ещё на моках.

## Фаза 028 — `client-di-flip` ☐

**Цель:** приложение работает с живым сервером.

Скоуп:

- `RealChatRemoteDataSource` / `RealMessageRemoteDataSource` поверх транспорта 027; файловый датасорс (`file.uploadBegin` → `PUT` → `message.send{attachment}`; `file.downloadBegin` → `GET` c Range).
- DI-флип тремя шагами по `specs/016-remote-datasource-seam/contracts/di-binding.md`; выбор окружений (какой флейвор смотрит на живой сервер) — решение фичи.
- Сверка live-поведения: merge-не-replace при применении событий, пересчёт непрочитанного от `seq` последнего открытия (§6/§8.3).

**DoD:** dev-приложение против локального `noxd`: список, тред, отправка с офлайн-очередью, файл туда-обратно — вживую; `Environment.test` остаётся на моках, весь тестовый сьют зелёный.
