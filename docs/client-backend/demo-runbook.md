# Демо этапа 2 — как поднять и что показывать

> Всё, что реализовано без TLS: первый запуск и владелец, добавление устройства, приглашение человека. Фаза 036 (`wss` с пиннингом) сюда **не входит** — она меняет транспорт, и до живой проверки остального её в `develop` нет.

## Поднять стенд — одна команда

```bash
./scripts/demo-stand.sh --reset-app
```

Скрипт собирает `noxd`, гасит прошлый стенд, заводит **свежую базу** в `/tmp/nox-demo`, поднимает сервер и печатает всё нужное. Флаг `--reset-app` дополнительно стирает данные macOS-приложения — контейнер **и связку ключей**, потому что связка переживает удаление контейнера, и без этого «чистая» установка запускается уже залогиненной.

Сервер поднимается на `0.0.0.0:8080`, а не на loopback, и это не мелочь: телефон не наберёт `127.0.0.1`, а на дефолтной привязке страница честно не покажет QR вовсе.

## Проверить, что всё работает, ничего не нажимая

```bash
cd client_backend && go run ./cmd/smoke '<ссылка из скрипта>'
```

Проходит весь путь по проводу за пару секунд: захват сервера, второе устройство той же личности, приглашение человека, вопрос на **обоих** устройствах владельца, ответ со второго, вход гостя, переписка, круг из двух человек. Печатает шаги и падает на первом же, который не сошёлся.

⚠️ Смоук **забирает сервер себе**. После него стенд поднимать заново — тем же скриптом.

## Две ссылки, один токен

Скрипт печатает две claim-ссылки, и это не ошибка:

| Ссылка | Для кого |
|---|---|
| с `127.0.0.1` | приложение на **этой же** машине — её печатает вывод запуска |
| с адресом в сети | телефон, снимающий QR **с экрана** — её показывает страница |

Право в них одно и то же — токен совпадает. Разный только адрес, потому что читатели разные.

## Сценарий показа

**1. Первый запуск и владелец.**

```bash
open http://127.0.0.1:8081
fvm flutter run -d macos --dart-define-from-file=config/stage.json
```

На странице — крупный QR и та же ссылка текстом. Вставить ссылку в приложение → `Sign in` → выбрать имя.

Показать: в `Settings` рядом с именем — отметка **`Server owner`**; в списке появилась строка **`People`**, которой у не-владельца нет вовсе. Обновить страницу в браузере — ссылки на ней больше нет, вместо неё состояние машины: версия, аптайм, счётчики, размер базы. Это второе состояние той же страницы.

**2. Добавление устройства.** `Settings` → `Devices` → `Add a device`. Появится QR и ссылка, живут **10 минут**. Второй клиент по ней входит **той же личностью** и **без выбора имени** — это и есть разница между устройством и человеком.

**3. Приглашение человека.** `Settings` → `People` → `Invite a person`. Ссылка живёт **24 часа**. Второй клиент по ней **не входит сразу**: он ждёт, а на устройстве владельца поверх любого экрана всплывает «Someone wants to join».

Показать здесь три вещи:

- вопрос приходит на **все** устройства владельца, и ответ с любого закрывает его на остальных;
- в вопросе **нет ничего о госте** — ни имени, ни платформы: до входа сервер о нём ничего и не знает;
- `Not now` даёт гостю «владелец отклонил», и это **другая** фраза, чем «владелец не ответил».

После `Let them in` гость выбирает имя, и его сообщения у владельца показаны **чужими**, с его именем.

## Если что-то не так

| Симптом | Причина |
|---|---|
| На странице нет QR, только ссылка | Сервер привязан к loopback. Так и задумано: код, который телефон не наберёт, страница не рисует. Поднимай через скрипт |
| Приложение стучится в `127.0.0.1` и получает отказ | Сервер поднят только на LAN-адресе. Скрипт поднимает на `0.0.0.0`, где работает и то, и другое |
| «Чистая» установка сразу залогинена | Связка ключей пережила удаление контейнера. `--reset-app` чистит обе |
| Страница не открывается с другого устройства | Так и должно быть: она слушает только loopback |
| Порт 8080 занят | Погасить прошлый `noxd`; скрипт гасит свой, но не чужой |

## Что в демо не показывать

- **TLS** — фаза 036, трафик пока открытый. На демо это не видно, но говорить, что «всё зашифровано», нельзя.
- **Отзыв человека** из круга — открытый вопрос [Q17](open-questions.md), реализации нет.
- **Восстановление без устройств** — [Q16](open-questions.md), фразы восстановления пока нет: сервер, потерявший все устройства владельца, снова принимает claim, и это единственный путь назад.
