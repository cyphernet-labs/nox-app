## Фаза 022 — `client-backend-bootstrap` ☑

**Цель:** пустой каталог → работающий процесс с конвертом, рукопожатием и живой базой. Ровно срез §10 контракта.

Скоуп:

- Скелет по блюпринту: `main.go` + `internal/{config,db,store,hub,protocol,server}` + `migrations/001_init.sql` (chats, messages, events; STRICT).
- Конверт §2 целиком: четыре вида кадров, диспетчер команд, «ровно один ответ на `id`», коды ошибок §2.1.
- `session.hello`: `limits` + `identity`-заглушка + **replay с `since`** и правилом «догнан» (`seq ≥ cursor`); приветствие `srv` с challenge (подпись игнорируется — этап 1).
- Hub (register/unregister/broadcast, буфер 16, drop-политика) + write pump с ping ~25 с.
- SQLite: два пула, прагмы по CLAUDE.md-инварианту 13, транзакционный outbox, `VACUUM INTO`-бэкап отложен.
- REST-заготовка: `GET /health`. Graceful shutdown полного порядка (инвариант 9).
- Тесты: конверт, hello+replay, drop медленного клиента, shutdown, миграция с нуля.

**DoD:** смоук из контракта §10 проходит двумя `websocat`-терминалами: create → send → событие у второго → kill → send → реконнект с `since` → догон.

## Фаза 023 — `client-backend-chats-messages` ☑

**Цель:** весь готовый набор команд и событий контракта (§4–§6).

Скоуп:

- Чаты: `chats.list` (пагинация/`query`/дедуп-правила §4), `chat.get`, `chat.create`, `chat.rename` (без бампа `last_activity_at`), `chat.nameAvailable` (+`exclude_chat_id`, регистронезависимость), правила поля `name`.
- Сообщения: `messages.list` (`before_seq`), `message.send` — идемпотентность по `client_message_id` (UNIQUE + прежнее эхо), `body?`/`attachment?`-валидация, эхо с `client_message_id`.
- События: `message.new` / `chat.created` / `chat.updated` с полными wire-моделями; свёртка превью по правилу §6; `created_by_label` в `Chat`.
- Тесты: по коду ошибок на команду; идемпотентный повтор; replay-тест с дедупликацией; монотонность `seq`.

**DoD:** полный чат-сценарий из двух websocat-клиентов; `chat.rename` не двигает чат в списке; повторный `message.send` не дублирует строку.

## Фаза 024 — `client-backend-files` ☑

**Цель:** файловая цепочка §7 + `chat.files`.

Скоуп:

- `file.uploadBegin` / `file.downloadBegin` по сокету; `PUT /files/{token}` c `http.MaxBytesReader`, `GET /files/{token}` через `http.ServeContent` (Range из коробки); одноразовые токены с TTL.
- Хранение байтов: каталог данных через `os.Root`; метаданные из `uploadBegin`; сборка `attachment` в эхо/событие; `expires_at`.
- `chat.files` (§4); код `attachment_gone`.
- Тесты: цепочка upload→send→echo; докачка Range; протухший токен; превышение лимита → 413.

**DoD:** файл, отправленный из одного клиента, скачивается вторым по `downloadBegin`+HTTP, с докачкой после обрыва.
