# Протокол обмена

Контракт между приложением и клиентским бэкендом, а в дальнейшем — между клиентским и центральным бэкендом.

**Транспорт:** приложение общается **исключительно** со своим клиентским бэкендом по постоянному двунаправленному соединению (WebSocket поверх TLS), то есть в модели publish/subscribe, а не request/response. Байты файлов и доставка при убитом приложении идут вне сокета — см. `wire-surface.md` §6.

**Чем этот раздел отличается от соседних.** `docs/research/` изучает чужие решения и ничего не предписывает. Здесь — наш собственный контракт: то, что реализуют обе стороны. Пока раздел в состоянии черновика, решения помечены как открытые и ведутся в [реестре](../research/open-questions.md).

Планируется:

- Черновик протокола — конверт, корреляция команда↔ack, коды ошибок, жизненный цикл соединения, версионирование схемы.
- Протокол «клиентский бэкенд ↔ центральный бэкенд» — отдельный контракт, разрабатывается другим инженером.
- Криптография: где заканчивается E2EE, формат полезной нагрузки, управление ключами.
