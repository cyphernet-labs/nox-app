# Карта верхнеуровневых экранов

> Черновик 2026-05-28, обновлён после закрытия всех верхнеуровневых открытых вопросов и ревью 2026-05-29. Названия экранов — рабочие; точные формулировки лейблов в UI определяются в детальных спеках `screens/`.

## Соответствие со структурой Signal

Signal использует нижние табы **Chats / Calls / Stories** + настройки через аватар. В NOX табов меньше, центральный элемент панели — кнопка действия, а не таб, и список чатов — это все чаты человека сразу, без папок и разделов (ревизия 2026-09-10: общего для всех списка не существует).

| Signal | NOX | Комментарий |
|---|---|---|
| Splash + onboarding по номеру + SMS | Splash + анонимное спаривание по ссылке / QR + установка имени | Разделы 1 и 2 |
| Tab Chats | Tab 1 «Chats» (весь список сразу) | В NOX все чаты человека видны на всех его устройствах |
| «New chat» (карандаш) | Центральная «+» | Создание нового чата, разрешения не требует |
| Tab Calls | — | Вне scope |
| Tab Stories | — | Вне scope |
| Settings через аватар | Tab «Settings» | Профиля как отдельного экрана нет |

## Карта экранов NOX

### 1. Запуск

| ID | Экран | Назначение |
|---|---|---|
| 1.1 | **Splash** | Логотип (brand-fixed тёмный фон); проверка состояния авторизации. Если устройство спарено — переход в 4.1 (авто-вход); иначе — в 2.1. |

### 2. Онбординг

| ID | Экран | Назначение |
|---|---|---|
| 2.1 | **Предъявление ссылки спаривания** | Поле для вставки ссылки — ссылки с машины сервера (служебная страница, `noxd link`) или приглашения с другого устройства человека; переключение в режим QR (2.2). Ожидание подтверждения, прерванное закрытием приложения, продолжается отсюда сразу на 2.4. |
| 2.2 | **Сканирование QR** | Камера-сканер той же ссылки; переключение обратно на ручную вставку (2.1). На Windows и Linux камеры нет — там 2.1 читает ссылку с картинки QR-кода. |
| 2.4 | **Подключение к серверу** | После любой читаемой ссылки: адрес сервера и onion-адрес из ссылки — их можно поправить, галочка `Use Tor` (выключена), кнопка `Connect`, которая и спаривает. Причина неудачи — под кнопкой. Ключ сервера не показывается. Приглашение ждёт `Allow` на выдавшем устройстве: экран показывает ожидание и `Cancel`. Детально — [screens/connect.md](screens/connect.md). |
| 2.3 | **Установка имени пользователя** | Показывается только когда спаривание **завело личность** — ссылкой с машины сервера, на котором человека ещё нет; устройству, присоединённому к человеку, имя уже принадлежит, и выбора быть не должно. Сервер уже назначил `User<random>`; экран опционально позволяет изменить имя (лимит 32, проверка символов и длины — **имена не уникальны и на занятость не проверяются**), кнопка «Готово». В дальнейшем редактируется в 7.1. |

Поток первого входа: `1.1 → (2.1 ↔ 2.2) → 2.4 → 2.3 → 4.1`; при спаривании по приглашению — `1.1 → (2.1 ↔ 2.2) → 2.4 (ожидание Allow) → 4.1`, минуя 2.3; по ссылке с машины сервера, на котором человек уже есть, — тоже минуя 2.3.

⚠️ **Смена смысла (фаза 032).** Раньше 2.1 принимал сам идентификатор входа — предъявление секрета делало предъявителя его владельцем. Теперь предъявляется **одноразовая ссылка спаривания**, а устройство заводит собственную пару ключей и доказывает владение подписью; идентификатор входа с провода ушёл.
Поток повторного запуска: `1.1 → 4.1` (авто-вход).
Ошибки входа: нечитаемая ссылка и ссылка новее приложения — **inline** на 2.1; связь, причины неудачи и отказы токена — под `Connect` на 2.4.

### 3. Универсальный экран ошибки

| ID | Экран | Назначение |
|---|---|---|
| 3.1 | **Ошибка** | Параметризован: иконка, заголовок/сообщение, кнопка `Try again`. Два режима: **блокирующий** (без back, последний в стеке — системный back сворачивает приложение) и **встраиваемый** (со стрелкой back). Используется только для fatal / неожиданных ошибок. |

### 4. Основной шелл

| ID | Экран | Назначение |
|---|---|---|
| 4.1 | **Tab bar shell** | Каркас приложения: нижняя панель из трёх элементов — таб «Chats» (5.x), центральная docked-«+» (6.1, видна на обоих табах), таб «Settings» (7.x). Полная спецификация — [screens/tab-bar-shell.md](screens/tab-bar-shell.md). |

Центральный элемент панели — кнопка действия, не самостоятельный таб с собственным состоянием.

### 5. Tab «Chats»

**Модель:** личное пространство одного человека на его собственном сервере. Все его чаты видны на всех его устройствах; «присоединения» нет — присоединяться некому; **удаления нет** ни на каком уровне. Общение с другими людьми уйдёт на relay-сервер и в объём этой итерации не входит.

| ID | Экран | Назначение |
|---|---|---|
| 5.1 | **Список чатов** | Список всех чатов этого сервера с превью последнего сообщения, относительным временем, бейджем непрочитанных (от последнего открытия, cap `99+`). В хедере — **поисковая строка по имени чата**. Точки входа: чат (5.2), создание (6.1, из центра нижней панели). |
| 5.2 | **Лента чата** | Список сообщений (текст + файлы-chip). Каждое сообщение подписано label автора; статус своих — только `sent`. Композер внизу: поле ввода, кнопка вложения, кнопка отправки. Хедер: имя чата, переход в карточку (5.4), **выключенное** действие `Invite a person`. |
| 5.3 | **Просмотр файла** | Иконка типа + имя + размер; auto-download в кэш, сохранение в Downloads. Превью содержимого нет. |
| 5.4 | **Карточка чата** | Имя чата, секция `People` (сам человек + **выключенная** кнопка приглашения), список вложений (List/Grid). Описания, действий «Удалить», ролей нет. |

### 6. Создание чата (центральная «+»)

| ID | Экран | Назначение |
|---|---|---|
| 6.1 | **Создание чата** | Полноэкранная форма: поле «Имя чата» (лимит 64, **валидация уникальности в реальном времени в пределах своего сервера** — занятое имя выбрать нельзя), кнопка «Создать». После создания — сразу в 5.2 нового чата. |

«Присоединение к чату» как отдельный поток отсутствует.

### 7. Tab «Settings»

Отдельного экрана профиля нет; всё, что обычно относится к профилю, размещено здесь.

| ID | Экран | Назначение |
|---|---|---|
| 7.1 | **Корень настроек** | Карточка идентичности (имя пользователя + `Your ID`), затем плоский список: Devices, Connection, Notifications, Appearance, Language, Terms, About, Log out. |
| 7.2 | **Уведомления** | Один переключатель push (on/off); push по чатам своего сервера — отбора «только свои» больше нет, все свои (ревизия 2026-09-10). |
| 7.3 | **Внешний вид** | Тема: System / Light / Dark. |
| 7.4 | **Язык** | System / English / Українська. |
| 7.5 | ~~**Поддержка**~~ | **Вне scope текущей версии.** |
| 7.6 | **Terms** | Юридическая информация (bundled), футер — версия приложения. |
| 7.7 | **О приложении** | Только версия + build. |
| 7.8 | **Устройства** | Список устройств личности (семейство ОС, когда привязано, когда было на связи), отзыв любого из них и выпуск приглашения для нового — QR и ссылка, живут 10 минут и срабатывают только после `Allow` на этом устройстве (8.2). Отзыв **своего** устройства — это выход из аккаунта, и говорит он копирайтом выхода. |
| 7.10 | **Связь** | Адрес сервера, onion-адрес (правка — кнопкой `Save`) и `Use Tor` (применяется сразу); после любой применённой правки приложение подключается заново. Пока связи нет — строка с причиной. Детально — [screens/connection.md](screens/connection.md). |

⚠️ **Фаза 037 сняла 7.9 «Люди» и 8.1 «Запрос на подтверждение».** Сервер принадлежит одному человеку, приглашать на него некого, отметка `Server owner` перестала что-либо различать. Спецификации удалены; см. [screens/README.md](screens/README.md).

### 8. Поверх любого экрана

| ID | Экран | Назначение |
|---|---|---|
| 8.2 | **Запрос нового устройства** | Диалог на устройстве, выпустившем приглашение: `New device: {platform}. Allow it to join?` с `Deny` и `Allow`. Поверх любого экрана вошедшего приложения, пока оно открыто и на связи; отложить нельзя; уходит, когда запрос закрылся любым исходом. Детально — [screens/pair-request.md](screens/pair-request.md). |

Номер 8.1 не переиспользуется — по той же причине, что 7.9: под ним в спецификациях фаз 034 и 037 остаётся запрос на подтверждение человека.

Пункт «Logout» в корне (7.1) — действие с диалогом подтверждения, без отдельного экрана. **Полностью очищает идентификатор и локальные данные с устройства**; в диалоге подтверждения это явно проговорено в копирайте. С фазы 032 выход вдобавок **отзывает собственный ключ на сервере**, если связь есть: иначе ключ остался бы дверью, о которой никто не помнит.

#### Блок имени пользователя в корне настроек (внутри 7.1)

- Показ текущего label; inline-редактирование с проверкой символов и длины (лимит 32 символа). **Уникальность не проверяется** — имена людей не уникальны (решение владельца 2026-09-02), а с фазы 037 на своём сервере ещё и сравнивать не с кем; поэтому нет ни спиннера проверки, ни отказа «занято». Отметки владения рядом с именем нет: она различала бы владельца и приглашённого, а приглашённых больше не бывает.

#### Блок идентификатора в корне настроек (внутри 7.1)

- Показ `Your ID` **целиком**, моноширинным. Действий у карты **два**: `Edit name` и `Copy ID`.
- ⚠️ **С фазы 032 маски нет**: `Your ID` — публичный идентификатор личности, выданный сервером, а не секрет входа; прятать нечего, поэтому `Show`/`Hide` убраны.
- ⚠️ **`Show QR` убран совсем**, а не перенаправлен: QR идентичности раздавал бы предъявительский секрет, а добавление устройства — это отдельный экран **7.8**, куда ведёт свой пункт списка, и там приглашение выпускается настоящим одноразовым токеном. На самой карте QR нет.

## Глобальная навигация — решение

Принято: **нижняя панель из трёх элементов** — Chats / «+» (docked FAB) / Settings. Альтернатива «без нижней панели» отклонена. Поведение панели — в [4.1](screens/tab-bar-shell.md).

## Принятые решения

Полная таблица — в [overview.md](overview.md#принятые-решения). Ключевое на уровне карты:

- Авто-вход; идентификатор хранится локально; имя (`User<random>`) есть всегда.
- Спаривание — ссылкой; любая читаемая ссылка ведёт на экран подключения 2.4. Ссылка с машины сервера спаривает сразу, приглашение — после `Allow` на выдавшем устройстве (8.2).
- Путь до сервера — сначала напрямую; через Tor — только с включённой `Use Tor` (2.4, 7.10).
- Одна идентичность на устройство.
- Термины UI: «чат», `Your ID`, `Sign in` / `Log out`.
- Splash — brand-fixed тёмный (исключение из темизации).
- Центральная «+» — docked FAB, видна на обоих табах.
- Маска идентификатора — 8 точек фиксированной длины.
- Logout — полная очистка.
- Лимиты имён: label 32, имя чата 64. Имя чата уникально **в пределах своего сервера**; label на занятость не проверяется.
- Удаление чата невозможно.
- Статус сообщений — только `sent`; непрочитанные — от последнего открытия (`99+`); push — по чатам своего сервера, отбора «только свои» больше нет (все свои).
- В списке чатов — поисковая строка по имени.

## Открытые вопросы

На уровне верхнеуровневой карты экранов открытых вопросов нет. Оставшееся — артефакты дизайн-системы (палитра, типографика, токены, логотип, иллюстрации empty-states), готовятся отдельным блоком перед макетами.
