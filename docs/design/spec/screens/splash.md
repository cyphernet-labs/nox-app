# 1.1 Splash

> Детальная спецификация экрана. Часть [карты экранов](../top-level-screens.md). Общие решения — в [overview.md](../overview.md). Все верхнеуровневые открытые вопросы по 1.1 закрыты 2026-05-28.

## Назначение

Стартовый экран приложения. Показывает лого с подписью «NOX», проигрывает короткую анимацию появления, проверяет состояние авторизации и маршрутизирует пользователя дальше.

## Контекст и переходы

- **Откуда:** **только холодный старт** приложения (запуск с нуля после kill, открытие из иконки, открытие по push, когда процесс не висит в памяти). При **тёплом возврате из бэкграунда** splash **не показывается** — пользователь сразу возвращается на экран, на котором был.
- **Куда:**
  - устройство спарено и шаг выбора имени пройден → **4.1 Tab bar shell** (авто-вход);
  - устройство спарено, шаг выбора имени не пройден → **2.3 Установка имени пользователя**;
  - устройство не спарено → **2.1 Вход по ссылке спаривания**; оттуда же продолжается ожидание подтверждения, прерванное закрытием приложения (2.1 сразу открывает [2.4](connect.md));
  - ключ локальных данных потерян, а данные на месте — база, которую ключ не открывает, или база без ключа (фаза 048) → данные стираются, сессия тоже, и открывается **2.1** — устройство спаривается заново;
  - ошибка чтения сессии, когда хранилище на старте уже ответило, → «не спарено» (**2.1**), а не падение (фаза 009, FR-015).

**Маршрута на 3.1 из splash нет:** ни одна ошибка старта не ведёт на экран ошибки.

Пока системное хранилище секретов не отвечает на старте, splash **остаётся на экране**, и приложение спрашивает хранилище снова — через 2, 4, 8, 16, 30… с. Из-за хранилища, которое не отвечает, ничего не стирается (фаза 048). Исключение — Android: хранилище, которое не ответило и на пятую попытку подряд (около полуминуты), считается потерявшим ключ — данные стираются, открывается 2.1. Переход к следующему экрану происходит **не раньше, чем завершится анимация появления** (см. ниже) — даже если состояние авторизации проверено быстрее. Возврат на splash из других экранов не предусмотрен.

## Лейаут

- Полноэкранный Material-Scaffold. Фон — токен **`brand/canvas-dark` (#0C2424)**, фиксированный (**не** из `ColorScheme`): splash одинаков в светлой и тёмной теме. Это одно из двух исключений из темизации (второе — QR-код приглашения в 7.8; см. [design-system](../design-system.md)).
- В геометрическом центре экрана — **цветной логотип NOX** (168, одинаковый на узкой и широкой ширине). Стилистический ориентир — маска в разноцветных штрихах на тёмном фоне.
- Непосредственно под лого — wordmark **«NOX»**: Roboto Bold, размер 28, цвет `brand/white`.
- Между лого и wordmark — отступ 16.
- Системные status bar и navigation bar отображаются прозрачно поверх фона (edge-to-edge).
- На экране нет других элементов: текста, кнопок, индикаторов прогресса.

## Анимация появления

Лого и wordmark анимируются **параллельно (вместе)** как единая группа: два эффекта одновременно.

| Параметр | От | До |
|---|---|---|
| Прозрачность (opacity) | 0 | 1 |
| Scale | 0.85 | 1.0 |

Параметры:

- **Длительность** — ~400 мс.
- **Easing** — decelerated (M3 «emphasized decelerate»). Метафора «появление из ниоткуда» — быстрое начало, мягкое замедление к финалу.
- **Точка отсчёта scale** — геометрический центр группы (лого + wordmark).
- После завершения — статика. Никаких циклических / loop-эффектов, никаких пульсаций.

## Состояния

| Состояние | Описание | UI |
|---|---|---|
| Routing | Splash виден от старта приложения до маршрутизации | Лого + wordmark, в процессе и после анимации |
| Waiting-store | Системное хранилище секретов ещё не отвечает | Лого + wordmark остаются; приложение повторяет запрос через 2, 4, 8, 16, 30… с (на Android пятая неудача подряд — потерянный ключ) |

Отдельного состояния «загрузка» нет: индикатор прогресса не показываем. Если состояние авторизации проверено до окончания анимации, маршрутизация всё равно дожидается её завершения.

## Взаимодействия

- Экран пассивный: тапы, свайпы и системные жесты back не вызывают действий.
- Системные жесты ОС работают штатно (свернуть приложение, переключиться на другое).

## Material-компоненты

- `Scaffold` — корневой контейнер с **фиксированным тёмным бренд-фоном** (не зависит от `ColorScheme` / темы).
- `Image` или `SvgPicture` — логотип.
- `Text` — wordmark «NOX» (Roboto Bold, поставляется с приложением).
- Анимация — через `AnimationController` + `FadeTransition` + `ScaleTransition` (стандартные Flutter-примитивы; внешний пакет вроде Lottie на этом этапе избыточен).

## Принятые решения (Q1–Q5)

| # | Вопрос | Решение |
|---|---|---|
| Q1 | Логотип: монохром / цвет | Цветной; референс — `assets/logo-reference.png` |
| Q2 | Шрифт wordmark | Без отдельного бренд-шрифта: Roboto Bold, тот же, что во всём приложении (поставляется с приложением на всех платформах) |
| Q3 | Параметры анимации | Baseline: ~400 мс, decelerated, scale 0.85 → 1.0 |
| Q4 | Порядок лого / wordmark | Параллельно (единая группа) |
| Q5 | Восстановление из бэкграунда | Splash только при холодном старте; при тёплом возврате — сразу прежний экран |
| — | Тема splash | Brand-fixed **всегда тёмный** (исключение из темизации; фон не из `ColorScheme`) |
