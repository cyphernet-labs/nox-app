# 5.3 Просмотр файла

> Детальная спецификация экрана. Часть [карты экранов](../top-level-screens.md). Общие решения — в [overview.md](../overview.md). Все верхнеуровневые открытые вопросы по 5.3 закрыты 2026-05-29.

## Назначение

Экран файла-вложения: его скачивание в кэш при открытии, показ (картинка, видео) и сохранение копии в место, выбранное человеком.

Экран, который уже скачал байты, показывает их (решение владельца 2026-09-20):

- **Картинка** — рисуется вместо глифа (тот же предикат формата, что у миниатюры в 5.2: формат, который там остаётся чипом, здесь остаётся глифом, а не превращается в «битую картинку» на одном экране из двух). Ошибка декодирования → глиф, как и в треде.
- **Видео** — **проигрывается здесь же**: кадр, play/pause, полоса прогресса с перемоткой, таймкод `позиция / длительность`. Играет **только из локального файла** — нативный плеер ходит собственным HTTP-стеком мимо канала Rust-модуля, то есть мимо проверки `POST /auth` → `POST /auth2`, а клиентский сервер до этой проверки ни на что не отвечает; байты приносит та же цепочка скачивания, что и для любого файла.
- Все прочие типы — глиф типа, имя, размер.
- Файл, который пришёл целиком, но не играется здесь (кодек, которого нет у платформы), говорит об этом фразой `Couldn't play this video. Save it to open it in another app.` — это утверждение о файле, а не пустой прямоугольник.

**Файл на устройстве зашифрован (фаза 048).** Картинка расшифровывается для показа в память. Видео плеер играет из **временной открытой копии** во временной папке приложения: экран делает её, когда байты на месте (пока она делается — ожидание плеера), и стирает, когда закрывается вместе с плеером; оставшиеся копии стираются при каждом запуске и при выходе. Копию, которую сделать нельзя — нет места на диске, — экран называет на месте плеера фразой `Couldn't open this file. Free up some space and try again.`: файл при этом цел, `Save` доступен, повтор — закрыть экран и открыть снова.

⚠️ **Плеер есть не везде, и это решение владельца, а не недоделка.** `video_player` реализован для **iOS, Android и macOS**; для Windows и Linux реализаций нет вовсе. На них 5.3 показывает для видео глиф, имя, размер и `Save` — и ничего не обещает. Альтернатива `media_kit` закрыла бы все пять, но тянет libmpv нативными библиотеками и добавила бы именно те две платформы, которые здесь нельзя проверить (P15/P17 отложены по той же причине). Предикат один — `VideoPlaybackCapability`.

## Контекст и переходы

- **Откуда:** 5.2 Лента чата — тап на файл-chip или на место ещё не пришедшей картинки; 5.4 Карточка чата — тап на файл в списке вложений.
- **Куда:**
  - Back / back-стрелка → возврат туда, откуда открыли.
  - В 3.1 экран не уходит. **Исчезнувший файл** — терминальное состояние на самом 5.3 (контракт §2.1): потерять одно вложение не повод отнимать у человека переписку, в которой он был.

## Лейаут

Material Scaffold; адаптируется под тему. Сверху вниз:

1. **AppBar (M3):** сплошной, цвет — `ColorScheme.surface` (адаптируется под тему). Слева — back-стрелка; title — имя файла (ellipsis при переполнении); справа — иконка `Save`.
2. **Body:** центрированная column:
   - крупный глиф типа файла в тонированном квадрате по **единому маппингу** из [overview.md / Файлы](../overview.md#файлы-иконки-типов-и-превью) — или скачанная картинка, или плеер видео (см. «Назначение»);
   - filename (`Title Large`, по центру, перенос если длинный);
   - строка под именем: размер файла (например `2.4 MB`); пока идёт скачивание — `Downloading… N%`; при отказе — текст ошибки цветом `error`.
3. **Loading-индикатор:** во время auto-download — горизонтальный `LinearProgressIndicator` с определённым % под AppBar.

## Состояния

| Состояние | Описание |
|---|---|
| Loading | Auto-скачивание в кэш. Linear progress bar (определённый %) — доля **всего** файла, вместе с тем, что уже было на устройстве. `Save` в AppBar disabled. Обрыв связи — не ошибка: полоса стоит и продолжает сама, с того байта, где остановилась. |
| Loaded | Файл закэширован. `Save` enabled. Progress bar скрыт. |
| Inline-error | Скачивание сдалось: сервер раз за разом отказывал, и автоматические повторы исчерпаны. Обрыв связи сюда **не** ведёт. Строка под именем — текст ошибки цветом `error`, плюс `SnackBar` (error-вариант) с действием `Try again` (см. [overview.md / Уровни ошибок](../overview.md#уровни-ошибок-и-обратной-связи)); повтор начинает повторы заново и продолжает с того, что уже на устройстве. |
| Terminal | Байтов на сервере больше нет (`attachment_gone`, либо файла не существует). Строка под именем — `This file is no longer on the server` цветом `error`, **без кнопки повтора** — повторять нечего. Контракт §2.1: «Терминальное error-состояние экрана файла (5.3), без кнопки повтора — **не** фатальный экран всего приложения». |
| Open-error (видео, фаза 048) | Байты на устройстве, плеер есть, но временную открытую копию для него сделать нельзя (нет места на диске). На месте плеера — `Couldn't open this file. Free up some space and try again.` цветом ошибки; имя, размер и `Save` — как в Loaded. Обе ширины. |

При открытии экрана: если файл уже в кэше — сразу состояние Loaded; иначе Loading → Loaded.

Скачивание принадлежит приложению, а не экрану: закрытый экран его не останавливает. Открыв файл снова, человек видит прогресс того же скачивания или готовый файл.

## Взаимодействия

- **Открытие экрана** → если файл не в кэше, запускается auto-скачивание; прогресс отображается линейным баром с %.
- **Тап на `Save` в AppBar** → файл записывается **открытым** (расшифрованным, фаза 048) в место, выбранное в системном диалоге сохранения, + snackbar `File saved`: файл лежит там, куда человек его сохранил. Отменённый диалог ничего не пишет; сбой записи — snackbar `Could not download file. Check your connection and try again.`. Диалог у каждой платформы свой: на iOS — экспорт в «Файлы», на Android — системный выбор места и имени файла, на десктопах — диалог «Сохранить как». Повторный тап, пока идёт сохранение, ничего не делает: на телефоне файл сначала готовится для диалога, и второй тап открыл бы второй диалог.
- **Тап на back** → возврат туда, откуда открыли.
- **Long-press на icon / filename** — no-op на этом этапе.
- **Share** — отсутствует на этом этапе.
- **Open in external app** — отсутствует на этом этапе.

## Material-компоненты

- `Scaffold`.
- `AppBar` (M3) — сплошной (`ColorScheme.surface`); адаптируется под тему.
- `IconButton` — `Save` в actions AppBar.
- Глиф типа файла (Material Symbols Rounded) в тонированном квадрате — крупно в body.
- `Image` — скачанная картинка; плеер видео с play/pause, полосой прогресса и таймкодом (iOS, Android, macOS).
- `Text` — filename и размер.
- `LinearProgressIndicator` — Loading.
- `SnackBar` (M3) — confirmation после Save, inline-error.

## Десктоп-раскладка

> Сведена с `nox-desktop-screens/screens/08-file.md`.

- Десктоп (`>= 840dp`): просмотр файла — центрированный **lightbox-`Dialog` до 520** со scrim (`showFileView`): шапка (глиф типа + имя `Title Medium` + close, hairline под шапкой), под ней полоса прогресса во время скачивания, затем то же тело — глиф или картинка или плеер, имя, размер — и кнопка `Download` на всю ширину (пока скачивается — `Downloading… N%`, недоступна); `Download` делает то же, что `Save` на узкой ширине. Мобайл — fullscreen push (AppBar back + имя + `Save`).
- Прогресс-бар заполняется по ходу настоящей передачи байтов; скачивание продолжается с того места, где остановилось (фаза 043).
