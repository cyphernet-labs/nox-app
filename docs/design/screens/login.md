# 2.1 Вход по идентификатору

> Детальная спецификация экрана. Часть [карты экранов](../top-level-screens.md). Общие решения — в [overview.md](../overview.md). Все верхнеуровневые открытые вопросы по 2.1 (Q1–Q9) закрыты 2026-05-28.

## Назначение

Точка ручного ввода длинного идентификатора пользователя. Показывается при первом запуске и после Logout. Альтернатива ручному вводу — сканирование QR (2.2), доступное с этого же экрана как переключатель режима.

## Контекст и переходы

- **Откуда:**
  - 1.1 Splash — если идентификатор не сохранён локально (первый запуск или после Logout с полной очисткой).
- **Куда:**
  - **2.2 Сканирование QR** — по тапу `Scan QR`.
    - **Возврат через back / `Enter manually`** — содержимое поля 2.1 сохраняется.
    - **Возврат после успешного скана** — 2.2 закрывается автоматически, распознанный идентификатор подставляется в поле 2.1 и **сразу** отправляется на проверку (override 2.1 Q5 «только по тапу»: сам акт скана — действие пользователя, эквивалентное submit'у).
  - **2.3 Установка имени пользователя** — при первом успешном входе под этим идентификатором.
  - **4.1 Tab bar shell** — при повторном успешном входе под уже зарегистрированным идентификатором.
  - **3.1 Универсальный экран ошибки** — для **fatal** ошибок (server 5xx, неожиданная) со стрелкой back.

**Системный back / жест back** — свернуть приложение (стандарт корневого экрана; `SystemNavigator.pop`).

## Лейаут

Material Scaffold с `resizeToAvoidBottomInset: true`; фон — `ColorScheme.surface`. Сверху вниз:

1. **Верх:** Material 3 `AppBar` с wordmark `NOX`. Тип и высота — за дизайн-системой.
2. **Центр:** многострочное поле ввода идентификатора (text wrap, поле растёт по высоте по мере набора). Внутри поля или рядом — suffix-иконка `Paste`. При наличии ошибки — `errorText` под полем.
3. **Низ:** primary `FilledButton` `Sign in` на всю ширину, под ним secondary `TextButton` `Scan QR` (центрирован).

При фокусе поля клавиатура поднимается; контент сжимается под видимую область. AppBar может уменьшаться или сворачиваться согласно дизайн-системе, primary action остаётся виден.

## Состояния

| Состояние | Описание |
|---|---|
| Empty | Поле пустое. `FilledButton` `Sign in` disabled. Кнопка `Paste` disabled (буфер пуст). |
| Filled | В поле есть содержимое (любой длины и формата — клиент не валидирует). `Sign in` enabled. Кнопка `Paste` enabled, если в буфере что-то есть. |
| Loading | Идёт запрос на проверку. Поле и обе кнопки disabled; внутри primary button — `CircularProgressIndicator`. |
| Inline-error | Сервер вернул «неверный формат» или произошла ошибка сети. Поле подсвечено error-цветом, под ним — `errorText`. Кнопки возвращаются в enabled. |
| Fatal | Неожиданная / server-fatal (HTTP 5xx, не-detail-error) → передача в 3.1 со стрелкой back. |

Граница между Inline-error и Fatal: всё, что сервер возвращает как «ошибку формата» или «нет сети» — inline. Всё, что выходит за классы, — Fatal → 3.1.

## Взаимодействия

- Тап в поле → системная клавиатура поднимается.
- **`Paste`** — всегда отображается. Disabled, если буфер обмена пуст. При тапе вставляет содержимое буфера в поле.
- **`Sign in`** — отправляет идентификатор на проверку. Auto-submit нет — отправка только по явному действию пользователя.
- Enter / Go на программной клавиатуре — эквивалент тапу `Sign in`.
- **`Scan QR`** — переход в 2.2.
  - При возврате через back / `Enter manually` поле восстанавливается с сохранённым содержимым.
  - При успешном скане 2.2 закрывается автоматически; распознанный идентификатор подставляется в поле и сразу отправляется на проверку (override auto-submit-правила для QR-flow).
- **Системный back** — свернуть приложение.

## Material-компоненты

- `Scaffold` с `resizeToAvoidBottomInset: true`.
- `AppBar` (M3) с wordmark `NOX`.
- `TextField` (M3 outlined), многострочный (`maxLines: null` или большое значение), без `obscureText`. Suffix — `IconButton` `Paste`. `helperText` / `errorText` — стандартные.
- `FilledButton` — primary action.
- `TextButton` — secondary action.
- `CircularProgressIndicator` (внутри primary button) — Loading.

## Принятые решения (Q1–Q9)

| # | Вопрос | Решение |
|---|---|---|
| Q1 | Формат поля ввода | Многострочное (text wrap) |
| Q2 | Видимость ввода | Открытый текст, без маски |
| Q3 | Клиентская валидация | Не валидируем — только серверная |
| Q4 | Кнопка `Paste` | Всегда видна, disabled при пустом буфере |
| Q5 | Auto-submit | Ручной ввод — только по тапу `Sign in` / Enter. **Исключение:** QR-success → программный submit (см. [qr-scan.md](qr-scan.md)) |
| Q6 | Хедер экрана | M3 AppBar с wordmark `NOX` |
| Q7 | Системный back | Свернуть приложение |
| Q8 | Возврат из 2.2 | Содержимое поля сохраняется |
| Q9 | Inline-error vs 3.1 | Формат / сеть — inline; fatal — 3.1 |
