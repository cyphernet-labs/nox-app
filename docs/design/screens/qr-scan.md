# 2.2 Сканирование QR

> Детальная спецификация экрана. Часть [карты экранов](../top-level-screens.md). Общие решения — в [overview.md](../overview.md). Все верхнеуровневые открытые вопросы по 2.2 закрыты 2026-05-29.

## Назначение

Альтернатива ручному вводу идентификатора (2.1) — сканирование QR-кода, в котором закодирован тот же идентификатор. После успешного распознавания 2.2 **закрывается автоматически**, идентификатор подставляется в поле 2.1 и **сразу** отправляется на проверку (программный submit).

## Контекст и переходы

- **Откуда:**
  - 2.1 Вход по идентификатору — по тапу `Scan QR`. Содержимое поля 2.1 при этом сохраняется (см. 2.1 Q8).
- **Куда:**
  - **2.1 Вход по идентификатору + auto-submit** — при успешном распознавании QR. 2.2 автоматически закрывается, распознанный идентификатор подставляется в поле 2.1, и происходит программный submit (override стандартного правила 2.1 Q5 «только по тапу»: сам акт скана — действие пользователя, эквивалентное submit'у). Дальнейший маршрут (2.3 / 4.1 / inline-error) управляется логикой 2.1.
  - **2.1 Вход по идентификатору** (без submit) — по тапу `Enter manually`, по back-стрелке в AppBar или системному back. Поле 2.1 возвращается с ранее введённым содержимым.
  - **3.1 Универсальный экран ошибки** — для fatal-сценариев (отказ системного уровня на доступ к камере, server-fatal).

## Лейаут

Полноэкранный Scaffold. Сверху вниз:

1. **AppBar (M3):** сплошной; цвет берётся из текущей темы через `ColorScheme` — тёмный в dark mode, светлый в light mode. Слева — back-стрелка. В actions — иконки фонарика (toggle) и переключения камеры (toggle front/back).
2. **Подложка:** live-видео с камеры заполняет область под AppBar до низа экрана.
3. **Overlay-инструкция:** в верхней зоне видео поверх — текст `Aim your camera at a QR code`.
4. **Прицел:** квадратное окно-«прицел» в центре, остальная площадь затемнена (mask).
5. **Низ:** secondary action `TextButton` `Enter manually` (возврат в 2.1 без submit).

Камера активна всё время, пока экран на переднем плане.

## Состояния

| Состояние | Описание |
|---|---|
| Permission-prompt | Системный диалог запроса доступа к камере (управляется ОС). |
| Permission-denied | Доступ к камере отклонён. **Blocking-overlay** прямо на 2.2: пояснение и кнопка `Open settings`. |
| Scanning | Камера активна, прицел отображается. Кастомного UI-feedback'а нет — поведение библиотеки сканера остаётся как есть. |
| Inline-error | QR распознан, но содержимое не валидно как идентификатор. **Snackbar внизу** с сообщением; сканирование продолжается. |
| Fatal | Камера недоступна на уровне устройства → передача в 3.1. |

Отдельного «Detected» состояния с кастомным feedback'ом нет: после успешного распознавания сразу запускается closing-flow к 2.1.

## Взаимодействия

- Открытие экрана → запрос доступа к камере (если ещё не получен).
- Тап **иконки фонарика** в AppBar → toggle вспышки on/off.
- Тап **иконки переключения камеры** в AppBar → переключение front ↔ back.
- Тап **`Enter manually`** → возврат в 2.1 (без submit); содержимое поля 2.1 сохранено.
- Тап **back-стрелки** в AppBar или системный back → возврат в 2.1 (без submit).
- **Распознавание QR (success):**
  1. Камера останавливается (single-shot).
  2. Без звука и вибрации.
  3. Без кастомного UI-feedback'а на прицеле.
  4. 2.2 автоматически закрывается, управление передаётся 2.1.
  5. 2.1 получает идентификатор в поле и сразу запускает submit.
- **Распознавание QR (валидный код, но содержимое не подходит):** snackbar внизу; камера продолжает сканировать.

## Material-компоненты

- `Scaffold`.
- `AppBar` (M3) — сплошной, цвет `ColorScheme.surface`; адаптируется под тему. `IconButton` actions для фонарика и переключения камеры; back-стрелка по умолчанию.
- Сторонний пакет для сканирования (например `mobile_scanner`) — в Material нет встроенного компонента; конкретный выбор — решение технического этапа.
- `TextButton` — `Enter manually`.
- `SnackBar` (M3) — inline-error.
- `Text` — инструкция и сообщения в Permission-denied overlay.
