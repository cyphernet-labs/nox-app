# Документация NOX

Входная страница документации NOX: что это за продукт, в каком он состоянии и где что описано.

**NOX** — кросс-платформенный мессенджер для iOS, Android, Windows, Linux и macOS (web — вне рамок) на Flutter (Dart) со сквозным шифрованием. Ориентир — Signal. Русское рабочее название в материалах — «Секюрный Мессенджер». Репозиторий — `cyphernet-labs/nox-app`.

## Модель продукта

Пространство NOX — **личное**: клиентский сервер принадлежит одному человеку и обслуживает только его собственные устройства; все чаты человека видны на всех его устройствах и больше нигде. Серверы разных людей между собой не соединяются. Всё, что между разными людьми, пойдёт через релей, протокол которого ещё не существует ([Q13](client-backend/open-questions.md), блокирующий), и в текущие рамки не входит; единственный видимый след — навсегда выключенное действие `Invite a person` в шапке чата и в карточке чата. Подробно — [design/spec/overview.md](design/spec/overview.md).

## Состояние

- **Приложение** (`lib/`): экраны спецификации дизайна на обеих ширинах; реактивные список чатов и лента; очередь исходящих, которая переживает перезапуск; чат, который создаётся и без связи; файлы с докачкой в обе стороны; картинки в ленте и видео в приложении (видео — на iOS, Android и macOS); интерфейс на английском и украинском. Сборка `stage` работает с живым клиентским сервером, `prod` — на моках поверх локальной базы, пока нет боевого адреса.
- **Клиентский сервер** (`client_backend/`): Go и встроенная SQLite. Провод — контракт v0 ([client-backend/protocol/contract-draft.md](client-backend/protocol/contract-draft.md)): WebSocket-конверт для команд и событий (`wss`), HTTPS для байтов вложений.
- **Канал.** Каждое соединение — TLS 1.3 и сразу за ним проверка `POST /auth` → `POST /auth2`: приложение сверяет ключ сервера с ключом из ссылки спаривания `nox://pair/`, сервер пускает спаренное устройство ко всему, а незнакомый ключ — только к спариванию. На стороне приложения канал целиком живёт в Rust-модуле `packages/nox_tor`; ключи и подписи считает RustSecureBox (`packages/rust_secure_box`) — одна библиотека на Rust у приложения и у сервера, пока заглушка. Адреса сервера с портами приезжают ссылкой.
- **Tor.** Дома приложение ходит к серверу напрямую, вне дома — через встроенный Tor к onion-сервису сервера, если у человека включено `Use Tor`. Onion-сервис публикует tor — отдельная служба ОС на машине сервера; клиентский сервер его не запускает и хранит только свои адреса.
- **Спаривание.** Ссылка с машины сервера (служебная страница или `noxd link`) спаривает сразу: так появляется первое устройство и так возвращается человек, потерявший все устройства. Приглашение со своего устройства спаривает новое только после `Allow` на выдавшем. Отзыв — с любого устройства.
- **Данные на диске.** База и вложения сервера зашифрованы ключом данных, который отпирает пароль сервера: после каждого запуска сервер заперт, пока пароль не введён. На устройстве база и файлы зашифрованы ключом, который хранится только на этом устройстве, и в системные бэкапы не попадают.
- **Установка сервера** — скриптом на Linux, macOS и Windows вместе с tor ([deploy/README.md](../deploy/README.md)).

Фичи 001–050 — в ветке `develop` (034 отменена); переделка безопасности, фичи 044–050, слита в `develop` 2026-10-19 (PR #38). Открыты: протокол с релеем (Q13), граница сквозного шифрования (Q1), push (Q2), ATS и App Review для личного сервера, канал которого идёт через собственный Rust-модуль приложения (Q14) — реестр [client-backend/open-questions.md](client-backend/open-questions.md). Рабочий режим и принципы — в конституции (`.specify/memory/constitution.md`) и `CLAUDE.md`.

## Соглашения

- Язык документации в `docs/` и `specs/` — русский.
- Код, идентификаторы, имена файлов, комментарии в коде, сообщения коммитов и названия веток — английский; `CLAUDE.md` и `AGENTS.md` — тоже.
- Строки интерфейса — всегда английские, даже внутри русского текста. Языки интерфейса приложения — английский и украинский; русского в интерфейсе нет.
- Не смешиваем языки внутри одного артефакта: код остаётся английским даже когда упоминается в русском тексте, и наоборот.
- Имя продукта в UI и в прозе — **NOX** (все заглавные буквы); сервер человека в прозе — «клиентский сервер».
