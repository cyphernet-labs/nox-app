# Data Model: Стартовая и статусная страница сервера

**Фаза 1** для [plan.md](./plan.md). Решения — в [research.md](./research.md).

## Схема не меняется

Ни одной новой таблицы, колонки или индекса. `001_init.sql` не трогается. Страница только читает.

## Что читается

| Сведение | Откуда | Примечание |
|---|---|---|
| Забран ли сервер | `ReadOwnershipState` | **тот же** предикат, что у claim-ссылки в выводе запуска (Р4) |
| Идентификатор хранилища | `journal_id` из `server_identity` | уже есть, едет в приветствии |
| Версия схемы | `PRAGMA user_version` | то, что вернул мигратор при старте |
| Людей | `COUNT(1) FROM users` | |
| Устройств | `COUNT(1) FROM devices` | |
| Чатов | `COUNT(1) FROM chats` | |
| Сообщений | `COUNT(1) FROM messages` | |
| Размер базы | `os.Stat(cfg.DBPath)` | размер файла, без WAL (Р7) |
| Версия и билд | `runtime/debug.ReadBuildInfo()` | ревизия, время, «грязное» дерево (Р3) |
| Аптайм | от момента старта процесса | |
| Предупреждения старта | собранные в `Run` | Р8 |

**Чего не читается вообще**: `users.label`, `chats.name`, `messages.body`, `messages.author_label`, `devices.device_key`, `pair_tokens.token`. Их нет в запросах — не «не показываются на странице», а не покидают базу.

## Новые типы Go

### `store.Counts`

`People`, `Devices`, `Chats`, `Messages` — четыре целых, одним чтением. Отдельный тип, а не четыре вызова, потому что показываются они вместе и разъехаться не должны.

### `server.machineStatus`

Всё, что страница показывает, собранное в одном месте: состояние владения, идентификатор хранилища, версия схемы, счётчики, размер, версия, аптайм, предупреждения. Собирается на каждый запрос — страница живёт ровно столько, сколько её смотрят.

### `server.statusListener`

Второй `http.Server` со своим мультиплексором. Поднимается в той же группе, что основной, и гасится в том же порядке — до закрытия базы (инвариант 9).

## Конфигурация

| Поле | Флаг | По умолчанию | Правило |
|---|---|---|---|
| `StatusAddr` | `-status-addr` | `127.0.0.1:8081` | пусто — страницы нет; не-loopback — отказ при разборе |

**Не-loopback отвергается при разборе**, а не игнорируется: человек, который написал `0.0.0.0:8081`, должен узнать об этом сразу, а не когда кто-то заберёт его сервер.

## Клиент

Не затрагивается. Ни одного файла в `lib/`, ни одного голдена, ни одной строки в ARB.
