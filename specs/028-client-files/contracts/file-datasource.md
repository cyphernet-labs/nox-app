# Contract: файловая цепочка

Провод фаза **не меняет** — §7 контракта v0 берётся дословно. Ниже граница между приложением и этим проводом.

## Проверено вживую

Перед написанием этого документа серверная половина прогнана против запущенного `noxd`:

```text
file.uploadBegin {name:"pic.png", size:5, mime:"image/png"}
  → {file_id:"f_7c58…", upload_url:"/files/tUKb…", upload_token:"tUKb…",
     max_attachment_bytes:104857600}
PUT /files/tUKb…  (5 байт)                          → 204
file.downloadBegin {file_id:"f_7c58…"}
  → {download_url:"/files/XLYb…", download_token:"XLYb…"}
```

## `FileRemoteDataSource` — `lib/data/remote/datasource/file_remote_data_source.dart`

Граница фичи по шву 016: репозиторий зависит от интерфейса, а не от сокета.

```dart
abstract class FileRemoteDataSource {
  Future<ResponseEntity<UploadTicketWireEntity>> uploadBegin({
    required String name,
    required int sizeBytes,
    required String mime,
  });

  Future<void> putBytes({
    required String uploadPath,
    required File file,
    void Function(int sent, int total)? onProgress,
  });

  Future<ResponseEntity<DownloadTicketWireEntity>> downloadBegin({required String fileId});

  Future<void> getBytes({
    required String downloadPath,
    required File destination,
    void Function(int received, int total)? onProgress,
  });
}
```

Привязки как у остальных: `Real*` на `[Environment.dev]`, `Mock*` на `[Environment.prod, Environment.test]` — тестовый набор и снимки от сервера не зависят.

### Обязательства

| Член | Обязательство |
|---|---|
| `uploadBegin` | Объявляет файл. `mime` выводится из расширения имени и **никогда** из байтов — пикер их не читает. `name` ≤ 255, `mime` ≤ 128 после трима, оба непустые: нарушение → `invalid_request` |
| `putBytes` | Передаёт **ровно** заявленное число байт. Больше → `413`, меньше → `400`, и байты не сохраняются. Адрес относительный — база из `AppConfig.apiUrl` |
| `downloadBegin` | Просит пропуск на получение. Коды сервера различаются, и различие важно: файла нет вовсе → `not_found`; байты ещё не переданы → `invalid_request`; срок истёк или байтов физически нет → `attachment_gone` |
| `getBytes` | Забирает байты в указанный файл. Любой отказ пропуска на HTTP — единый `404` без раскрытия причины |

Пропуски **одноразовые, TTL 10 минут**, гаснут первым обращением независимо от исхода. Поэтому ни один не хранится: после обрыва запрашивается новый той же командой.

### Классификация отказов — отдельно от общей

Это место, где готовая классификация фазы 027 даёт **неверный** ответ, и её нельзя переиспользовать вслепую.

Контракт: «Все отказы токена на HTTP — единый `404` без раскрытия причин». Общий маппер превращает HTTP 404 в `notFound`, а слив очереди считает `notFound` окончательным — то есть протухший или уже использованный пропуск **убил бы сообщение навсегда**, хотя контракт называет это штатным исходом, после которого просто запрашивают новый пропуск.

Поэтому передача байтов классифицируется у себя:

| Исход | Как трактуется |
|---|---|
| `404` на пути `/files/<токен>` | Пропуск негоден → **начать заново с заявки**, не окончательно |
| `413` / `400` | Размер разошёлся с заявленным → окончательно по этому сообщению |
| обрыв связи, таймаут | Повторяемо, как везде |
| `attachment_gone`, `not_found` при скачивании | Окончательно: байтов нет и не будет. По §2.1 — терминальное состояние **на экране файла, без повтора**, а не фатальный экран приложения |
| `invalid_request` «байты ещё не переданы» | Повторяемо: отправитель, возможно, ещё грузит |

## `FileRepository` — `lib/domain/repository/file/file_repository.dart`

```dart
abstract class FileRepository {
  /// Заявка + передача байтов. Возвращает идентификатор файла ТОЛЬКО когда
  /// байты подтверждённо на сервере.
  Future<RepositoryResult<String>> upload({
    required String path,
    required String mime,
    void Function(double fraction)? onProgress,
  });

  /// Байты на устройство. Возвращает путь к локальной копии.
  Future<RepositoryResult<String>> download({
    required String fileId,
    required String suggestedName,
    void Function(double fraction)? onProgress,
  });

  /// Удаляет весь кэш скачанного (выход из аккаунта).
  Future<void> clean();
}
```

Домен получает **путь**, а не `dart:io File`: `domain` не импортирует ничего, и файловый тип втащил бы туда платформенную библиотеку ради значения, которое и так является строкой. Тот же выбор уже сделан у пикера (`PickedFile.path`).

### Обязательства

1. **`upload` возвращает идентификатор только после подтверждения.** Вернуть его после заявки, но до передачи, значит позволить сообщению сослаться на файл без байтов: сервер такое примет, а получатель не скачает никогда.
2. **Предел проверяется до передачи.** Контракт требует проверять заранее, а не узнавать из отказа; предел лежит в конфиге с приветствия (фаза 026).
3. **`download` пишет в кэш и возвращает путь.** Тот же путь ложится в `localPath` вложения — поле, на которое уже смотрят миниатюра и сохранение.
4. **`attachment_gone` — окончательное.** Повторять нечего: байтов нет.
5. **Тишина в логах.** Ни имён файлов, ни путей, ни идентификаторов вложений.

## Что это выполняет из контракта

| Пункт | Как |
|---|---|
| §7 целиком | Обе цепочки, одноразовые пропуски, относительные адреса, точный размер |
| §9.6, файловая часть | Файловый датасорс `uploadBegin → PUT → send`; `attachment: {file_id}` вместо модели вложения на проводе |
