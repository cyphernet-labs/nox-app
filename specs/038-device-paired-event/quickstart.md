# Проверка фазы 038 — руками и тестами

## Стенд

```bash
./scripts/demo-stand.sh --reset-app
```

Свежая база, чистая установка macOS-приложения, claim-ссылка в выводе. База **обязана** быть свежей: правило одной миграции до релиза действует.

Второй клиент — симулятор iOS: он делит сеть с хостом, поэтому ссылка с `127.0.0.1` из него достижима.

```bash
fvm flutter build ios --simulator --debug --dart-define-from-file=config/stage.json
xcrun simctl install booted build/ios/iphonesimulator/Runner.app
xcrun simctl launch booted com.cyphernetlabs.noxapp
```

## Главная проверка — та, ради которой фаза

**Не уходя с экрана.** Это условие, а не деталь: уход и возврат чинят картинку и сегодня, и именно поэтому баг прожил с фазы 032 незамеченным.

1. На macOS: `Settings` → `Devices` → `Add a device`. На экране QR и ссылка.
2. **Не трогая это окно**, войти по ссылке с симулятора.
3. Смотреть на macOS:
   - в списке появляется второе устройство — само, без единого действия;
   - карточка с QR исчезает.

Если для этого пришлось куда-то нажать — фаза не сделана.

## Вторая проверка — разрыв связи (FR-010)

1. Открыть `Devices` на macOS и оставить открытым.
2. Погасить сервер: `pkill -f nox-demo-noxd`.
3. Поднять обратно тем же бинарником с теми же флагами (их печатает скрипт стенда).
4. Список приводится в соответствие сам, без ухода с экрана.

Смысл проверки: событие живое и разрыв не переживает. Без перечитывания по возврату связи человек, у которого моргнул вайфай ровно в момент привязки, остался бы с неверным списком в той самой ситуации, ради которой делается фаза.

## Третья — что ничего не сломалось

- **Отзыв работает как раньше** (FR-009): `Revoke` на чужом устройстве убирает его из списка; `Revoke` на своём — это выход с полной очисткой.
- **Экран верен при открытии** (FR-006): привязать устройство, когда раздел закрыт, потом открыть — список верен с первого взгляда.
- **Ничего не мигает на других экранах** (FR-011): во время привязки посидеть в чатах — никаких уведомлений, отметок и всплывающих сообщений.

## Проверка на проводе, без единого нажатия

```bash
cd client_backend && go run ./cmd/smoke '<claim-ссылка>'
```

Проходит захват, второе устройство и переписку. ⚠️ Смоук **забирает сервер себе** — после него стенд поднимать заново.

## Автоматические проверки

```bash
cd client_backend && go build ./... && go vet ./... && go test ./...
fvm flutter test --exclude-tags "golden || live" -j 3
fvm flutter test --tags golden -j 1
```

CI на паузе, поэтому локальный гейт — единственное место, где ловится регрессия. Оба прогона обязательны перед каждым коммитом.

Что должны утверждать новые тесты, чтобы они могли упасть:

- **Go, два соединения**: поздоровавшееся получает `device.paired`, привязывающееся — **не** получает. Без отрицательной половины проходит реализация «слать всем подряд».
- **Go, содержимое кадра**: ни токена, ни ключа устройства (SC-004).
- **Dart, `DevicesBloc`**: приход события вызывает повторное чтение `device.list` **и** обнуляет `inviteLink`.
- **Dart, возврат связи**: переход фазы «не жив → жив» вызывает повторное чтение, а повтор той же фазы — **не** вызывает.

Каждую новую проверку прогнать мутацией: убрать проверяемое поведение в продакшн-коде и убедиться, что тест падает. Три теста, которые не могли упасть, эта кодовая база уже набрала за прошлую фазу.

## Чего эта фаза не обещает

Устройство, бывшее **офлайн** в момент привязки, о ней не узнает: событие живое. Откроет экран — увидит правду. Это записанное решение (Assumptions спеки), а не недоделка, и проверять тут нечего, кроме того, что список верен при открытии.
