# Модель данных — фаза 038

**Хранимых данных фаза не добавляет.** Ни таблицы, ни колонки, ни ключа в настройках, ни записи в Sembast. Миграция `001_init.sql` не трогается.

Это не оговорка, а следствие устройства фазы: извещение выводится из факта, который уже записан — строка в `devices` появилась, — и само нигде не хранится, потому что живёт ровно до конца доставки.

## Что появляется в памяти

| Сущность | Где живёт | Чем является |
|---|---|---|
| Кадр `device.paired` | провод | внежурнальное событие, `seq: 0`, нагрузка `{}` |
| Сигнал «состав устройств изменился» | `DeviceRepository.watchDeviceListChanged()` | поток без значения: `Stream<void>`, событие есть — читай заново |
| Отметка предыдущей фазы канала | поле в `DevicesBloc` | нужна, чтобы перечитывать по фронту «не жив → жив», а не на каждом такте |
| Признак `actionFailed` | поле в `DevicesState` | «то, что вы попросили, не произошло» — отдельно от «список не прочитался» |

## Существующие сущности — без изменений

**Устройство** (`DeviceModel`): платформа, время привязки, время последней активности, признак «это я», ключ. Новых полей нет, старые не меняют смысла.

**Приглашение устройства**: одноразовое, живёт 10 минут. Новых полей нет. Меняется не сущность, а то, **как экран узнаёт** о её расходовании: раньше не узнавал никак, теперь узнаёт из события.

**Состояние экрана** (`DevicesState`): **появляется одно поле** — `actionFailed`, «то, что вы попросили, не произошло». До этой фазы на два разных вопроса отвечал один признак `failed`, и это сходило с рук ровно до тех пор, пока экран не начал перечитывать список сам: удачное фоновое чтение снимало сообщение о неудавшемся отзыве. Остальные поля те же — список, признак загрузки, признак отказа чтения, ссылка приглашения, — но `inviteLink` теперь может обнулиться не только нажатием `Hide`, а `failed` отвечает только за чтение списка.

## Поток данных целиком

```
устройство B предъявляет приглашение
        │
        ▼
store.Pair — строка в devices появилась          ← единственная запись за всю фазу
        │
        ├─► ответ предъявителю (как раньше)
        │
        └─► device.paired ──► всем соединениям этого человека, кроме B
                                     │
                                     ▼
                        DeviceRepository.watchDeviceListChanged()
                                     │
                                     ▼
                    DevicesBloc: device.list заново + inviteLink = null
```

Обратите внимание, чего в схеме нет: ветки, которая бы **дописала** строку в список из полезной нагрузки события. Её нет намеренно — сервер остаётся единственным источником правды о том, кому позволено говорить от имени человека, и экран узнаёт состав только спросив (FR-004).
