# Контракт: запертый сервер и восстановление (дельта контракта v0)

Правится первым в `docs/client-backend/protocol/contract-draft.md`.

## §1

- Данные сервера на диске зашифрованы ключом данных, который запирает пароль владельца. После каждого запуска сервер **заперт**, пока пароль не введён на служебной странице или командой: основной порт не принимает соединений — устройства видят то же, что при выключенном сервере.
- `GET /health` на служебном адресе: `{"status":"locked"}` — заперт, `{"status":"ok"}` — открыт; код всегда `200`.

## §3 `journal_id`

Восстановленный из бэкапа сервер получает **новое** `journal_id`: устройства по действующему правилу сбрасывают локальный мир и перечитывают переписку. Ключ сервера после восстановления тот же — спаривать заново не нужно.
