# Feature Specification: Данные на диске сервера — шифрование базы и файлов, пароль владельца, запертый старт, бэкап

**Feature Branch**: `security-rework` (фичи 044–049 идут в одной ветке, решение владельца 2026-10-09)

**Created**: 2026-10-09

**Status**: Draft

**Input**: Тема 4 трекера безопасности `docs/client-backend/roadmap-security.md` (решения 1–2, 7, 9) и раздел 047 его плана реализации; страница темы 4 артефакта NOX Architecture. Зависит от 044: ключ сервера Ed25519 хранится в базе.

## Зачем это вообще

Сегодня база сервера хранит переписку открытым текстом, ключ сервера лежит в ней же, вложения — обычными файлами, а копия базы — это весь сервер. Кто унёс диск или машину или получил копию базы, получил всё.

Граница темы: всё, что делается с доступом к работающей машине сервера, вне рамок. Эта фича защищает данные сервера от кражи диска или машины и от утечки копий — и не опирается на шифрование диска средствами системы.

## Решения владельца

1. **Сервер шифрует базу и файлы вложений сам.** Ключ данных — случайный; его запирает пароль, который владелец задаёт при установке (Argon2id). Шифрованию диска средствами системы не доверяем. Забытый пароль — потерянные данные (2026-10-08).
2. **Бэкап зашифрован тем же паролем**: снимок базы, файлы вложений и запертый ключ данных — одним файлом; восстановление — на любой машине с тем же паролем (2026-10-08).
3. **Пароль не короче 12 знаков; вложения — кусками по 64 КиБ; смена пароля перезапирает ключ данных без перешифровки** (приняты при вычитке страницы, 2026-10-09).
4. **Запертый старт** (вариант А, «пока так, владелец уточнит позже», 2026-10-09): после каждого перезапуска сервер ждёт пароль на служебной странице или в терминале; пока пароль не введён — страница показывает только поле пароля, устройствам сервер не отвечает; неверный пароль ничего не меняет; новая база поверх существующей не создаётся.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Украденный диск ничего не даёт (Priority: P1)

Диск или вся выключенная машина сервера попали к постороннему. Он видит файлы базы и вложений, но ни одной строки переписки, ни одного вложения и ни одного ключа прочитать не может: всё зашифровано, а пароля на диске нет.

**Why this priority**: суть темы 4.

**Independent Test**: наполнить сервер перепиской и вложениями, остановить его и поискать по всем его файлам на диске известные фрагменты текста и файлов — ни одного совпадения.

**Acceptance Scenarios**:

1. **Given** сервер с перепиской остановлен, **When** посторонний читает базу с диска, **Then** ни одна страница базы не содержит открытого текста.
2. **Given** на сервере есть вложения, **When** посторонний читает их файлы, **Then** содержимого вложений в них нет — в том числе у незаконченных загрузок.
3. **Given** диск у постороннего, **When** он ищет ключ сервера или токены, **Then** они лежат только внутри зашифрованной базы.

---

### User Story 2 — Запуск с паролем (Priority: P1)

При первом запуске владелец задаёт пароль — на служебной странице или в терминале; скрипт установки делает это за него. После каждого следующего перезапуска сервер стартует запертым: служебная страница показывает только поле пароля, устройства подключиться не могут. Владелец вводит пароль — сервер открывается и работает как обычно.

**Why this priority**: без пароля зашифрованный сервер не открыть; решение 4.

**Independent Test**: запустить свежий сервер — он просит задать пароль; перезапустить — он заперт, устройства не подключаются; ввести неверный пароль — ошибка, на диске ничего не изменилось; ввести верный — устройства подключаются.

**Acceptance Scenarios**:

1. **Given** базы ещё нет, **When** сервер стартует, **Then** он ждёт, пока владелец задаст пароль не короче 12 знаков и повторит его.
2. **Given** база есть, **When** сервер перезапускается, **Then** он заперт: страница показывает только поле пароля, без ссылок и адресов, а устройствам сервер не отвечает.
3. **Given** сервер заперт, **When** владелец вводит неверный пароль, **Then** сервер сообщает об ошибке, остаётся запертым и ничего не меняет на диске.
4. **Given** сервер заперт, **When** владелец вводит верный пароль на странице или в терминале, **Then** сервер открывается, и устройства подключаются.
5. **Given** база есть, **When** кто-то пытается задать новый пароль вместо ввода прежнего, **Then** сервер не создаёт новую базу поверх существующей.

---

### User Story 3 — Бэкап и восстановление (Priority: P2)

Владелец командой сервера делает бэкап — один файл со снимком базы, вложениями и запертым ключом данных. Всё внутри зашифровано; открыть бэкап можно только паролем сервера. Машина сломалась — владелец восстанавливает сервер из бэкапа на другой машине тем же паролем. Устройства продолжают работать с ним без повторного спаривания.

**Why this priority**: решение 2; бэкап — единственный способ пережить потерю машины.

**Independent Test**: сделать бэкап работающего сервера, восстановить его на другой машине, открыть паролем — спаренные устройства подключаются без спаривания; в файле бэкапа нет открытого текста.

**Acceptance Scenarios**:

1. **Given** сервер работает, **When** владелец делает бэкап, **Then** получается один файл, согласованный на момент снимка, без открытого текста.
2. **Given** файл бэкапа, **When** владелец восстанавливает его на пустом месте другой машины и вводит пароль, **Then** сервер открывается с той же перепиской и тем же ключом сервера.
3. **Given** восстановленный сервер, **When** спаренное устройство подключается, **Then** спаривать заново не нужно.
4. **Given** на месте восстановления уже есть база, **When** владелец запускает восстановление, **Then** команда отказывает и ничего не меняет.

---

### User Story 4 — Смена пароля и вложения кусками (Priority: P3)

Владелец меняет пароль — сервер перезапирает ключ данных за секунды, без перешифровки базы и файлов. Вложения тем временем загружаются и скачиваются, как раньше: обрыв посреди загрузки продолжает её, просмотр большого видео читает файл по частям.

**Why this priority**: решение 3; без кусков шифрование сломало бы докачку из фичи 043.

**Independent Test**: сменить пароль на сервере с большим объёмом данных — меньше 5 секунд, старый пароль больше не открывает сервер; оборвать загрузку 100 MiB посреди куска и продолжить — файл целый; запросить диапазон из середины вложения — получены точные байты.

**Acceptance Scenarios**:

1. **Given** сервер открыт, **When** владелец меняет пароль, указав текущий, **Then** новый пароль открывает сервер, а прежний — нет.
2. **Given** загрузка оборвалась посреди куска, **When** она продолжается, **Then** сервер принимает её с начала этого куска, и файл получается целым.
3. **Given** вложение на сервере, **When** устройство просит диапазон байтов, **Then** получает ровно эти байты открытого файла.

---

### Edge Cases

- **Забытый пароль** — базу и бэкапы открыть нечем; служебная страница предупреждает об этом, когда пароль задают.
- **Восстановлен бэкап старее, чем знают устройства** — восстановленный сервер получает новое имя журнала, и устройства перечитывают переписку с него: то, что появилось после бэкапа, пропадает и у устройств. Иначе устройства разошлись бы с сервером.
- **Пароль из пробелов или короче 12 знаков** — отказ при задании.
- **Повтор пароля не совпал** — отказ при задании.
- **Сбой питания посреди смены пароля** — открывается либо прежний, либо новый пароль; ключ данных не теряется.
- **Сбой посреди бэкапа** — недописанный файл бэкапа не считается бэкапом и не открывается.
- **Ключ onion-адреса** в бэкап не входит: после переезда без папки tor у сервера новый onion-адрес (045).

## Requirements *(mandatory)*

### Functional Requirements

**Пароль и ключ данных**
- **FR-001**: Если базы нет, сервер MUST ждать, пока владелец задаст пароль не короче 12 знаков и повторит его, — на служебной странице или командой в терминале; затем MUST создать случайный ключ данных (32 байта) и запереть его ключом, полученным из пароля функцией Argon2id. На диске MUST лежать только запертый ключ.
- **FR-002**: Если база есть, сервер MUST стартовать запертым: служебная страница показывает только поле пароля, без ссылок и адресов; устройствам сервер MUST NOT отвечать, пока пароль не введён.
- **FR-003**: Пароль MUST вводиться на служебной странице или командой в терминале; команда MUST передавать его работающему серверу.
- **FR-004**: Неверный пароль MUST давать сообщение об ошибке, оставлять сервер запертым и MUST NOT менять ничего на диске.
- **FR-005**: Сервер MUST NOT создавать новую базу поверх существующей: задать пароль можно, только когда базы нет.
- **FR-006**: Смена пароля MUST требовать текущий пароль, MUST перезапирать ключ данных и MUST NOT перешифровывать базу и файлы; сбой посреди смены MUST оставлять рабочим прежний или новый пароль.
- **FR-007**: Восстановления забытого пароля MUST NOT быть; служебная страница MUST предупреждать об этом при задании пароля.

**Шифрование**
- **FR-008**: База MUST шифроваться по страницам так, что ни одна страница — включая служебные файлы базы — не лежит на диске открытым текстом.
- **FR-009**: Файлы вложений MUST шифроваться кусками по 64 КиБ, каждый со своей проверкой целостности, — и готовые, и незаконченные загрузки.
- **FR-010**: Загрузка, оборванная посреди куска, MUST продолжаться с начала этого куска; чтение диапазона MUST возвращать точные байты открытого файла.
- **FR-011**: Ключ сервера, токены, ключи устройств и адреса MUST храниться только в зашифрованной базе.
- **FR-012**: Сервер MUST оставаться одним статическим бинарником без C-кода.

**Бэкап и восстановление**
- **FR-013**: Команда сервера MUST делать бэкап одним файлом: согласованный снимок базы, файлы вложений и запертый ключ данных; всё внутри MUST быть зашифровано; открыть бэкап MUST можно только паролем сервера. Бэкап MUST делаться работающим сервером, без остановки.
- **FR-014**: Восстановление MUST работать на любой машине с тем же паролем, только на пустом месте; при существующей базе команда MUST отказывать и ничего не менять.
- **FR-015**: Восстановленный сервер MUST сохранять свой ключ, чтобы устройства продолжали работать без повторного спаривания, и MUST получать новое имя журнала, чтобы устройства перечитали переписку с него.
- **FR-016**: Ключ onion-адреса MUST NOT входить в бэкап.

**Интерфейс и приватность**
- **FR-017**: Служебная страница MUST иметь три состояния: «задать пароль» (пароль и повтор, предупреждение о забытом пароле), «заперт» (только поле пароля) и «открыт» (как сегодня плюс смена пароля); с понятными сообщениями о неверном, коротком и не совпавшем пароле.
- **FR-018**: Пароль, ключи и содержимое переписки и файлов MUST NOT попадать в логи и в вывод команд.
- **FR-019**: Изменения провода (сервер заперт и не отвечает, новое имя журнала после восстановления) MUST сначала описываться в контракте v0 (Принцип VII).

### Key Entities

- **Ключ данных** — случайные 32 байта, которыми зашифрованы база и вложения.
- **Запертый ключ данных** — ключ данных, запертый ключом из пароля; единственное, что о ключах лежит на диске вне базы.
- **Пароль сервера** — задаётся владельцем, не хранится нигде.
- **Файл бэкапа** — снимок базы, вложения и запертый ключ данных в одном файле.
- **Имя журнала** — то, по чему устройства понимают, что сервер стал «другим» по переписке, и перечитывают её.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Поиск известных фрагментов переписки, вложений и ключей по всем файлам остановленного сервера и по файлу бэкапа даёт ноль совпадений.
- **SC-002**: После ввода верного пароля сервер открывается не дольше чем за 2 секунды.
- **SC-003**: Неверный пароль не меняет на диске ни одного байта.
- **SC-004**: Загрузка 100 MiB, оборванная посреди передачи, доходит целой; чтение любого диапазона возвращает точные байты.
- **SC-005**: Сервер, восстановленный из бэкапа на другой машине, принимает все прежние устройства без спаривания.
- **SC-006**: Смена пароля занимает меньше 5 секунд при любом объёме данных.

## Assumptions

- Скрипт установки (049) спрашивает пароль и задаёт его сам; без скрипта — служебная страница или терминал.
- Бэкапы делаются по команде; расписания нет. Куда класть файл бэкапа, решает владелец.
- Параметры Argon2id выбираются в плане так, чтобы проверка пароля занимала около секунды.
- Содержимое памяти работающего сервера — вне рамок (граница темы).
- Продукт не выпущен: миграций нет, сервер начинает с новой базы.

## Out of Scope

- Шифрование данных на устройстве (048).
- Скрипты установки (049).
- Расписание бэкапов и хранение их вне машины.
- Открытие сервера без пароля после перезапуска (варианты Б и В темы 4 не выбраны).
- Постквантовая защита (вне рамок).
