# Quickstart: проверка защищённого канала

## 1. Автоматические проверки

```bash
# Rust: векторы Eidolon, канал против локального TLS-сервера с Eidolon (успех, чужой ключ, посредник, обрыв, срок)
make tor-test

# Go: векторы Eidolon, слушатель (успех, чужой ключ, посредник с двумя TLS, незнакомый ключ — только pair, /files с ключом и токеном), ссылка v3
cd client_backend && gofmt -l . && go vet ./... && go test -race ./...

# Dart: векторы ссылки, ChannelSocket поверх фейкового канала (окна, addStream, flush), сессия, приветствие, спаривание, проба адреса
make gate && make golden-verify
```

Ожидается: всё зелёное; векторы `contracts/eidolon-vectors.json` и `contracts/link-vectors.json` проходят у Rust, Go и Dart.

## 2. Сквозной прогон на macOS

```bash
# Сервер с новой базой
cd client_backend && go build -o /tmp/nox044/noxd . && \
  /tmp/nox044/noxd -db /tmp/nox044/nox.db -addr 0.0.0.0:8443 -status-addr 127.0.0.1:8081 -tor=false

# Служебная страница: http://127.0.0.1:8081 — ссылка вида nox://pair/A…
# Приложение (stage):
fvm flutter run -d macos --dart-define-from-file=config/stage.json
```

1. На экране входа вставить ссылку → спаривание проходит, экран имени, затем чаты.
2. Создать чат, отправить сообщение и картинку → оба доходят; на сервере — новые строки.
3. Перезапустить приложение → подключение без спаривания; сообщения на месте.
4. Остановить сервер, поднять второй с другой базой на том же адресе → приложение молча считает адрес недоступным («No connection»), данные и вход на месте.
5. Вернуть первый сервер → связь восстанавливается.
6. `curl -k https://127.0.0.1:8443/health` → ответа нет: сервер ждёт сообщение проверки и по сроку (10 с) закрывает соединение; `curl http://127.0.0.1:8081/health` → `ok`.
7. В логе приложения строки открытия канала напрямую дома показывают меньше секунды (SC-006); ключей, токенов и ссылки в логах приложения и сервера нет, кроме ссылки первого спаривания в журнале сервера (до 046).
