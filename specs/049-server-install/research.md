# Research: Установка сервера

Опора — 045 (`-public-addr`, `-onion-addr`, tor отдельно), 046 (`noxd link`), 047 (`noxd unlock` из stdin, запертый старт), страница темы 2 («Как поставить tor»), `client_backend/CLAUDE.md` (заметки о tor на macOS: официальная сборка без подписи).

## R1. Скрипты и где что лежит

- **Decision:**

| | Linux | macOS | Windows |
|---|---|---|---|
| Скрипт | `deploy/install-linux.sh` (bash) | `deploy/install-macos.sh` (bash) | `deploy/install-windows.ps1` (PowerShell 5+) |
| Бинарник | `/usr/local/bin/noxd` | `/usr/local/bin/noxd` | `C:\Program Files\NOX\noxd.exe` |
| Данные | `/var/lib/nox` | `/Library/Application Support/NOX` | `C:\ProgramData\NOX` |
| Учётная запись | системный `nox` | системный `_nox` | виртуальная `NT SERVICE\noxd` |
| Автозапуск | systemd `noxd.service` (`KillMode=mixed` не нужен — tor отдельно) | launchd `/Library/LaunchDaemons/com.cyphernetlabs.noxd.plist` | служба `noxd` (`sc.exe`/`New-Service`) |
| tor | пакет дистрибутива ≥ 0.4.9 или репозиторий Tor Project; служба `tor` | Tor Expert Bundle (macOS), подпись ad-hoc (`codesign -s -`), launchd `org.torproject.tor` | Tor Expert Bundle, служба `tor` (`tor --service install`) |

- **Rationale:** FR-001, FR-002; служба под своей учётной записью — доступ только к своим данным.

## R2. Бинарник

- **Decision:** `--binary <путь>` — готовый; иначе, если есть Go, `CGO_ENABLED=0 go build -trimpath -ldflags=-s` из `client_backend/` рядом со скриптом; иначе — отказ с инструкцией.
- **Rationale:** уточнение; поставка архивов — вне рамок.

## R3. tor и onion-сервис

- **Decision:** отдельный файл настроек NOX для tor: `HiddenServiceDir <tor-data>/nox`, `HiddenServicePort 443 127.0.0.1:<порт>`, `HiddenServicePoWDefensesEnabled 1`, `HiddenServiceMaxStreams 16`, `HiddenServiceMaxStreamsCloseCircuit 1` (R9); подключается через `%include` в основной `torrc` (tor ≥ 0.4.0), чужие настройки не трогаются. Onion-адрес — из `<HiddenServiceDir>/hostname` после первого старта tor (ожидание до 60 с). Проверка скачанного: `sha256sums-signed-build.txt` + `.asc` подписью Tor Project через `gpg` (ключ Tor Browser Developers по отпечатку, зашитому в скрипт); нет `gpg` или подпись не сошлась — tor не ставится.
- **Rationale:** FR-002, FR-003, уточнение; PoW на стороне сервиса (тема 2).

## R4. Первый запуск, пароль, ссылка

- **Decision:** порядок: учётная запись и папки → бинарник → tor и onion-адрес (если выбран) → служба сервера с `-addr 0.0.0.0:<порт> -db <данные>/nox.db -status-addr 127.0.0.1:8081 [-onion-addr …] [-public-addr …]` → ожидание `/health` `locked` → на новой установке пароль дважды (без эха, ≥ 12 знаков, повтор при ошибке) → `noxd unlock` из stdin → `noxd link` (ссылка, QR в терминале, срок) → адрес служебной страницы и как открыть сервер после перезагрузки. Пароль передаётся только через stdin команды, не в аргументах и не в файлах.
- **Rationale:** FR-004–FR-007, SC-004.

## R5. Повторный запуск

- **Decision:** есть `<данные>/nox.db` — режим обновления: заменить бинарник, обновить файлы служб и настройку onion-сервиса NOX, перезапустить; пароль не спрашивается (сервер стартует запертым — скрипт напоминает открыть его); ключ onion-адреса (`HiddenServiceDir`) и база не трогаются.
- **Rationale:** FR-008, SC-003.

## R6. Сбои

- **Decision:** проверки до изменений: права администратора, занятость порта (`ss`/`lsof`/`Get-NetTCPConnection`), наличие Go или `--binary`; сбой tor — сервер ставится без него и скрипт говорит, что не вышло; при сбое после частичных изменений — откат созданного этим запуском (служба, файлы службы).
- **Rationale:** FR-009, FR-010.

## R7. QR в терминале

- **Decision:** `noxd link -qr` печатает QR-код символами `▀▄█` (две строки модулей в одной строке терминала) с тихой зоной; кодирует `rsc.io/qr` (уже зависимость сервера).
- **Rationale:** FR-006, уточнение.

## R8. Проверка

- **Decision:** macOS — на этой машине: установка в изолированные пути (`--prefix` для проверки без затрагивания системы), tor из подписанного bundle, служба launchd, перезапуск, `noxd unlock`, спаривание; Linux и Windows — владелец (`shellcheck` и `PSScriptAnalyzer` для статической проверки, если установлены).

## R9. Решения реализации там, где документы молчат

Выбран осторожный вариант; каждое решение записано здесь.

- **Пароль — до любых изменений.** Скрипт спрашивает пароль (и публичный адрес) сразу после проверок, до учётных записей, файлов и служб, а серверу отдаёт его в конце, через стандартный ввод `noxd unlock`. Несовпавший или короткий пароль и Ctrl+C на вопросе не оставляют на машине ничего (FR-010); пароль живёт только в переменной скрипта и не попадает ни в аргументы процессов, ни в файлы. Эхо выключается до того, как показан вопрос: `read -s` сначала печатает вопрос, и вставленное в это мгновение отображалось бы. Без терминала пароль читается двумя строками со стандартного ввода — так скрипт проверяется без человека.
- **Точка невозврата — ответ служебной страницы.** Каждое изменение пишет в журнал скрипта, как его отменить; сбой до ответа `/health` отменяет всё, сделанное этим запуском, в обратном порядке (созданные учётные записи, папки, файлы, службы, правило брандмауэра; прежние файлы возвращаются из копий). После ответа установка стоит: сбой задания пароля или выдачи ссылки только описывается — пароль задаётся на служебной странице или `noxd unlock`. Журнал сервера, который откат удалит, показывается до отката.
- **Откат доводится до конца.** Шаг уходит из журнала, как только выполнен, и второй Ctrl+C во время отката не действует (`trap '' INT TERM`; на Windows — `TreatControlCAsInput`): оборванный откат оставил бы машину в состоянии, которого никто не выбирал, а пакетные менеджеры и `launchctl`, получив Ctrl+C, бросили бы шаг на середине. На Windows откат — в `finally`, не в `catch`: Ctrl+C останавливает скрипт мимо всех `catch`, выполняются только `finally`, и копии прежних файлов удаляются уже после отката. Шаг, который отменить не удалось, назван, и вместо «машина как была» сказано, что вернулось не всё.
- **Обновление.** Установка считается существующей, если есть база, файл ключа или описание службы. Порт, порт служебной страницы и публичный адрес берутся из установленной службы, если их не передали; свои порты, занятые своим же сервером, проверку портов проходят. База, `nox.db.key`, папка ключа onion-адреса не трогаются; перед перезапуском tor удаляется только файл `hostname` — tor пишет его из ключа при каждом старте, и ожидание доказывает именно этот старт.
- **tor на Linux — системная служба.** Onion-сервис NOX — отдельный файл `/etc/tor/nox-tor.conf`, подключённый к `/etc/tor/torrc` одной строкой `%include` между метками; остальные настройки tor, включая `SocksPort`, не меняются. tor берётся из дистрибутива, если кандидат 0.4.9+ и сборка умеет PoW, иначе — из репозитория Tor Project (apt и dnf; pacman — только дистрибутив). Пакет, поставленный этим запуском, при сбое tor удаляется.
- **Ключи репозиториев Tor Project.** Скачанный файл ключа принимается, только если каждый ключ в нём — пинованный, по основному отпечатку: apt доверяет каждому ключу связки `signed-by`, rpm импортирует каждый ключ файла, и ключ, дописанный после настоящего, получил бы то же доверие. Ставится не скачанный файл, а то, как gpg его прочёл (`--import-options import-export`: без того, что gpg счёл недействительным, например подключа без привязки; связка ключей при этом не пишется), — и оно проверяется ещё раз. dnf получает ключ локальным файлом `/etc/pki/rpm-gpg/RPM-GPG-KEY-torproject` (`gpgkey=file://…`), не адресом: ключ по адресу `dnf -y` импортирует сам, без сверки отпечатка. Ключ, впервые импортированный в rpm этим запуском, при откате удаляется (`rpm -e gpg-pubkey-…`).
- **Порты ниже 1024 — отказ до изменений.** На Linux служба работает под `nox` без `CAP_NET_BIND_SERVICE`, и порт ниже `net.ipv4.ip_unprivileged_port_start` (1024) скрипт не принимает — и основной, и служебной страницы. Иначе установка дошла бы до ответа `/health` (страница слушает с первого старта), а основной порт сервер открывает только после пароля — и не открыл бы. Выбран отказ, а не право в юните: служба не получает права, без которого обходится, а 443 снаружи даёт проброс на роутере. macOS пускает на порты ниже 1024 без root только на всех адресах сразу (проверено здесь: `0.0.0.0` — да, `127.0.0.1` — нет), поэтому там отвергается только порт служебной страницы.
- **Папка бэкапов.** `noxd backup` пишет файл сам работающий сервер, под своей учётной записью, а ей можно писать только в папку данных: скрипт заводит в ней `backups` (с правами папки данных) и называет её в конце установки и в `deploy/README.md` вместе с тем, как унести файл с правами администратора.
- **tor на macOS и Windows — своя служба.** Tor Expert Bundle ставится своей службой с метками `com.cyphernetlabs.nox-tor` (launchd) и `nox-tor` (служба Windows) вместо `org.torproject.tor` и `tor` из R1: имя Tor Project может принадлежать tor, поставленному иначе, и его настройки этот скрипт не трогает. У своей службы — своя учётная запись (`_noxtor`, `NT SERVICE\nox-tor`), свой `torrc` с `SocksPort 0`, пустой `torrc-defaults` (сборка Tor Browser иначе подхватывает свой). «tor уже стоит и подходит» здесь — tor, поставленный этим скриптом раньше, или `--tor-bin`; tor, поставленный иначе (Homebrew — без PoW), не используется. Из архива ставятся только `tor` и библиотеки рядом (на macOS — `libevent`), без мостов и GeoIP.
- **launchd: остановка с ожиданием.** `launchctl bootout` возвращается, пока задание ещё завершается, а `bootstrap` той же метки в это время отвергается (`5: Input/output error`). Штатная остановка noxd укладывается в 25 с (по 5 с на основной сервер и служебную страницу, до 15 с на закрытие соединений устройств), а задание, пережившее свой `ExitTimeOut`, launchd убивает раньше. Поэтому скрипт после `bootout` ждёт до 30 с, пока метка не пропадёт из `launchctl print`, повторяя `bootout`, и только тогда загружает новое задание; отказ `bootstrap` в первое мгновение повторяется дважды. «Вернуть прежнее задание» пишется в журнал отката до остановки, а откат сначала останавливает новое задание с тем же ожиданием.
- **`--binary` на macOS — копия без карантина.** Файл, пришедший через AirDrop, Messages, почту или браузер, несёт `com.apple.quarantine`, и Gatekeeper не запускает такую программу без нотаризации — а `noxd` её не имеет, — значит, не прошла бы и проверка `noxd unlock -h`. Скрипт копирует файл в рабочую папку, снимает карантин с копии, проверяет и ставит её; исходный файл не трогается. Отказ приводит, что программа сказала, и что карантин ни при чём.
- **PoW — обязательное свойство tor.** tor без модуля `pow` отвергает настройки с `HiddenServicePoWDefensesEnabled 1` и не стартует; такой tor считается неподходящим, как старее 0.4.9 (`tor --list-modules` → `pow: yes`).
- **Предел потоков.** Onion-адрес открыт любому, кто его знает, а PoW ограничивает только новые подключения к сервису: каждая настройка onion-сервиса несёт `HiddenServiceMaxStreams 16` и `HiddenServiceMaxStreamsCloseCircuit 1` (замечание ревью кода 045) — устройству хватает сокета и нескольких передач, а цепочку, по которой открыли больше, tor закрывает. `HiddenServicePort 443` ведёт на `127.0.0.1:<порт>`, сервер слушает `0.0.0.0:<порт>`, и loopback до него доходит.
- **Кавычки в `torrc`.** Пути в `DataDirectory`, `HiddenServiceDir` и `%include` пишутся в кавычках с экранированием `\` и `"` — tor читает там экранирование C, и путь с пробелом работает. В строке `Log` кавычки не разбираются: служба Windows пишет журнал tor по пути без пробелов (иначе — без журнала, с предупреждением), launchd и проверка без служб берут вывод tor сами.
- **Проверка подписи.** Сначала `gpgv` с ключом в роли связки: ему не нужны ни папка ключей, ни агент (у `gpg` без агента код выхода ненулевой даже после верной проверки). Вердикт — по строкам состояния: `VALIDSIG`, последнее поле которой — отпечаток основного ключа, равный зашитому, и ни одной `BADSIG`, `ERRSIG`, `REVKEYSIG`; затем SHA-256 архива — по строке подписанного списка. Ключ скачивается по WKD Tor Project; `NOX_TOR_DIST`, `NOX_TOR_VERSION` и `NOX_TOR_KEY_URL` указывают на зеркало или локальную копию (`file://`), отпечаток проверяется всегда. На macOS скачанный tor подписывается ad hoc после проверки.
- **Сервер на Windows — служба Windows сам.** Консольную программу диспетчер служб убивает, если она не отчиталась; поэтому `noxd`, запущенный диспетчером, работает через `golang.org/x/sys/windows/svc` (до сих пор — косвенная зависимость модуля): `Running` сразу, `Stop` и `Shutdown` — штатная остановка сервера, журнал — в `noxd.log` рядом с базой, откладывается в `noxd.log.1` на 16 МиБ. Виртуальные учётные записи `NT SERVICE\noxd` и `NT SERVICE\nox-tor`; папки данных — только им, SYSTEM и администраторам (SID, а не имена — одинаково на любом языке Windows); перезапуск при сбое; правило брандмауэра на порт сервера для `noxd.exe` во всех профилях — без него прямые соединения на Windows не доходят.
- **Остановка по просьбе диспетчера — чистый выход.** Служба зарегистрирована с действиями при сбое, которые считают сбоем и ненулевой код остановки (`sc failureflag 1`, перезапуск через 5 с), а штатная остановка сервера возвращает ошибку, когда истёк её срок, — например, пока идёт передача файла через Tor. Остановка, о которой попросил диспетчер, поэтому всегда завершается кодом 0, а ошибка остановки уходит в журнал; сбой — только сервер, остановившийся сам: его диспетчер и перезапускает.
- **Windows: пароль из перенаправленного ввода — UTF-8.** `[Console]::In` декодирует кодовой страницей консоли, и пароль вне ASCII менялся бы по дороге к серверу; скрипт читает байты как UTF-8 (BOM UTF-8 и UTF-16 учитывается), недопустимые байты — отказ. Windows PowerShell 5.1 в конвейере заменяет не-ASCII на `?` ещё до скрипта, этого скрипт не видит — в `deploy/README.md` сказано, как подать файл.
- **Windows: `-TorBin` копируется.** Служба tor работает под `NT SERVICE\nox-tor`, которая читает `Program Files`, но не папки владельца, где tor.exe обычно лежит (Tor Browser на рабочем столе, архив в загрузках); заданный tor.exe ставится в `C:\Program Files\NOX\tor\` вместе с библиотеками рядом — как скачанный, у которого библиотеки рядом тоже копируются.
- **Команды без `sudo`.** Подсказки говорят `noxd unlock` и `noxd link -qr` без `sudo` (в отличие от T006 и quickstart): команды ходят на loopback-страницу и прав администратора не требуют, а `sudo` спросил бы пароль учётной записи macOS прямо перед паролем сервера.
- **Сборка.** Под `sudo` сервер собирается от имени запустившего (`SUDO_USER`): его кэш модулей и сборки, и git доверяет его копии репозитория для отметки версии; от root без `SUDO_USER` при отказе git — сборка без отметки версии. Бинарник проверяется запуском: `noxd unlock -h` и `noxd link -h` должны знать `-status-addr` и `-qr`.
- **Брандмауэр.** Windows — правило ставит скрипт (см. выше); macOS, ufw и firewalld — только подсказка с командой: политику брандмауэра скрипт не меняет.
- **`--prefix` и `--no-service` — только вместе.** Проверка без изменения системы: все файлы под префиксом, включая временные и кэш сборки; ни учётных записей, ни служб, ни пакетов; описания служб пишутся под префикс для просмотра (`plutil -lint` на macOS), сервер и tor работают фоновыми процессами с файлами pid и той же маской `077`, что у служб.
- **Удаление** — вне рамок (spec, Out of Scope): таблица «Где что лежит» в `deploy/README.md` перечисляет всё, что ставит скрипт.
