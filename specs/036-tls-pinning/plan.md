# Implementation Plan: TLS с пиннингом по ключу сервера

**Branch**: `036-tls-pinning` | **Date**: 2026-09-07 | **Spec**: [spec.md](./spec.md)

## Summary

Сервер выпускает себе сертификат **из ключа, который у него уже есть** — Ed25519-ключа личности, лежащего в базе с фазы 032 и едущего в каждой ссылке спаривания. Клиент отключает проверку цепочки и ставит на её место одно сравнение: публичный ключ предъявленного сертификата равен сохранённому при спаривании.

Из этого следует всё остальное. Форма ссылки не меняется — ключ там уже есть. Спаренные устройства продолжают работать — ключ у них уже сохранён. Сертификат собирается при каждом запуске в памяти и нигде не хранится: доверие держится на ключе, а сертификат — расходник, у которого нет ни срока, который мог бы истечь на чужих глазах, ни второй записи, которая могла бы разойтись с первой.

Служебная страница фазы 035 остаётся открытым HTTP на loopback: сетевого трафика у неё нет по построению, и TLS там — сложность без цели.

## Technical Context

**Language/Version**: Go 1.27 (сервер) + Dart / Flutter 3.44.1 FVM (приложение).

**Primary Dependencies**: ни одной новой. На сервере — `crypto/tls`, `crypto/x509` из стандартной библиотеки; на клиенте — `HttpClient` из `dart:io`, который `IOWebSocketChannel` уже использует под собой.

**Storage**: схема **не меняется**. Ключ уже в `server_identity`, сохранённый ключ сервера уже в сессии клиента.

**Testing**: `go test -race ./...` с настоящим TLS через `httptest.NewUnstartedServer` + собственный `tls.Config`; на клиенте — тесты сверки ключа против подставного сертификата.

**Target Platform**: сервер — процесс на машине владельца; приложение — iOS, Android, macOS, Windows, Linux.

**Project Type**: клиент-серверная пара; меняется транспорт с обеих сторон и одна строка контракта.

**Performance Goals**: не применимо. TLS-рукопожатие один раз на соединение, соединение живёт часами.

**Constraints**: провод (команды, события, коды) **не меняется вовсе**; форма ссылки не меняется; спаренные устройства не пере-спариваются; отката на открытый канал нет.

**Scale/Scope**: круг ~10 человек. Затрагивается один слушатель на сервере, одна фабрика сокета на клиенте, один манифест Android.

**Structure Decision**: один новый файл на сервере и один на клиенте. Фабрика сокета — существующий шов, и именно поэтому подмена транспорта не расходится по коду.

## Порядок работ

1. **Контракт** — схема адреса и правило пиннинга.
2. **Сервер** — сертификат из ключа личности, `tls.Config`, `ServeTLS`; страница 035 не трогается.
3. **Клиент** — сверка ключа в фабрике, `wss` в адресе, отличимый отказ.
4. **Android** — снять разрешение на открытый трафик.
5. **Тесты** — подменённый сервер отвергается; перевыпущенный на том же ключе принимается; спаренное до фазы устройство подключается.
6. **Доки** — контракт, роадмап, CLAUDE.md.

## Когда это делается

**После живого прогона 034 и 035.** Фаза меняет транспорт целиком: уронив её в `develop` до проверки, мы сделали бы результат той проверки нечитаемым — при отказе нельзя было бы сказать, виновато приглашение человека, страница или TLS, который никто ещё не пробовал.
