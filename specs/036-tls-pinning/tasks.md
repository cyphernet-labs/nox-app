# Tasks: TLS с пиннингом по отпечатку ключа сервера

**Input**: Design documents from `/specs/036-tls-pinning/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/wire-delta.md](./contracts/wire-delta.md), [quickstart.md](./quickstart.md)

**Tests**: включены. Спека требует их прямо — SC-005 закрывается только положительными проверками терпимости, SC-007 только проверкой непоследствий, — а конституция требует локального гейта, пока CI на паузе.

**Organization**: задачи сгруппированы по user story. Порядок фаз — не вкусовой: контракт правится первым (Принцип VII), ключ раньше сертификата, тестовые хелперы раньше перевода слушателя.

**Гейт снят 2026-09-14.** Прежнее «не начинать до живого прогона 034/035» относилось к отменённой фазе и к двум смерженным.

**Три слова, которые нельзя путать**: **ключ** — ECDSA-пара личности машины в `server_identity`; **отпечаток** — `sha256(SPKI)`, тридцать два байта в ссылке и в сессии; **пиннинг** — операция сверки.

## Dependencies

```
Phase 1 (Setup)
   └─► Phase 2 (Foundational: контракт + ключ + TLS-хелперы)
          ├─► Phase 3 (US1) ──┐
          ├─► Phase 4 (US2) ──┤
          │                   ├─► Phase 5 (US3)
          └─► Phase 6 (US4) ──┘
                              └─► Phase 7 (Polish)
```

**US1 и US2 не отгружаются по отдельности, и это честнее сказать, чем изобразить независимость.** Как только слушатель становится TLS, клиент обязан уметь принять самоподписанный сертификат — то есть механизм пиннинга нужен уже для US1. Разделены они не по коду, а по вопросу, на который отвечают: US1 про **нечитаемость**, US2 про **подлинность**. Шифрование без аутентификации — это защита от прохожего и никакая от того, кто может встать посередине, поэтому «US1 готова» без US2 не означает ничего.

**US3 зависит от US2**: отказ, который надо показать, до неё не происходит.

**US4 независима** и делается в любой момент после Phase 2.

## Implementation strategy

**MVP** — Phase 1 → 2 → 3 → 4. На этом канал закрыт и подмена не проходит; фаза делает то, ради чего заведена.

**Дальше по ценности**: Phase 5 (US3) — она не добавляет защиты, но без неё единственный новый режим отказа неотличим от мёртвой сети, и человек чинит роутер, пока приложение говорит с чужим сервером.

**Phase 6** — одна задача и один тест, делается когда удобно.

**Phase 7** закрывается целиком перед мержем: гейты и живой прогон — часть определения готовности, а не полировка.
