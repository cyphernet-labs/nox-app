# Quickstart: проверка фазы 033

Как убедиться, что владелец назван и доезжает. Сценарии соответствуют пользовательским историям спеки.

## Предусловия

```bash
cd client_backend && CGO_ENABLED=0 go build -o /tmp/noxd .
```

Адрес привязки — **LAN-адрес машины**, а не loopback: иначе ссылка-приглашение из фазы 032 не дозвонится со второго устройства.

```bash
rm -f /tmp/nox033.db* && /tmp/noxd -addr <LAN-IP>:8080 -db /tmp/nox033.db
```

Ссылка для claim печатается в вывод запуска. Приложение — `fvm flutter run -d macos --dart-define-from-file=config/stage.json`.

Чистая установка на macOS требует стереть **и** контейнер, **и** keychain:

```bash
rm -rf ~/Library/Containers/com.cyphernetlabs.noxapp
security delete-generic-password -s flutter_secure_storage_service -a session.device_secret
```

## Автоматические проверки

```bash
cd client_backend && go test -race ./...    # владение в хранилище и на проводе
make gate                                    # клиентская половина
make golden-verify                           # отметка на обеих ширинах
```

## US1 — хозяин видит, что машина его

1. Чистая установка, вставить claim-ссылку, выбрать имя.
2. Открыть корень настроек.

**Ожидается**: рядом с именем стоит отметка владения. На широком окне — та же отметка в панели настроек.

**Проверка со стороны сервера**:

```bash
sqlite3 /tmp/nox033.db "SELECT owner_user_id, claimed_at FROM server_identity;"
sqlite3 /tmp/nox033.db "SELECT user_id, label FROM users;"
```

`owner_user_id` совпадает с `user_id` единственной личности; `claimed_at` заполнен, но ни одно правило его не читает.

## US2 — признак доезжает от сервера

1. С владельца выпустить приглашение устройства (`Settings → Devices → Add a device`).
2. Спарить второе устройство (iOS-симулятор или Android в той же сети).

**Ожидается**: второе устройство — **то же самое** лицо, поэтому отметка владения на нём тоже есть. Это не ошибка: владение принадлежит личности, а не аппарату (FR-014).

**Что подтверждает провод**: в журнале сервера видны `pair`, затем `session.hello` на другом соединении. Ответ на `pair` уже нёс владение — второе устройство не ждало приветствия.

Сценарий «не владелец» сегодня недостижим: на сервере один человек. Он появится в фазе 034 и проверяется там.

## US3 — владение переживает потерю всех устройств

1. Отозвать все устройства (или выйти с каждого).
2. Перезапустить сервер — он снова печатает claim-ссылку.
3. Предъявить её с чистой установки.

**Ожидается**: возвращается **та же** личность с тем же именем, той же перепиской и той же отметкой владения. Экран выбора имени не показывается.

**Проверка**:

```bash
sqlite3 /tmp/nox033.db "SELECT COUNT(1) FROM users;"   # ровно 1, вторая личность не завелась
sqlite3 /tmp/nox033.db "SELECT owner_user_id FROM server_identity;"  # тот же id, что и был
```

## Отрицательные проверки

| Что проверяем | Как | Ожидается |
|---|---|---|
| Claim на занятом сервере | предъявить второй claim-токен, пока есть устройство | отказ; владелец не изменился |
| Приложение не выдумывает владение | запустить приложение офлайн после выхода | отметки нет |
| Признак стирается при выходе | выйти, посмотреть prefs | ключа `session.is_owner` нет |
| Хранилище без владельца | вручную `UPDATE server_identity SET owner_user_id = NULL` при живой личности | сервер стартует, пишет предупреждение, владельца не выбирает |
| Владение не течёт в журналы | `grep` по выводу сервера и приложения | нет строки, где признак владения стоит рядом с идентификатором личности |
