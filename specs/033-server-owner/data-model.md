# Data Model: Сервер знает своего владельца

**Фаза 1** для [plan.md](./plan.md). Решения и их обоснования — в [research.md](./research.md).

## Сервер — SQLite

### `server_identity` (изменяется)

Единственная строка машины. Уже хранит её пару ключей и отметку «когда забрали»; получает ссылку на владельца.

| Поле | Тип | Было | Стало |
|---|---|---|---|
| `id` | INTEGER PK, `CHECK (id = 1)` | ✓ | без изменений |
| `public_key` | TEXT NOT NULL | ✓ | без изменений |
| `private_key` | TEXT NOT NULL | ✓ | без изменений |
| `claimed_at` | INTEGER NULL | **решающее** | **только информация** — «когда забрали», для статусной страницы 035 |
| `owner_user_id` | TEXT NULL | — | **новое.** Внешний ключ на `users(user_id)`. `NULL` ⇔ машина не забрана |

**Правила**:

- `owner_user_id IS NOT NULL` — единственное определение «сервер забран». Ни одна ветка не решает по `claimed_at` (FR-005).
- Единственность владельца обеспечена **строкой**: `CHECK (id = 1)` уже гарантирует одну строку, значит и одну ссылку. Отдельный индекс не нужен (FR-004).
- Внешний ключ на `users` — с `ON DELETE` по умолчанию (`NO ACTION`): личность владельца удалить, не сняв владение, нельзя. Личности сегодня и не удаляются — удаляются только устройства, — но ограничение делает будущий отзыв человека (открытый вопрос) явной работой, а не тихой порчей ссылки.
- Правка идёт в `001_init.sql` **на месте**: развёрнутых баз нет (пре-релизное правило владельца 2026-08-27).

### `users` (не изменяется)

Ролей не хранит. Владение записано у машины, а не у человека — см. [research.md](./research.md) Р1.

### Состояния машины

| Состояние | `owner_user_id` | Что означает | Как достигается |
|---|---|---|---|
| Не забрана | `NULL` | claim принимается | пустое хранилище, первый запуск |
| Забрана | ссылка на личность | claim отвергается, пока есть устройства | первый успешный claim |
| Забрана, устройств нет | ссылка сохраняется | claim принимается **снова** и **переприсоединяет** к той же личности | отозвано последнее устройство (выход) |
| Аномалия | `NULL`, но личности есть | считается «не забрана»; предупреждение в журнал, старт продолжается | только ручная правка базы |

Переход «забрана → не забрана» **отсутствует**: владение не снимается ничем. Сервер, потерявший все устройства, остаётся забранным — просто снова пускает своего владельца внутрь.

## Сервер — типы Go

### `store.ServerIdentity` (изменяется)

Добавляется `OwnerUserID string` (пусто ⇔ не забрана). Появляется предикат «забрана», который читают три места решения вместо `claimed_at`.

### `store.Identity` (изменяется)

| Поле | Роль |
|---|---|
| `UserID`, `Label` | без изменений |
| `Created` | без изменений — описывает **ответ**, не личность |
| `Owner` | **новое.** Владеет ли **эта** личность сервером |

`Owner` описывает личность и потому **устойчив**: в отличие от `Created`, он одинаков в любом ответе про одного и того же человека. Заполняется и в `ResolveIdentity` (приветствие), и в `Pair`.

## Провод — контракт v0

Объект `identity` в ответе на приветствие (§3) и в ответе на `pair` (§8A) получает булево поле владения. Пишется **всегда**, без `omitempty`: пропавшее `false` читается как «не заявлено» (урок `created` из фазы 032).

Точная форма — в [contracts/](./contracts/).

`device.list` не меняется (FR-016).

## Клиент — Dart

### `ServerIdentity` (изменяется)

Добавляется `bool? owner`. Нулевой тип по той же причине, что у `created`: `null` = «сервер не заявил» (старый сервер или кадр без поля), и это **не** то же самое, что «не владелец». `false` рисует отсутствие отметки; `null` тоже — но по другой причине, и различие важно для FR-022.

### `SessionModel` (изменяется)

Добавляется `bool? isOwner` рядом с `authorId`. Тоже нулевой: `null` = «ещё ни разу не слышали от сервера».

### Хранение

| Ключ | Хранилище | Почему |
|---|---|---|
| `session.is_owner` | `SharedPreferences` | признак роли, а не доступа; политика проекта кладёт в защищённое хранилище только то, что даёт доступ |

Стирается в `SessionRepository.clear()` вместе с остальными ключами сессии (FR-020). При `discardSignIn()` — тоже: несостоявшийся вход не оставляет следа о владении.

### Поток

```
pair reply ──┐
             ├─→ SessionRepository.adoptServerIdentity(authorId:, label:, owner:) ──→ prefs
hello reply ─┘                                                                          │
                                                                                        ▼
                                                       SettingsRootBloc ──→ AppIdentityCardWidget
```

Оба кадра ведут в **одну** точку записи, как `authorId` и `label` сегодня. Второй путь означал бы второй способ разойтись.
