# Data Model: Remote-Data-Source Seam

> **Superseded (Feature 017):** `ChatFilesRemoteDataSource` / `GetChatFilesApi` were **retired**. Chat files are not a network resource — they are a local derivation from the persisted `MessageDao` attachments (`MessageRepository.chatFiles(chatId)`, newest-first), so `ChatRepository.getChatFiles` delegates there. The rows below are the historical 016 catalog; ignore the `ChatFilesRemoteDataSource` entries.

No persisted data, no domain entities. The "model" here is the **interface catalog** and the **DI binding table**. Method signatures mirror the current `*Api.execute(...)` exactly (byte-for-byte behaviour).

## Interface catalog (`lib/data/remote/datasource/`)

| Interface | Method(s) | Signature (mirrors today) | Backed by (mock generator) |
|-----------|-----------|---------------------------|-----------------------------|
| `ChatRemoteDataSource` | `getChats` | `Future<(List<ChatModel>, PageMetadata)> getChats({required GetChatsConfig config})` | `GetChatsApi.execute` |
| `ChatFilesRemoteDataSource` | `getChatFiles` | `Future<List<MessageAttachment>> getChatFiles({required String chatId})` | `GetChatFilesApi.execute` |
| `MessageRemoteDataSource` | `getMessages`, `sendMessage` | `Future<(List<MessageModel>, PageMetadata)> getMessages({required GetMessagesConfig config})` · `Future<MessageModel> sendMessage({required String chatId, required String authorId, required String authorLabel, String? text, MessageAttachment? attachment})` | `GetMessagesApi.execute` · `SendMessageApi.execute` |
| `ItemRemoteDataSource` | `getItems` | `Future<ResponseEntity<ItemsEntity>> getItems({required GetItemsConfig config})` | `GetItemsApi.execute` |

Notes:
- Signatures are copied verbatim from the current generators (same params, same return tuples/types) — the interface adds no shaping (FR-002/FR-011).
- `MessageRemoteDataSource.sendMessage` carries the feature-015 `authorId`/`authorLabel` params already on `SendMessageApi.execute`.
- `ItemRemoteDataSource.getItems` keeps the `ResponseEntity<ItemsEntity>` return (the Item harness's wire-shaped path); populating `EntityConverter` for chat/message is S4, out of scope.

Each mock impl is a thin forwarder — no data logic (that stays in the unchanged generators).
