# Quickstart — проверка фазы 030

Как убедиться, что фича работает. Сначала автоматические проверки, затем живой сценарий на двух клиентах, который проверяет то, чего автоматика не видит.

---

## 1. Автоматические проверки, по порядку

```bash
# 1. Сервер: гонки обязательны, не опциональны
cd client_backend && gofmt -l . && go vet ./... && go test -race ./...

# 2. Клиент: полный гейт (generate → format → analyze → test)
cd .. && make gate

# 3. Снимки экранов — UI не менялся, все 216 обязаны совпасть
make golden-verify
```

Что доказывает каждая:

| Проверка | Что именно закрывает |
|---|---|
| `go test -race` | девять инвариантов опознания ([identity-resolution.md](./contracts/identity-resolution.md) §7), три пути сравнения личности, отказ старта на устаревшей схеме |
| `make gate` | производная `login_ref` совпадает с контрольным вектором контракта; сброс мира при смене `journal_id`; заявление имени только после переименования |
| `make golden-verify` | UI действительно не изменился. Любое расхождение здесь — регресс, а не ожидаемое обновление: базовые снимки **не** перегенерируются в этой фазе |

## 2. Живой сценарий на двух клиентах

Проверяет SC-001, SC-002, SC-003 и SC-005 — то, что видно только человеку.

### 2.1. Чистый старт

Сервер — обязательно с нуля: правленая `001_init.sql` к существующей базе **не применится**, и сервер откажется стартовать.

```bash
pkill -f noxd
rm -rf /tmp/nox-demo/demo.db /tmp/nox-demo/demo.db-wal /tmp/nox-demo/demo.db-shm /tmp/nox-demo/demo.db-files
cd client_backend && go build -o /tmp/nox-demo/noxd . && cd ..
cd /tmp/nox-demo && ./noxd -addr 127.0.0.1:8080 -db /tmp/nox-demo/demo.db
```

Клиенты стирать **не нужно**: смена `journal_id` должна сбросить локальный мир сама. Это и есть проверка FR-024 — если после чистого старта сервера установленный клиент продолжает работать и получать новое, требование выполнено. Если он молча оглох — фича не готова.

### 2.2. Два разных человека

> ⚠️ Оба клиента входят **разными** идентификаторами: два произвольных непохожих значения, вставленных в `Your ID`. Значения `demo` и `registered` — зарезервированные, они считаются уже зарегистрированными и пропускают экран выбора имени; для этого сценария они не годятся.

**Записать оба идентификатора** — они понадобятся в §2.4.

- Десктоп: свой идентификатор → **Sign in** → имя `Anna`
- Телефон: другой идентификатор → имя `Boris`

Создать чат, обменяться сообщениями. **Ожидается:** у каждого свои сообщения справа, чужие слева.

### 2.3. Переименование не переписывает прошлое (SC-003)

На десктопе: **Settings → имя → `Anna2`** → отправить второе сообщение.

**Ожидается:** первое сообщение по-прежнему справа и подписано `Anna`, второе — `Anna2`. **Без ручного переподключения**: переименование перезапускает живой канал само.

На телефоне после переподключения имя автора новых сообщений — `Anna2`, старых — `Anna`. Телефон при этом **не** возвращает `Anna` обратно на сервер.

### 2.4. Переустановка не стирает человека (SC-002) — главный сценарий

На десктопе: **Settings → Log out**, затем войти **тем же идентификатором**, что был записан в §2.2.

**Ожидается:** прошлые сообщения снова размечены как собственные, `Anna2` на месте. Это то, чего сегодняшний сервер не умеет вообще.

Жёсткая версия того же — полное стирание локального состояния:

```bash
rm -f ~/Library/Containers/com.cyphernetlabs.noxapp/Data/Documents/app_dev.db
rm -f ~/Library/Containers/com.cyphernetlabs.noxapp/Data/Library/Preferences/com.cyphernetlabs.noxapp.plist
defaults delete com.cyphernetlabs.noxapp; killall cfprefsd
security delete-generic-password -s flutter_secure_storage_service -a session.identifier
```

Затем запустить и войти тем же идентификатором — результат обязан быть тот же. На iOS для честной проверки нужен `xcrun simctl erase`: keychain переживает удаление приложения.

### 2.5. Прерванная отправка не двоится (SC-005)

Остановить сервер. Отправить сообщение с вложением — повиснет в очереди. **⌘Q** (закрыть целиком, не свернуть), запустить снова, поднять сервер.

**Ожидается:** сообщение появляется **ровно один раз**, повторной отправки нет, у отправителя видно превью картинки. Двойной пузырь означает, что автор не получил собственный ключ отправки — то есть одно из трёх мест сравнения личности пропущено.

### 2.6. Журналы чисты (SC-007)

```bash
grep -Eic 'u_[0-9a-f]{16}|[0-9a-f]{64}|Anna2?|Boris' /tmp/nox-demo/noxd.log
```

**Ожидается `0`.** Любое вхождение — нарушение Принципа I.

## 3. Признаки, что что-то пошло не так

| Симптом | Скорее всего |
|---|---|
| Сервер не стартует, ругается на схему | Ожидаемо на старой базе — стереть файл и спутников |
| Клиент подключился, но новых сообщений не видит | Сброс по `journal_id` не сработал — ловушка T3 открыта |
| Свои сообщения выглядят чужими | `session.author_id` от прежнего мира не стёрт при сбросе |
| Сообщение двоится после перезапуска | Пропущено место сравнения личности — ловушка T1 |
| Имя откатывается само | Заявление имени всё ещё безусловное — ловушка T4 |
| После входа унаследовано чужое имя | Приветствие без сессии усвоило личность — ловушка T5 |
