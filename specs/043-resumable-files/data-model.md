# Data Model: Файлы с докачкой

## Сервер

### Строка `files` — без изменений

`file_id, name, size, mime, created_at, expires_at, uploaded, message_id`. Незаконченная загрузка — строка с `uploaded = 0`. Сколько её байтов на сервере, знает пакет `blob`, а не база (research §3). Зачистка прежняя: при старте сервера не привязанные к сообщению строки старше суток удаляются вместе с байтами.

### Каталог файлов

| Файл | Что | Когда появляется и исчезает |
|---|---|---|
| `<id>` | загруженный файл | `Finalize`; `Remove` при зачистке |
| `<id>.part` | незаконченная загрузка: дописывается с конца | первый `PUT`; `Finalize` переименовывает его в `<id>`; `Abort` и `Remove` удаляют |
| `<id>.synced` | **новый.** Десятичная длина начала части, уже сброшенного на носитель | первая точка сохранения; меняется атомарно (временный файл + переименование); `Finalize`, `Abort` и `Remove` удаляют |

**Надёжно получено** = `min(<id>.synced, размер <id>.part)`. Без `<id>.synced` — `0`. У загруженного файла — `size`.

Правила:
- **Длина в `<id>.synced` только растёт**, если не считать `Resume`. Точка сохранения пишет её **после** `fsync` части.
- **`Resume(id, offset)`** отказывает, если надёжно получено меньше `offset`. Иначе он сначала записывает `offset` в `<id>.synced`, затем обрезает часть до `offset`. Это делается до первой новой записи.
- **Точка сохранения** ставится каждые 4 MiB, полученные одним запросом, и в конце каждого запроса — при любом исходе.

### Токен (в памяти) — `tokenEntry`

| Поле | Было | Стало |
|---|---|---|
| `fileID`, `op`, `expires` | ✓ | ✓ |
| `offset` | — | **новое:** смещение, с которого `PUT` по этому токену несёт байты (у токенов скачивания — `0`, не используется) |

Одноразовость и срок 10 минут не меняются. Срок проверяется в начале запроса.

### Реестр писателей (в памяти) — `writers`

`map[fileID] → {прервать(), готово}` под своим мьютексом. Регистрируется `PUT` на время записи.
- `take(fileID)` прерывает прежнего писателя и ждёт его «готово» до 5 с.
- `release()` снимает запись и закрывает «готово».

Прерывание и продление срока чтения идут под одним мьютексом писателя, поэтому прерывание не теряется.

### Состояния незаконченной загрузки

```text
uploadBegin {name,size,mime}                         → строка (uploaded=0), received=0, токен(offset=0)
uploadBegin {…, file_id} — загрузка незакончена      → прерывание прежнего писателя → received=надёжно получено, токен(offset=received)
uploadBegin {…, file_id} — файл загружен             → received=size, токен(offset=size)
uploadBegin {…, file_id} — нет / привязан / вычищен  → not_found
uploadBegin {…, file_id} — name/size/mime не те      → invalid_request
uploadBegin {…, file_id} — писатель не отпустил 5 с  → internal

PUT(токен с offset)
  ├─ байты идут ──► точка сохранения каждые 4 MiB
  ├─ остаток весь ──► Finalize → uploaded=1 → 204
  ├─ пустой остаток, уже uploaded ──► 204
  ├─ застой > 60 с ──► точка сохранения → 408
  ├─ обрыв / прерывание ──► точка сохранения (ответ некому)
  ├─ больше остатка ──► откат к offset (сначала <id>.synced, потом часть) → 413
  ├─ тело кончилось короче остатка ──► точка сохранения → 400
  ├─ надёжно получено < offset ──► 404
  └─ прежний писатель не отпустил за 5 с ──► 409
```

## Приложение

### `UnfinishedUpload` (домен, новый, freezed)

| Поле | Тип | Смысл |
|---|---|---|
| `fileId` | `String` | id файла на сервере, загрузка которого не кончилась |
| `sourceSize` | `int` | размер исходного файла, когда сервер назвал загрузку |
| `sourceModifiedAt` | `DateTime` | время изменения исходного файла тогда же |

Ручка продолжения. Слепок (`sourceSize`, `sourceModifiedAt`) сверяется перед каждой попыткой; не совпал — исходник другой, и продолжать нельзя (`notFound`, окончательно).

### `OutboxEntry` / `OutboxEntity`

| Домен | Хранилище (`outbox`, snake_case на диске) | Когда пишется | Когда стирается |
|---|---|---|---|
| `UnfinishedUpload? upload` | `uploadFileId: String?`, `uploadSourceSize: int?`, `uploadSourceModifiedAt: int?` (мс эпохи) | сервер назвал загрузку и прислал `received` — до первого байта (`noteUpload`) | байты подтверждены (`attachFile`), окончательный отказ загрузки, сервер забыл загрузку или оказался старым (`noteUpload(null)`), запись удалена, выход, смена мира |

Все три поля необязательны: записи, сделанные до 043, читаются как есть. Ручка есть, только если заполнены все три. `fileId` (подтверждённые байты) остаётся как был. Пока он записан, ручки нет.

`markPending` (ручной повтор) сбрасывает оба счётчика и **сохраняет** ручку (FR-011).

### Ответ `file.uploadBegin` — `UploadTicketWireEntity`

`+ received: int?` (`@JsonKey(name: 'received')`). `null` — сервер старше 043: продолжения нет, файл идёт целиком.

### Недокачанный файл (кэш)

| Файл | Что |
|---|---|
| `<кэш>/nox_attachments/<fileId>.<ext>` | скачанный файл (как сегодня; появляется только переименованием) |
| `<…>.part` | недокачанное, дописывается с конца |
| `<…>.part.tag` | **новый.** `Last-Modified` сервера, с которым пришли байты части |

Правила:
- Часть без `.part.tag` не продолжается: она выбрасывается.
- На `200` порядок такой: обрезать часть → записать `.part.tag` → писать тело.
- Перед переименованием длина сверяется с заявленным размером.
- `clean()` удаляет каталог целиком (FR-017).

### Скачивания (в памяти) — `AttachmentDownloadService`

| Состояние на файл | Смысл |
|---|---|
| `result` | одна общая `Future` для всех просивших |
| `listeners`, `lastFraction` | кто слушает прогресс; новый слушатель сразу получает последнюю долю |
| `refusals`, `attempts` | лестница пауз и предел отказов (10); обрыв — только `attempts` |
| `messageId` | куда записать путь, когда байты на месте |

`reset()` очищает всё, отменяет передачи (`FileRepository.cancelTransfers()`) и ждёт циклов.

### Поколение передач (в памяти) — `ApiClient`

Текущий токен отмены. Меняется, когда `initBase` переводит адрес REST на другой, или по `cancelTransfers()`. Отменённое поколение прерывает все свои передачи.

### Доля передачи — `AttachmentTransfer`

Без изменений по форме. После ответа на продолжение доля сразу равна `received/size`, а не `null` или `0`. Документ модели правится: перезапуск больше не начинает файл с первого байта.
