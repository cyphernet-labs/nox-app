# Quickstart: проверка файлов с докачкой

## Гейты

```bash
make gate                       # codegen → format → analyze → tests
make golden-verify              # снимки не меняются — все должны остаться зелёными
(cd client_backend && gofmt -l . && go vet ./... && go test -race ./...)
```

Ожидание: всё зелёное.

**Сервер** (`internal/server`, `internal/blob`):
- продолжение после оборванного `PUT`;
- застой при коротком пределе;
- прерывание висящего писателя;
- надёжная длина короче части после «сбоя»;
- пустой `PUT` завершает загрузку;
- ответы на продолжение;
- медленный, но идущий `GET` дольше предела застоя;
- `If-Range` с датой.

**Приложение:**
- `PUT` с остатком и сторож застоя — против локального TLS-сервера;
- `Range` и `If-Range`;
- ручка продолжения записывается до первого байта;
- сервер забыл загрузку — новая, без ошибки;
- изменённый исходник — ошибка;
- скачивание идёт после закрытия 5.3;
- обрыв не исчерпывает повторы, отказы — исчерпывают.

## Живой зонд: 100 MiB через onion (SC-001 — SC-004)

`test/live/resumable_files_probe.dart` построен на обвязке `tor_live_probe.dart`: свой `noxd` с tor, спаривание дома, «вне дома» через проверку прямых адресов, которая ничего не находит. Он:

1. уходит на Tor и отправляет сообщение с файлом 100 MiB через очередь исходящих;
2. посреди загрузки отменяет передачу (обрыв), потом останавливает и снова запускает очередь — как перезапуск. Каждый раз загрузка продолжается с `received` сервера: по логу `noxd` (`upload resumed … from=`) смещение растёт, а не падает к нулю;
3. посреди второй половины возвращается «домой»: путь прямой, загрузка продолжается напрямую;
4. скачивает тот же файл через `AttachmentDownloadService` на Tor с обрывом посреди и сравнивает байты с отправленными;
5. печатает `MEASURE:` — время загрузки и скачивания через onion, сколько байтов пришло на сервер сверх размера.

```bash
(cd client_backend && go build -o /tmp/noxd .)
fvm flutter test test/live/resumable_files_probe.dart \
  --dart-define=noxd=/tmp/noxd --dart-define=tor=/path/to/tor \
  --dart-define=host=<LAN-адрес машины> --dart-define=work=/tmp/nox_files_e2e
```

Ожидание:
- файл дошёл в обе стороны и совпал побайтово;
- ни одна передача не начиналась с нуля после первой;
- сверх размера пришло не больше того, что было в пути при обрыве (SC-002);
- ни одного `error` у сообщения.

## На стенде (владелец)

Стенд — `noxd` с tor (`scripts/demo-stand.sh`), приложение на `stage`. Вне дома — мобильная сеть телефона или debug-ключ `--dart-define=nox.forceTor=true`.

| # | Действия | Ожидание |
|---|---|---|
| 1 | Вне дома отправить видео 80–100 MiB | кольцо растёт; сообщение уходит, когда байты на сервере (US1) |
| 2 | Посреди загрузки включить и выключить авиарежим | после возврата связи кольцо продолжает с той же доли, не с нуля (US1-1, US1-3) |
| 3 | Посреди загрузки закрыть приложение и открыть снова | загрузка продолжается с того же места (US1-2) |
| 4 | Начать загрузку дома, выйти из дома (Wi-Fi выкл.) | продолжается через Tor (US3-1) |
| 5 | Открыть на 5.3 большой полученный файл вне дома, оборвать связь | полоса стоит и продолжает сама, без `Try again` (US2-1) |
| 6 | Посреди скачивания закрыть 5.3, открыть снова | тот же прогресс или готовый файл (US2-5) |
| 7 | Посреди скачивания перезапустить приложение и открыть файл | скачивание продолжается с того, что уже есть (US2-2) |
| 8 | Картинка подкачивается сама, связь рвётся | после возврата подкачка продолжается (US2-4) |
| 9 | Остановить `noxd` посреди загрузки на 10 минут, запустить | загрузка продолжается сама; сообщение не помечено ошибкой (US4-1) |
| 10 | Выйти из аккаунта посреди скачивания | недокачанного в кэше нет |
