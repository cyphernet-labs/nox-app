# Contract: `chat.create` с id устройства

Изменение контракта v0, §4 (`docs/client-backend/protocol/contract-draft.md`). Остальной провод не меняется.

## Запрос

| Команда | `data` запроса | `data` ответа |
|---|---|---|
| `chat.create` | `{name, chat_id?}` | `{chat: Chat}` |

- `name` — правила прежние (§4): trim, непустое, ≤64 символов, уникальность регистронезависимая в пределах сервера.
- `chat_id` — **необязательный**. Id, который придумало устройство: `c_` и ровно 32 шестнадцатеричных знака в нижнем регистре (`^c_[0-9a-f]{32}$`).

```json
{"id": 12, "cmd": "chat.create", "data": {"chat_id": "c_5f0e9c1d2a3b4c5d6e7f8091a2b3c4d5", "name": "Kitchen"}}
```

## Поведение сервера

Всё — в одной пишущей транзакции, в этом порядке:

1. `chat_id` есть, но не того вида → `invalid_request`.
2. `chat_id` есть, и чат с таким id уже существует → ответ `{chat}` с этим чатом **в нынешнем виде**; ничего не пишется, события нет. Имя запроса не сравнивается — это повтор.
3. Имя занято другим чатом → `name_taken`.
4. Иначе — чат с id `chat_id` (или серверным `c_` + 16 hex, если `chat_id` нет) и событие `chat.created` в той же транзакции.

```json
{"id": 12, "ok": true, "data": {"chat": {"chat_id": "c_5f0e9c1d2a3b4c5d6e7f8091a2b3c4d5", "name": "Kitchen",
  "created_at": 1759600000, "created_by_label": "Anna", "last_message_preview": "", "last_activity_at": 1759600000}}}
```

Событие `chat.created` несёт тот же `chat_id`.

## Совместимость

- Новое необязательное поле не требует признака поддержки (§2.1): сервер, который о нём не знает, пропускает его и придумывает id сам.
- Сработало ли поле, клиент видит по ответу: если `chat.chat_id` в ответе не тот, что он прислал, сервер старый — клиент принимает id сервера (переносит на него сообщения в очереди и убирает локальную копию).
- Клиент без `chat_id` работает как раньше.

## Коды отказов

| Код | Когда | Клиент |
|---|---|---|
| `invalid_request` | неверный вид `chat_id` или `name` | состояние «не создан», `Try again` |
| `name_taken` | имя занято другим чатом | состояние «имя занято», ждёт переименования |
| `internal`, `rate_limited` | как везде (§2.1) | повтор с паузой, «ждёт создания» |
