# Quickstart: проверка чата без связи

## Что нужно

- Сервер с этой фичей: `go build -o /tmp/noxd ./client_backend/cmd/noxd` (или `scripts/demo-stand.sh`).
- Приложение на флейворе `stage`: `fvm flutter run --dart-define-from-file=config/stage.json -d <устройство>`.
- Два устройства одного человека (например, Мак и телефон), спаренные с этим сервером.

## Автоматические проверки

```sh
make gate                      # тесты клиента, без голденов
make golden-verify             # голдены трёх категорий, обе ширины
(cd client_backend && go test -race ./...)
```

Ожидание: всё зелёное; среди тестов — повтор `chat.create` с тем же `chat_id` (один чат, одно событие), проверка id раньше имени, неверный вид id, удержание сообщений ждущего чата, исходы `name_taken` / `failed` / другой id.

## Сценарий 1 — создать без связи (US1, SC-001, SC-002)

1. На телефоне выключить сеть (или остановить сервер).
2. Создать чат «Kitchen» — он сразу в списке, вместо времени часики.
3. Открыть, написать три сообщения — у каждого часики; плашка `This chat isn't on your server yet. It will be once NOX connects.`
4. Включить сеть (или сервер).

Ожидание: часики в строке пропадают, плашка уходит, сообщения по очереди получают галочку. На Маке появляется «Kitchen» с этими тремя сообщениями.

## Сценарий 2 — создание при связи не ждёт (US2)

1. На подключённом устройстве создать чат.

Ожидание: чат открывается сразу; часики в строке списка — меньше секунды на прямом пути.

## Сценарий 3 — имя занято (US3, SC-004)

1. На Маке (со связью) создать «Kitchen 2».
2. На телефоне без связи создать «Kitchen 2», написать сообщение.
3. Включить сеть на телефоне.

Ожидание: в списке у чата знак ошибки и `Name already taken`; в ленте плашка `Another chat already has this name. Rename this one to finish creating it.` с действием `Rename`; сообщение с часиками, не ошибка.

4. Нажать `Rename`, ввести «Kitchen 3».

Ожидание: чат создаётся, сообщение уходит; на Маке появляется «Kitchen 3».

## Сценарий 4 — повтор после обрыва (US4, SC-003)

Покрыт тестами сервера: повтор `chat.create` с существующим `chat_id` возвращает тот же чат, событий одно, `name_taken` не приходит.

## Сценарий 5 — старый сервер (US5)

Покрыт тестом очереди: фейковый источник отвечает другим id — в списке один чат под id сервера, сообщения перенесены на него.
