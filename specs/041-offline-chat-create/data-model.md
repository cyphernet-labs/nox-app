# Data Model: Чат без связи

## ChatCreation (домен, новое)

Состояние чата, которого ещё нет на сервере. Отсутствие значения — чат на сервере.

| Значение | Смысл | Что делает очередь |
|---|---|---|
| `pending` | ждёт создания | создаёт при первом текущем канале; повторяемые отказы — с паузами |
| `nameTaken` | сервер ответил `name_taken` | ничего, пока человек не переименует |
| `failed` | прочий окончательный отказ | ничего, пока человек не нажмёт `Try again` |

Хранится в сущности строкой: `pending`, `name_taken`, `failed`.

## ChatModel (домен, меняется)

| Поле | Тип | Новое | Смысл |
|---|---|---|---|
| `creation` | `ChatCreation?` | да | состояние создания; `null` — чат на сервере |

Остальные поля без изменений.

## ChatEntity (Sembast `chats`, меняется)

| Поле | Тип | Новое | Смысл |
|---|---|---|---|
| `creation` | `String?` | да | `pending` / `name_taken` / `failed`; отсутствует у чатов, принятых сервером, и у всех старых записей |
| `creationAttempts` | `int?` | да | сколько раз создание провалилось повторяемо; основа паузы, переживает перезапуск |

Старые записи читаются без изменений: оба поля необязательны и отсутствуют.

## Переходы состояния

```text
                createChat (устройство)
                        │
                        ▼
                    pending ──── повторяемый отказ ──► pending (попытки +1, пауза)
                    │   │  ╲
     принят (тот же id) │   ╲ name_taken            прочий отказ
                    │   │    ╲                            │
                    ▼   │     ▼                           ▼
                  (null)│   nameTaken ── renameLocally ─► pending
                        │                                  ▲
                        │   failed ──── retryCreation ────┘
                        │
     принят (другой id) ▼
       перенос сообщений на id сервера, локальная строка удаляется

     событие chat.created / chat.updated с этим id ──► (null) из любого состояния
     выход / смена мира ──► строка удалена
```

## Очередь исходящих (без изменения схемы)

- Записи сообщений не меняются. Сообщение чата с `creation != null` очередь пропускает без попытки — оно остаётся `pending`.
- **`OutboxRepository.moveChat({from, to})`** (новое) переносит записи очереди с одного id чата на другой — только для старого сервера (research, п. 5).

## Id чата

- Устройство: `c_` + 32 hex в нижнем регистре, `Random.secure()` (`lib/general/id/chat_id.dart`).
- Сервер: `c_` + 16 hex, как раньше.
- Проверка вида на сервере: `^c_[0-9a-f]{32}$` для присланного `chat_id`.

## Сервер (SQLite) — без изменения схемы

`chats.chat_id` уже ключ. `CreateChat` получает `chatID`: если строка с ним есть — возврат без записи; иначе проверка имени и вставка с этим id и событием `chat.created` в одной транзакции.
