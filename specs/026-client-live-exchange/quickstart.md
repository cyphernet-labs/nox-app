# Quickstart: локальная проверка фазы 026

## Автоматическая валидация

```bash
make gate            # generate → format → analyze → test
make golden-verify   # 216 baseline — внешний вид не меняется (SC-005)
```

Новые сьюты: `test/data/remote/socket/` (конверт, корреляция по `id`, backoff, дедупликация), `test/data/remote/datasource/real/`, `test/data/repository/sync/` (эпоха источника), обновлённые тесты `GetMessagesConfig` (кламп к 100) и `chat_thread_bloc` (рефреш читает только новейшую порцию).

Тестовое окружение остаётся на моках, поэтому весь набор проходит **без запущенного сервера**.

## Живая проверка вертикали (главное — ради неё фаза и делается)

Нужны два клиента. Второй — это `websocat`, чтобы не собирать приложение дважды.

```bash
# 1. Поднять сервер
cd client_backend && go build -o /tmp/noxd . && /tmp/noxd -addr 127.0.0.1:8080 -db /tmp/nox-live.db

# 2. Запустить приложение (dev-флейвор смотрит на живой сервер)
fvm flutter run --dart-define-from-file=config/stage.json -d macos
```

**Сценарий US1 — данные приходят с сервера.** Создать чат вторым клиентом и убедиться, что он появился в приложении:

```bash
( printf '%s\n' '{"id":1,"cmd":"session.hello","data":{"schema":1,"label":"Boris","since":0}}' ; sleep 1 ;
  printf '%s\n' '{"id":2,"cmd":"chat.create","data":{"name":"From Boris"}}' ; sleep 2 ) \
  | websocat -t ws://127.0.0.1:8080/ws
```

Ожидаемо: чат `From Boris` виден в списке приложения; открыть его — тред пуст (истории ещё нет).

**Сценарий US2 — обмен.** Отправить сообщение из приложения → оно должно прийти Борису; отправить Борисом → должно само появиться в открытом треде.

```bash
# слушать события: канал должен ОСТАВАТЬСЯ открытым, иначе stdin закроется
# сразу после приветствия и соединение оборвётся
( printf '%s\n' '{"id":1,"cmd":"session.hello","data":{"schema":1,"label":"Boris"}}' ; sleep 600 ) \
  | websocat -t ws://127.0.0.1:8080/ws
```

Замер SC-002: сравни время события в журнале сервера с моментом появления сообщения на экране — должно укладываться в секунду.

**Сценарий US3 — обрыв и догон.** Остановить сервер (Ctrl+C) — приложение показывает «нет связи», загруженная история остаётся. Поднять сервер обратно, дослав перед этим пару сообщений вторым клиентом, — приложение переподключается и показывает пропущенное **ровно по одному разу**.

**Сценарий SC-007 — объём не тормозит показ.** Насыпь на сервер ≥200 чатов и чат с ≥1000 сообщений (цикл `websocat` или короткий Go-скрипт), затем открой список и этот чат. В журнале сервера должно быть **по одному** `chats.list` и `messages.list` на открытие — а не обход всех страниц; время показа не должно заметно отличаться от маленького набора.

**Смена мира данных.** Первый запуск против живого сервера обязан один раз очистить локальный мок-мир: в списке не должно остаться ни одного чата вида `Design crit`, `Garden` и прочих мок-имён.

## На что смотреть в логах сервера

```
"msg":"client connected"      # приветствие принято
"seq":N                        # каждое событие журнала
```

Расхождение поведения приложения с контрактом чинится **в клиенте** (Принцип VII): сервер — эталонная реализация.
