# Feature Specification: Экраны этапа M1 — Splash и простые автономные экраны

**Feature Branch**: `004-splash-simple-screens`

**Created**: 2026-06-20

**Status**: Draft

**Input**: User description: "Запланировать работу из `docs/roadmap.md` — Этап M1 — Splash + простые автономные экраны"

## Контекст фичи

Фаза 1 проекта (см. `docs/roadmap.md`) — сборка визуального слоя приложения по одному экрану; **интеграция с бэкендом вне scope**. Каркас «Галереи экранов» (этап M0) уже готов: на главном экране есть кнопка `Open Screens` → `ScreensGalleryPage` со списком всех экранов карты, где каждая строка активируется по мере реализации экрана.

Эта фича закрывает **этап M1** — семь экранов, не требующих плагинов (камера/файлы/QR) и низкорисковых: **Splash (1.1)**, **универсальный экран ошибки (3.1)**, **Внешний вид (7.3)**, **Язык (7.4)**, **Уведомления (7.2)**, **Terms (7.6)**, **О приложении (7.7)**. Каждый экран реализуется как самостоятельный, открываемый из Галереи экранов, мультиплатформенный (мобайл + десктоп), со всеми визуальными состояниями на заглушечных данных, в соответствии с зафиксированными спеками `docs/design/spec/screens/` и десктоп/мобайл-корпусами.

Связывание экранов в продуктовый флоу и реальные данные — отдельная (backend) фаза.

## Clarifications

- Q: Десктоп-раскладка экранов без выделенного desktop-корпуса (Appearance/Language/Notifications/Terms/About) при открытии из Галереи → A: Одна полнооконная панель с ограниченной по ширине/центрированной колонкой; master-detail settings-shell — это этап M3, здесь не строится.
- Q: Поведение Splash после завершения анимации при открытии из Галереи (реальные 2.1/4.1 ещё не построены) → A: Исход выбирается debug-переключателем (has-ID/no-ID/error); по завершении анимации — переход к placeholder для shell/login, а для исхода error — к реальному экрану ошибки 3.1 в блокирующем режиме.
- Q: Источник иконок универсального экрана ошибки (спека: Material; kit: SVG-only) → A: Только SVG `NoxIcons`; недостающие семантические глифы (wifi/cloud) добавляются как новые SVG в дизайн-систему; Material icon-шрифт не подключается.
- Q: Оформление single-select опций на Appearance и Language → A: Appearance — карточки с мини-превью темы (по мобайл-корпусу); Language — простые radio-строки (`RadioListTile`), без флагов.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Брендовый запуск (Splash) (Priority: P1)

При холодном старте пользователь видит брендовый экран запуска: цветной логотип NOX и подпись «NOX» по центру тёмного фона с короткой анимацией появления; по её завершении приложение маршрутизирует пользователя дальше.

**Why this priority**: Первое впечатление и опорный брендовый момент продукта; головной экран этапа M1 и первая задача дорожной карты.

**Independent Test**: Открыть Splash из Галереи экранов на узком и широком окне; убедиться, что логотип + wordmark появляются на brand-fixed тёмном фоне с одноразовой reveal-анимацией (без циклов) и что по её завершении выполняется переход к (заглушечному) следующему экрану.

**Acceptance Scenarios**:

1. **Given** экран Splash открыт, **When** он появляется, **Then** по центру на тёмном фоне (одинаковом в светлой и тёмной теме) показаны цветной логотип и wordmark «NOX», и один раз проигрывается анимация появления (opacity 0→1, scale 0.85→1.0, ~400 мс, плавное замедление), после чего изображение статично.
2. **Given** анимация ещё идёт, а заглушка состояния авторизации уже вернула результат, **When** результат получен раньше конца анимации, **Then** переход не происходит до завершения анимации.
3. **Given** Splash виден, **When** пользователь тапает/свайпает/жмёт системный back, **Then** ничего не происходит (экран пассивен), системные жесты ОС работают штатно.
4. **Given** заглушка возвращает «идентификатор есть» / «идентификатора нет» / «ошибка чтения», **When** анимация завершилась, **Then** выполняется переход к заглушке шелла / логина / блокирующего экрана ошибки соответственно.

---

### User Story 2 — Универсальный экран ошибки (Priority: P2)

При фатальном/неожиданном сбое пользователь видит единый понятный экран с иконкой, заголовком, сообщением и кнопкой `Try again`; экран используется во многих потоках в двух режимах — блокирующем и встраиваемом.

**Why this priority**: Переиспользуемая основа, на которую опираются другие экраны и будущие потоки; полностью реализуема без бэкенда.

**Independent Test**: Открыть экран ошибки из Галереи в обоих режимах и для нескольких пресетов параметров; убедиться, что блокирующий режим не имеет стрелки back, встраиваемый — имеет, и что `Try again` показывает состояние повтора.

**Acceptance Scenarios**:

1. **Given** экран ошибки в блокирующем режиме, **When** он показан, **Then** нет стрелки back, отображаются иконка, заголовок, сообщение и кнопка `Try again`.
2. **Given** экран ошибки во встраиваемом режиме, **When** он показан, **Then** присутствует стрелка back, которая возвращает назад.
3. **Given** экран ошибки, **When** пользователь нажимает `Try again`, **Then** кнопка переходит в состояние повтора (в UI-only — заглушка обработчика).
4. **Given** широкое окно (десктоп), **When** экран показан, **Then** содержимое выводится в оконной раскладке с TitleBar, иконка крупнее.

---

### User Story 3 — Внешний вид: выбор темы (Priority: P2)

Пользователь выбирает тему оформления — System / Light / Dark — и она немедленно применяется ко всему приложению.

**Why this priority**: Единственный экран M1 с реально работающей функцией (живое переключение темы через существующий контроллер темы приложения) — наглядная демонстрация ценности.

**Independent Test**: Открыть Appearance из Галереи, переключить тему и убедиться, что оформление мгновенно меняется на всех видимых поверхностях; текущее значение отражает фактическое состояние приложения.

**Acceptance Scenarios**:

1. **Given** экран Appearance, **When** он показан, **Then** есть три взаимоисключающих варианта System / Light / Dark, и отмечен текущий (по умолчанию System).
2. **Given** выбран один из вариантов, **When** пользователь его выбирает, **Then** тема приложения немедленно переключается на выбранную и выбор визуально отмечен.

---

### User Story 4 — Язык интерфейса (Priority: P3)

Пользователь выбирает язык интерфейса — System / English / Українська.

**Why this priority**: Простой экран выбора; полноценная живая перерисовка зависит от ещё не существующего слоя локализации и в этой фазе заглушена.

**Independent Test**: Открыть Language из Галереи, выбрать вариант и убедиться, что выбор фиксируется и отмечается; System выбран по умолчанию.

**Acceptance Scenarios**:

1. **Given** экран Language, **When** он показан, **Then** есть три взаимоисключающих варианта System / English / Українська, по умолчанию отмечен System.
2. **Given** выбран вариант, **When** пользователь его выбирает, **Then** выбор отмечается и сохраняется в пределах сессии (полная live-перерисовка интерфейса — вне scope до появления l10n).

---

### User Story 5 — Уведомления (Priority: P3)

Пользователь включает/выключает push-уведомления (только по «своим» чатам); при отсутствии системного разрешения видит баннер с переходом в системные настройки.

**Why this priority**: Простой экран-настройка с одним переключателем; реальное разрешение ОС и доставка вне scope.

**Independent Test**: Открыть Notifications из Галереи, потогглить переключатель; смоделировать состояние «разрешение отклонено» и убедиться, что показывается баннер с действием перехода в настройки.

**Acceptance Scenarios**:

1. **Given** экран Notifications, **When** он показан, **Then** есть один переключатель push on/off с поясняющим текстом (push только по своим чатам).
2. **Given** смоделировано «системное разрешение отклонено», **When** экран показан, **Then** отображается информационный баннер с действием «открыть системные настройки» (само действие в UI-only — заглушка).

---

### User Story 6 — Правовая информация и «О приложении» (Priority: P3)

Пользователь читает правовую информацию (Terms/Privacy, bundled) с версией приложения в подвале и отдельно видит экран «О приложении» с версией и билдом.

**Why this priority**: Статичные read-only экраны; самые простые, без бэкенда.

**Independent Test**: Открыть Terms — увидеть прокручиваемые озаглавленные секции и версию в подвале; открыть About — увидеть строку версии/билда.

**Acceptance Scenarios**:

1. **Given** экран Terms, **When** он показан, **Then** отображаются read-only прокручиваемые озаглавленные секции (placeholder-контент) и подвал с версией приложения; флоу принятия отсутствует.
2. **Given** экран About, **When** он показан, **Then** отображается только версия + билд, без лицензий/копирайта/сайта/кредитов.

---

### Edge Cases

- **Splash:** результат заглушки авторизации приходит раньше или позже конца анимации — переход в обоих случаях не раньше завершения анимации.
- **Splash (десктоп):** нативное скрытие оконного чрома (`chrome=false`) — нативная задача вне scope UI-only; на десктопе экран рендерится как полноэкранный контент без удаления чрома ОС.
- **Экран ошибки:** блокирующий режим — последний в стеке; системный back сворачивает приложение, а не уходит назад.
- **Appearance:** выбранная тема сбрасывается после перезапуска приложения (персистентность вне scope) — допустимо в этой фазе.
- **Notifications:** поведение переключателя при отклонённом разрешении (визуально off / переход в настройки) задаётся спекой 7.2.
- **Экраны без выделенного desktop-корпуса** (Appearance/Language/Notifications/Terms/About): десктоп-раскладка выводится из десктоп-конвенций (detail-pane/master-detail) и помечается как допущение.
- **Все экраны:** поведение и компоновка при большом масштабе текста и узком/широком окне не должны ломать вёрстку.

## Requirements *(mandatory)*

### Functional Requirements — сквозные

- **FR-001**: Все семь экранов M1 (Splash, Error, Appearance, Language, Notifications, Terms, About) MUST быть реализованы как самостоятельные экраны, открываемые из «Галереи экранов»; соответствующая строка галереи MUST активироваться (перестаёт быть `Coming soon`).
- **FR-002**: Каждый экран MUST иметь две адаптивные раскладки — мобайл (узкое окно) и десктоп (широкое окно), выбираемые по ширине окна, согласно мобильному и (где есть) десктопному корпусу. Экраны без выделенного desktop-корпуса (Appearance, Language, Notifications, Terms, About) на десктопе MUST рендериться как **одна полнооконная панель с ограниченной по ширине/центрированной колонкой**; master-detail settings-shell — это этап M3 и здесь не строится.
- **FR-003**: Каждый экран MUST корректно отображаться в светлой и тёмной теме и при переключении темы — кроме brand-fixed исключений (тёмный фон Splash).
- **FR-004**: Вся пользовательская микрокопия MUST быть на английском; русского текста в UI быть не должно.
- **FR-005**: Все визуальные состояния каждого экрана, определённые его спекой, MUST быть воспроизводимы на заглушечных данных без бэкенда (где полезно — через локальный демонстрационный переключатель состояний).
- **FR-006**: Любая бэкенд-зависимость (серверные данные, проверки, системные разрешения, реальная маршрутизация по флоу) MUST быть заглушена (фейковый результат/no-op) и помечена как точка будущей замены.
- **FR-007**: Каждый экран MUST быть покрыт автотестами уровня widget и golden (светлая + тёмная темы).

### Functional Requirements — Splash (1.1)

- **FR-010**: Splash MUST показывать цветной логотип NOX и wordmark «NOX» по центру на brand-fixed тёмном фоне, не зависящем от темы (одинаково в светлой и тёмной).
- **FR-011**: При входе MUST один раз проигрываться анимация появления группы «логотип + wordmark» (прозрачность 0→1, масштаб 0.85→1.0, ~400 мс, плавное замедление от центра группы), после чего изображение статично; циклов/пульсаций нет.
- **FR-012**: Splash MUST быть пассивным: тапы, свайпы и системный back не вызывают действий; системные жесты ОС работают штатно.
- **FR-013**: Переход к следующему экрану MUST происходить не раньше завершения анимации; целевой экран определяется состоянием авторизации (идентификатор есть → шелл; нет → логин; ошибка чтения → блокирующий экран ошибки). В standalone-превью из Галереи исход MUST выбираться debug-переключателем (has-ID / no-ID / error); по завершении анимации переход выполняется: для исхода **error** — к реальному экрану ошибки 3.1 в блокирующем режиме; для **has-ID / no-ID** — к лёгкой placeholder-странице назначения (реальные 4.1/2.1 ещё не построены).
- **FR-014**: Splash MUST отображаться во весь экран (edge-to-edge), системные бары прозрачны поверх фона; нативное скрытие оконного чрома на десктопе — вне scope.

### Functional Requirements — Универсальный экран ошибки (3.1)

- **FR-020**: Экран ошибки MUST быть параметризован: иконка, заголовок, сообщение, кнопка `Try again`.
- **FR-021**: Экран ошибки MUST поддерживать два режима — блокирующий (без стрелки back, последний в стеке) и встраиваемый (со стрелкой back).
- **FR-022**: Кнопка `Try again` MUST иметь состояние повтора (загрузка); в UI-only сам обработчик повтора — заглушка.
- **FR-023**: Микрокопия по умолчанию MUST использовать канонические строки (`Something went wrong`, `Try again`) и поддерживать сетевой текст вида `Could not <verb>. Check your connection and try again.`
- **FR-024**: На десктопе экран ошибки MUST выводиться в оконной раскладке (TitleBar), с увеличенной иконкой.
- **FR-025**: Иконки экрана ошибки MUST браться из SVG-набора `NoxIcons`; недостающие семантические глифы (например wifi/cloud) добавляются как новые SVG в дизайн-систему — Material icon-шрифт (`material_symbols_icons` / `Icons.*`) не подключается.

### Functional Requirements — Внешний вид (7.3)

- **FR-030**: Appearance MUST предлагать три взаимоисключающих варианта темы: System / Light / Dark, оформленных **карточками с мини-превью темы** (по мобайл-корпусу) с явным отмеченным состоянием.
- **FR-031**: Выбор темы MUST немедленно применяться ко всему приложению через существующий контроллер темы (реальное переключение, не заглушка).
- **FR-032**: Текущий выбор MUST отражать фактическое состояние темы приложения (по умолчанию System).
- **FR-033**: Персистентность выбора между перезапусками — вне scope (в памяти на время сессии).

### Functional Requirements — Язык (7.4)

- **FR-040**: Language MUST предлагать три взаимоисключающих варианта: System / English / Українська; по умолчанию System (следует языку ОС, fallback на English). Опции оформляются **простыми radio-строками** (`RadioListTile`), без флагов.
- **FR-041**: Выбор MUST визуально отмечаться немедленно; полная живая перерисовка интерфейса — вне scope до появления слоя локализации (заглушка/локальное хранение).
- **FR-042**: Выбор MUST сохраняться в пределах сессии.

### Functional Requirements — Уведомления (7.2)

- **FR-050**: Notifications MUST содержать один переключатель push on/off с поясняющим текстом (push только по «своим» чатам).
- **FR-051**: При смоделированном отказе системного разрешения экран MUST показывать информационный баннер с действием перехода в системные настройки.
- **FR-052**: Реальный запрос/состояние разрешения ОС, переход по deep-link и сохранение настройки — вне scope (заглушка флага).

### Functional Requirements — Terms (7.6)

- **FR-060**: Terms MUST показывать read-only прокручиваемые озаглавленные секции (bundled placeholder-контент) и подвал с версией приложения; флоу принятия отсутствует.
- **FR-061**: Внешние ссылки (если есть) MUST открываться корректно либо быть явно заглушены; финальный юридический текст — placeholder до поставки от юристов.
- **FR-062**: Подвал Terms MUST показывать **версию приложения** (без номера билда), получаемую из платформенной информации (тот же источник, что FR-071; локально, в scope).

### Functional Requirements — О приложении (7.7)

- **FR-070**: About MUST показывать только версию + билд (одна строка), без лицензий, копирайта, сайта и кредитов.
- **FR-071**: About MUST показывать **версию И номер билда** (FR-070), получаемые из той же платформенной информации, что и подвал Terms (FR-062) — единый источник, без отдельного механизма.

### Key Entities

- **Экран карты (Screen entry)**: запись Галереи экранов — идентификатор (например `1.1`), раздел, наличие двух раскладок, признак «реализован/заглушка».
- **Тема (ThemeMode)**: одно из System / Light / Dark; текущее значение приложения.
- **Язык (Language)**: одно из System / English / Ukrainian; выбор в пределах сессии.
- **Параметры экрана ошибки (ErrorParams)**: иконка, заголовок, сообщение, режим (блокирующий/встраиваемый), действие повтора.
- **Состояние разрешения (PermissionState, mock)**: granted / denied — заглушечный флаг для Notifications.
- **Версия приложения (AppVersion)**: версия + номер билда из платформенной информации.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все 7 экранов M1 открываются из Галереи экранов и отображаются без ошибок рендеринга в обеих темах и в обеих раскладках (узкое и широкое окно).
- **SC-002**: Splash проигрывает одноразовую анимацию (~400 мс) и затем выполняет переход; повторных/циклических анимаций нет.
- **SC-003**: На экране Appearance смена темы применяется мгновенно (в пределах одного перехода) ко всем видимым поверхностям приложения.
- **SC-004**: Для каждого экрана 100% состояний, определённых его спекой, демонстрируемы на заглушечных данных.
- **SC-005**: Один экран ошибки покрывает оба режима (блокирующий и встраиваемый) без дублирования экрана.
- **SC-006**: 100% пользовательской микрокопии — английская; 0 строк русского текста в UI.
- **SC-007**: Каждый экран покрыт widget- и golden-тестами (светлая + тёмная), и проектный гейт качества проходит зелёным.

## Assumptions

- Бэкенд, транспорт и протокол не выбраны (Конституция, тех-контекст) — поэтому все серверные зависимости (состояние авторизации, разрешения ОС, доставка, персистентность) заглушены и помечены как точки будущей замены.
- Экраны открываются через dev-«Галерею экранов» (этап M0), а не через продуктовый навигационный флоу; связывание экранов — отдельная задача backend-фазы.
- Дизайн-система, UI-kit (`App*Widget`) и токены готовы (Feature-003) и используются как есть; новые переиспользуемые элементы (settings-строки, info-баннер, опции темы, оконный TitleBar и т. п.) вводятся в рамках этой фичи и переиспользуются.
- Для экранов без выделенного desktop-корпуса (Appearance, Language, Notifications, Terms, About) десктоп-раскладка — одна полнооконная панель с ограниченной по ширине колонкой (решено в Clarifications / FR-002); полноценный desktop settings-shell (master-detail) — этап M3.
- Splash: цветной логотип-маска присутствует в ассетах (`assets/png/logo.png`, подтверждено); токены анимации присутствуют в дизайн-системе.
- Версия/билд для About и Terms берётся из платформенной информации; при отсутствии готовой зависимости она добавляется на этапе plan как мелкая инфраструктурная правка.
- Иконки экрана ошибки берутся только из SVG-набора `NoxIcons`; недостающие семантические глифы добавляются как новые SVG (решено в Clarifications / FR-025) — без сторонних icon-пакетов.
- Опции темы — карточки с превью; опции языка — radio-строки (решено в Clarifications / FR-030, FR-040).

## Out of Scope

- Связывание экранов в продуктовый навигационный флоу (`1.1 → 2.1↔2.2 → 2.3 → 4.1` и т. д.).
- Реальная авторизация, чтение/хранение идентификатора, серверные данные.
- Камера/QR, выбор и сохранение файлов, реальные системные разрешения и deep-links.
- Слой локализации (l10n) и живая перерисовка языка; персистентность настроек между перезапусками.
- Нативное скрытие оконного чрома Splash на десктопе и поведение «только холодный старт vs тёплый возврат».
- Экраны этапов M2–M4 и любая backend-интеграция.
