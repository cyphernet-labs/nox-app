# Quickstart — проверка фазы 031

---

## 1. Автоматические проверки, по порядку

```bash
# 1. Сервер: гонки обязательны
cd client_backend && gofmt -l . && go vet ./... && go test -race ./...

# 2. Клиент: полный гейт
cd .. && make gate

# 3. Снимки экранов
make golden-verify
```

| Проверка | Что закрывает |
|---|---|
| `go test -race` | признак `created` для всех трёх путей опознания; `false` не выпадает из кадра |
| `make gate` | порядок входа и все семь ловушек плана; пересчёт непрочитанного; снятие моков |
| `make golden-verify` | сдвиги — только там, где исчезло состояние «имя занято»; **четыре новых** эталона бейджа |

### Голдены: чем намеренный сдвиг отличается от регресса

**Не должны двигаться вовсе.** Эталоны виджета строки чата питаются литеральными числами (`unread: 5`, `unread: 120`) и настоящего механизма не касаются. **Диff в них — регресс**, а не обновление. Они же сохраняют покрытие формы «99+».

**Ожидаемо сдвигаются.** Экраны, где исчезло состояние «имя занято»: пропадает текст ошибки, меняется высота блока под полем.

**Добавляются — четыре новых.** Сценарий чата с бейджем, полученным настоящим механизмом: mobile + desktop, light + dark. Это **добавление**, а не сдвиг: 216 → 220. Причина — обнаруженный пробел паритета: без него ни один страничный голден не содержит строки с бейджем, и десктопная подача непрочитанного теряет покрытие на уровне страницы (Принцип VI).

## 2. Живой сценарий на двух клиентах

### 2.1. Чистый старт

```bash
pkill -f noxd
rm -rf /tmp/nox-031 && mkdir -p /tmp/nox-031
cd client_backend && go build -o /tmp/nox-031/noxd . && cd ..
cd /tmp/nox-031 && ./noxd -addr 127.0.0.1:8080 -db /tmp/nox-031/t.db
```

### 2.2. Главный сценарий — переустановка не гонит через онбординг (SC-001)

> ⚠️ Оба клиента входят **разными произвольными** идентификаторами. Значения `demo` и `registered` больше не имеют особого смысла — именно это фича и убирает, — но для чистоты сценария берите непохожие строки и **запишите их**.

1. Десктоп: свой идентификатор → **Sign in**. **Ожидается:** кнопка показывает **ожидание**, а не мгновенный переход — вход стал сетевой операцией. Затем экран выбора имени: сервер вас не знал.
2. Назваться `Anna`, отправить сообщение.
3. Стереть локальное состояние целиком:

```bash
rm -f ~/Library/Containers/com.cyphernetlabs.noxapp/Data/Documents/app_dev.db
rm -f ~/Library/Containers/com.cyphernetlabs.noxapp/Data/Library/Preferences/com.cyphernetlabs.noxapp.plist
defaults delete com.cyphernetlabs.noxapp; killall cfprefsd
security delete-generic-password -s flutter_secure_storage_service -a session.identifier
security delete-generic-password -s flutter_secure_storage_service -a session.device_id
```

4. Запустить, войти **тем же** идентификатором.

**Ожидается:** экран выбора имени **не показывается**, приложение открывает переписку, имя по-прежнему `Anna`, прошлые сообщения — собственные. Сегодня здесь показывается онбординг и имя затирается.

Проверка со стороны сервера:

```bash
sqlite3 /tmp/nox-031/t.db "SELECT label, COUNT(*) FROM users GROUP BY label"
```

Строк должно быть столько же, сколько людей, и `Anna` должна остаться `Anna`.

### 2.3. Вход без связи (SC-002a)

Остановить сервер, стереть локальное состояние, попробовать войти.

**Ожидается:** ожидание, затем внятная ошибка с возможностью повторить. **Не ожидается:** ни проскока в переписку, ни экрана выбора имени, ни бесконечного ожидания.

Поднять сервер, нажать повтор — вход проходит.

### 2.4. Прерванный онбординг

Войти новым идентификатором, дойти до экрана выбора имени, **закрыть приложение не назвавшись**. Запустить снова.

**Ожидается:** человек попадает в переписку под серверным `User<четыре знака>`. Это санкционированное спекой состояние — шаг выбора имени опционален, — и имя меняется в настройках. **Не ожидается** повторного экрана выбора имени с последующим затиранием.

### 2.5. Свободное имя чата (SC-003)

Создать чат с именем `General`. **Ожидается:** принимается — на сервере оно свободно. Затем создать второй с тем же именем: отказ приходит от сервера.

То же для переименования.

### 2.6. Имя человека не отвергается по выдуманной занятости (SC-004)

Настройки → переименоваться в `admin`, затем в `NOX`, затем в `User1234`. **Ожидается:** все три принимаются. Ввести имя с недопустимым символом или длиннее 32 — отказ остаётся с прежним объяснением.

### 2.7. Собственное сообщение не поднимает свой бейдж (SC-005)

При **закрытом** треде: остановить сервер, отправить сообщение в этот чат (оно повиснет в очереди), поднять сервер.

**Ожидается:** сообщение уходит, бейдж у этого чата **не появляется**. Сегодня появляется.

### 2.8. Дубликат не накручивает счётчик (SC-006)

Со второго клиента написать в чат, который на первом закрыт → бейдж `1`. Разорвать связь первого клиента и вернуть её так, чтобы то же событие пришло догоняющей синхронизацией повторно.

**Ожидается:** бейдж остался `1`.

### 2.9. Никогда не открытый чат бейджа не имеет

Создать чат со второго клиента и написать в него. На первом клиенте, ни разу его не открывав: **бейджа нет** — правило спеки продукта.

## 3. Признаки, что что-то пошло не так

| Симптом | Скорее всего |
|---|---|
| Вход мгновенный, без ожидания | решение об онбординге по-прежнему принимается локально |
| Вернувшийся попадает на выбор имени | признак не читается, либо локальный флаг не монотонен (T-правило R4) |
| Вход больше не проходит вообще, даже после повтора | внешний таймаут вместо внутреннего — вход заперт на процесс (T1) |
| После входа чужое имя в настройках | разовая личность усвоена в свежую сессию (T2/T3) |
| Бейдж чата умер навсегда | отметка отравлена чужим пространством номеров (T5) |
| Бейджи погасли после стирания мира | отметка пережила курсор (T6) |
| Список чатов заметно подтормаживает | пересчёт выполняется на страницу, а не на обновление (T7) |
