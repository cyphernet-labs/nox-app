# Research: методология рефакторинга + паритет-верификации

**Phase 0.** Открытых `NEEDS CLARIFICATION` нет (закрыты в spec Clarifications). Ниже — зафиксированные
методологические решения, определяющие безопасность выполнения.

## R0-1. Golden-driven behavior-preservation

- **Decision**: голдены обеих категорий (page-mobile `goldenTest` 360, page-desktop `goldenTestDesktop`
  1280×800) — единственный источник истины «UI не изменился». Behavior-preserving задача (E/O) считается
  корректной ⇔ `make golden-verify` проходит БЕЗ churn.
- **Rationale**: голдены фиксируют рендер байт-в-байт; любой непреднамеренный визуальный сдвиг от выноса/
  оптимизации виден сразу. Дешевле и надёжнее ручного визуального QA.
- **Alternatives**: ручной визуальный обход (отклонён — невоспроизводим, не ловит sub-pixel drift);
  снапшот-диффы вне CI (отклонён — уже есть встроенный harness).

## R0-2. Fail-first для паритет-фиксов

- **Decision**: каждый паритет-фикс (FR-001…FR-006) начинается с теста/голдена, который ПАДАЕТ на текущем
  коде (доказывает наличие gap), затем фикс, затем осознанная перегенерация baseline «отстающей» ветки.
- **Rationale**: доказывает и наличие дефекта, и факт закрытия; предотвращает «фикс без регрессионной сетки».
- **Alternatives**: только перегенерация golden (отклонён — не доказывает поведение, напр. `PopScope` в
  дереве не виден в пикселях → нужен widget-тест).

## R0-3. Порядок фаз P → E → O

- **Decision**: сначала паритет-дефекты (P, user-visible), затем выносы (E), затем оптимизации (O).
- **Rationale**: паритет — прямой запрос владельца и дефекты корректности; выносы уменьшают поверхность,
  на которой потом делаются оптимизации (меньше мест правки); оптимизации — косметика последней.
- **Alternatives**: extraction-first (отклонён — откладывает user-visible фиксы); big-bang (отклонён —
  ломает «одна задача = один reviewable merge»).

## R0-4. Конвенции выноса

- **Decision**: переиспользуемое → `App*Widget` под `lib/presentation/widgets/<subsystem>/` или
  `widgets/primitives/`; страница-локальное → приватный `StatelessWidget`; helper (навигация/lightbox) →
  `presentation/helpers/`. Только дизайн-токены; raw-color/opacity — только в `lib/design/theme/`.
- **Rationale**: соответствует блюпринту (05 §5.1 BLoC-less-виджеты) и Принципу IV.

## R0-5. Верификация паритета (метод свипа)

- **Decision**: для каждого из 13 responsive-файлов перечисляем действия/аффордансы/состояния, рендеримые
  `_narrow` и `_wide` ветками, и сверяем множества. Результат зафиксирован как контракт
  `contracts/parity-matrix.md` (acceptance для SC-005).
- **Rationale**: делает «паритет» проверяемым и полным, а не ad-hoc.

## R0-6. Отсутствие новых зависимостей

- **Decision**: рефакторинг не вводит новых пакетов; всё делается существующим стеком.
- **Rationale**: снижает риск и объём; цель — чистка, а не расширение.
