# Data Model: Данные на диске устройства

## Сейф (`flutter_secure_storage`, опции «только это устройство»)

| Ключ | Что |
|---|---|
| `device.storage_key` | **новый**: ключ локальной базы, base64 32 байт |
| `session.device_secret` | семя ключа устройства (044) — опции «только это устройство» |
| прочие `session.*` | опции «только это устройство» |

## Папка данных приложения

| Путь | Что | Зашифровано |
|---|---|---|
| `<data>/app.db` (`app_dev.db`; при сжатии рядом — `~<имя>`) | Sembast с `VaultCodec` | каждая строка |
| `<data>/nox_attachments/<file_id>.<ext>` | скачанное вложение | куски |
| `<data>/nox_attachments/<file_id>.<ext>.part` (+ `.part.tag`) | незаконченное скачивание | куски |
| `<data>/nox_outbox/<client_message_id>/<имя>` | копия исходящего | куски |
| `<data>/tor/…` | состояние Tor | своё |
| `<temp>/nox_open/…` | временные копии | нет; живут по правилам R6 |

`<data>` — `getApplicationSupportDirectory()` (iOS, Android, macOS, Linux), `%LOCALAPPDATA%\NOX` (Windows); на iOS и macOS — метка «не в бэкап».

## Формат файла

Заголовок 32 байта: `NOXF`, версия `1`, размер куска `65536`, случайный id файла (16 байт), резерв; куски по 64 КиБ + тег 16. Ключ файла — `HKDF-SHA256(ключ локальной базы, "nox/devfile/v1|" + hex(id файла))`: id лежит в заголовке, поэтому файл открывается после любого переименования и переноса. Записи базы — под ключом `HKDF(ключ локальной базы, "nox/devrec/v1")`. Векторы — в тестах `packages/nox_tor` (Rust и Dart), посчитаны двумя независимыми реализациями.

Заголовок по байтам:

| Смещение | Длина | Что |
|---|---|---|
| 0 | 4 | `NOXF` (ASCII) |
| 4 | 1 | версия `1` |
| 5 | 3 | нули |
| 8 | 4 | размер куска, u32 big-endian: `65536` |
| 12 | 16 | id файла, случайный; имя для сейфа — его hex в нижнем регистре |
| 28 | 4 | нули |

Заголовок с другими значениями — не файл этого формата. Кусок `i` — открытые байты `[i·65536, min((i+1)·65536, размер))`; кусков `max(1, ⌈размер / 65536⌉)`: пустой файл — один пустой последний кусок. Последний — тот, чей конец равен размеру; полный кусок в конце файла запечатан как последний. Кусок запечатывается, только когда он целый, последний — когда целый файл; докачка продолжается с последнего целого куска, который открывается как непоследний, а ответ целиком (`200`) начинает новую часть под новым id.

## Состояния при запуске

| Сейф | База | Что делать |
|---|---|---|
| ключ есть | открывается под ним | открыть |
| ключ есть | не открывается (другой ключ, нечитаемый файл) | стереть данные, принудительный выход, спаривание |
| ключа нет | нет | создать ключ; файлы в папке данных, которые нечем открыть, удалить |
| ключа нет | есть | стереть данные, принудительный выход, спаривание |
| ошибка чтения | — | без стирания, повтор через 2, 4, 8, 16, 30, 30… с; на экране заставка |

«База» — любая из баз обоих окружений (`app.db`, `app_dev.db`) или файл сжатия Sembast `~<имя>` рядом с ней: у окружений общие папка данных и ключ, и стирание удаляет их все, свою базу последней (research R10).

После выхода ключа нет; его создаёт первое, что запечатывает или открывает данные (вход).
