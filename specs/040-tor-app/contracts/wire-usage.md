# Провод: чем фаза пользуется из контракта v0 (без изменений)

Контракт `docs/client-backend/protocol/contract-draft.md` этой фазой **не меняется**. Всё ниже описано там с фазы 039 и реализовано сервером. Приложение впервые этим пользуется.

| Что | Раздел контракта | Как использует приложение |
|---|---|---|
| `addresses` в ответе на приветствие | §3 | читает `direct` и `onion`, сохраняет в `session.server_addresses`; наличие поля — признак сервера 039+ |
| событие `server.addresses` (seq 0) | §8A, «Событие server.addresses» | обновляет тот же список; курсор не трогает |
| `access_key` в `pair` | §8A, `pair` | шлёт всегда: необязательное поле безопасно для любого сервера (§2.1) |
| `device.setAccessKey` | §8A | один раз после первого приветствия с `addresses`; повтор того же ключа — успех |
| `device.invite {"onion": true}` и поле ответа `onion` | §8A, `device.invite` | всегда просит onion; `onion: false` — пометка «только дома» |
| ссылка версии 2 | §8A, таблица ссылки | разбирает: прямой адрес, отпечаток, токен, `onion_pub`, `onion_port`, `one_time_priv` |
| `invalid_request` на ключ доступа | §8A, отказы `pair` и `device.setAccessKey` | создаёт новый ключ и повторяет (не больше 3 раз за сессию) |
| `unauthenticated` на `device.setAccessKey`/`device.invite` | §8A | нынешний путь отзыва |
| claim через onion → `invalid_token` | §8A | приложение claim через Tor не пробует (FR-022) |

Onion-вход сервера принимает тот же TLS-сертификат, что и прямой, поэтому отпечаток из ссылки проверяется одинаково на обоих путях (§1).
