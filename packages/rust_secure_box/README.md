# RustSecureBox

Ключи и подписи проверки, которую проходит каждое соединение NOX: `POST /auth`, затем `POST /auth2` сразу после TLS 1.3 (контракт v0, §1). Одна библиотека — один исходный код у приложения и у сервера:

- **приложение** встраивает крейт в свой Rust-модуль (`packages/nox_tor`) и вызывает четыре функции напрямую;
- **сервер** выполняет тот же крейт, собранный в WebAssembly и переведённый в Go-код `wasm2go` (`client_backend/internal/securebox/boxwasm`). Так сервер собирается без cgo, без Rust и без компилятора C.

Сейчас внутри **заглушка** (`src/stub.rs`). Настоящую реализацию пишет разработчик заказчика.

## Интерфейс

Полное описание — `specs/050-rust-secure-box/contracts/rust-secure-box.md`; Rust API — `src/lib.rs`.

| Функция | Вход | Выход |
|---|---|---|
| `generate_keys` | — | закрытый ключ 32 байта, открытый 32 байта |
| `get_challenge` | свой закрытый ключ | челлендж 32 случайных байта, свой открытый ключ |
| `sign_challenge` | свой закрытый ключ, челлендж другой стороны | подпись 64 байта |
| `check_signature` | открытый ключ, челлендж, подпись | верна или нет |

Каждая функция возвращает `Result`. «Подпись неверна» — это `Ok(false)`, не ошибка.

Обязательные свойства:

- **без состояния** — ничего не хранит, ключи передаёт вызывающий;
- **потокобезопасна** — вызовы из любого числа потоков одновременно;
- **только вычисления** — без файлов, сети и обращений к системе. Случайные байты в приложении даёт система, в WebAssembly — хост через импорт `env.rsb_random`. Других импортов у WebAssembly быть не должно: сервер с лишним импортом не соберётся.

Настоящий RustSecureBox — Ed25519 по RFC 8032 с теми же размерами: закрытый ключ — семя 32 байта, открытый — 32, подпись — 64.

## Как заменить заглушку

1. **Реализация.** Положить её на место `src/stub.rs`: четыре функции с теми же сигнатурами. `src/lib.rs`, `src/random.rs` и `src/wasm.rs` остаются как есть. Их можно переписать, если C ABI WebAssembly (`rsb_io`, `rsb_*`) и импорт `env.rsb_random` не меняются.
   - Случайные байты брать только через `crate::random::fill`.
   - Библиотеку Ed25519 подключать без функций по умолчанию (`default-features = false`): без `rand`, `getrandom` и `OsRng`. Иначе у WebAssembly появятся лишние импорты (например, `__wbindgen_*` от `getrandom` с `wasm_js`), и сервер не соберётся.
   - Ключ, который библиотека не принимает, — ошибка `Error::InvalidArgument`, не паника.
   - Поправить тексты о заглушке: абзац с ⚠️ в `src/lib.rs`, `description` в `Cargo.toml` и строку «Сейчас внутри заглушка» в начале этого README. Файл `src/stub.rs` можно оставить под этим именем.
2. **Файлы зависимостей.** Выполнить `cargo metadata --format-version 1 >/dev/null` в `packages/rust_secure_box`, потом в `packages/nox_tor/rust`: новые зависимости попадут в оба `Cargo.lock` без сборки. Оба файла коммитятся вместе с реализацией, потому что копия сервера собирается с `--locked`. Тесты крейта до шага 3 не запускать: векторы ещё заглушки, и тесты векторов упадут.
3. **Векторы.** Выполнить `RSB_IMPLEMENTATION=<имя> cargo test --test vectors -- --ignored write_vectors`. Имя любое, кроме `stub-v1`, например `ed25519-v1`. Команда пишет все три копии векторов:
   - `tests/data/rsb-vectors.json`;
   - `specs/050-rust-secure-box/contracts/rsb-vectors.json`;
   - `client_backend/internal/securebox/testdata/rsb-vectors.json`.

   Тесты в Rust, Go и Dart берут векторы и имя реализации из этих копий. Проверки, которые касаются только заглушки, по имени видят, что заглушки больше нет.
4. **Копия сервера.** Выполнить `make box-wasm` из корня репозитория. Нужны тулчейн из `rust-toolchain.toml` с целью `wasm32-unknown-unknown` и Go. Скрипт сам задаёт флаги сборки, поэтому копия получается одинаковой на любой машине.
5. **Проверка:**
   - `cargo test` в крейте — свойства любой реализации и векторы;
   - `make box-verify` — копия сервера соответствует крейту;
   - `cd client_backend && go build ./... && go test -race -timeout 30m ./...`. Под `-race` настоящая библиотека в переводе `wasm2go` в десятки раз медленнее заглушки: пакет `internal/server` идёт минуты, отсюда запас по времени. `go vet` проверяет сгенерированный код тоже. Если он ругается только на `boxwasm` (например, на недостижимый код), запустите `go vet $(go list ./... | grep -v /boxwasm)`;
   - `make tor-test`;
   - `make gate`.

Меняются только крейт, его векторы, два `Cargo.lock` и копия на сервере (`client_backend/internal/securebox/boxwasm`). Остальной код приложения и сервера, включая тесты, остаётся прежним. Документы команды, где RustSecureBox назван заглушкой (`CLAUDE.md`, `client_backend/CLAUDE.md`, `docs/blueprints/client-backend/README.md`), команда правит после замены.

`stubProbePublicKey` в `client_backend/internal/securebox/securebox.go` не менять никогда. Это ответ заглушки на пробный ключ, а у настоящей реализации ответ другой, и тесты это проверяют. Подогнанная под новые векторы константа объявит настоящую библиотеку заглушкой.

## Пробный ключ

Сервер узнаёт заглушку без изменения интерфейса: спрашивает открытый ключ для закрытого из 32 байт `0x01` (`PROBE_PRIVATE_KEY`). Пока ответ равен ответу заглушки, сервер при каждом старте пишет в журнал предупреждение, а служебная страница показывает `RustSecureBox is a stub: devices are not really verified.`. С настоящей реализацией ответ другой, и предупреждение исчезает само. Пробный ключ не нулевой: библиотеки Ed25519 отказывают на нулевом семени, а иногда паникуют.

## Переход

Открытые ключи разных реализаций для одного закрытого ключа разные. Поэтому при каждом переходе:

- **сервер** перевыпускает свой открытый ключ и отпускает все устройства, а переписку сохраняет;
- **приложение** один раз возвращает человека к спариванию.

Устройство спаривается заново ссылкой с машины и видит всю прежнюю историю.
