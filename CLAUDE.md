# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**NOX** — secure cross-platform messenger for iOS, Android, Windows, Linux and macOS (web out of scope), built in Flutter (Dart). Design anchor: **Signal**-like — end-to-end encrypted text and file exchange. Product name in UI, wordmarks and prose is `NOX` (all caps); the GitHub repo is `cyphernet-labs/nox-app` (lowercase, technically derived). Russian working name in materials: «Секюрный Мессенджер».

**Status — Flutter app skeleton scaffolded (Feature-001) + UI kit built (Feature-003).** The repo is no longer docs-only: there is a single Dart package `nox_app` under `lib/` (Clean Architecture layers, injectable+get_it DI, design-token Material 3 theme, and a network-only `Item` verification harness on mock data), plus `pubspec.yaml`, tests, CI workflows and a `Makefile`. The presentation layer now also holds the complete BLoC-less **UI-kit widget library** (`App*Widget` under `lib/presentation/widgets/`), full M3 stock-widget theming, and an in-app launcher → gallery (`HomePage` → `UiKitPage`). Targets: iOS, Android, macOS, Windows, Linux (web out of scope); Flutter `3.44.1` is FVM-pinned. Alongside it lives the substantial design corpus (vision/requirements drafts, a locked UI/UX spec with a full design system, and a Flutter design-token handoff), the adopted NOX Flutter architecture blueprint, and Spec Kit scaffolding (all below). The transport protocol, sync model and server are still open, and there are **no real product features yet** — the `Item` slice plus the Feature-001 `AppShell`/`ItemListPage` are verification-only and **not mounted** (the app boots straight to the launcher).

## Language Conventions

The team's working/documentation language is **Russian**; only the code sphere stays **English**. Split:

| Surface | Language |
|---|---|
| Chat with the user | Russian |
| Documentation prose in `docs/` | Russian |
| Spec Kit feature artifacts in `specs/` (`spec.md`, `plan.md`, `tasks.md`, `research.md`, `data-model.md`, `quickstart.md`, `contracts/`, `checklists/`) | Russian |
| Project `README.md` and other repo-root prose docs | Russian |
| Code: identifiers, file/dir names, **code comments**, shell commands | English |
| Git: **commit messages, PR titles & descriptions, branch names** | English (repo artifacts; branch names ASCII — Cyrillic breaks tooling/CI) |
| Spec Kit tool internals (`.specify/templates`, `.claude/skills/speckit-*`) and this `CLAUDE.md` | English (tooling / agent-instruction files) |
| **In-product UI microcopy** (labels, buttons, errors — even quoted inside Russian docs) | **English** |

Do not mix languages within one artifact: code, commit messages and PR text stay English even when referencing Russian docs; docs and specs stay Russian even when quoting English APIs / identifiers. UI nuance: the app's user-facing languages are **English + Ukrainian** (system default, fallback to English); **Russian is never a UI language** — only the language of internal docs, specs and chat. So UI strings stay English even inside otherwise-Russian design docs.

**Chat is always Russian — including command output.** Every assistant chat reply is Russian prose, including Spec Kit command reports (`/speckit-analyze` findings, headings and tables; `/speckit-plan|tasks|implement` completion summaries; coverage/severity tables; "next steps") and interactive-tool prompts (`AskUserQuestion` question text/options/headers). A skill or template that presents English headings does **not** make the reply English — the template language never sets the chat language. Only code identifiers, file paths, shell commands, severity tokens (CRITICAL/HIGH/…) and canonical UI microcopy (`Sign in`, `Your ID`, screen IDs like `5.1`) stay English inline. Known recurring drift: after editing English code/specs the chat silently continues in English — re-check every message is Russian before sending.

## NOX product model — facts that span the design spec

NOX-specific decisions to know before reasoning about any screen or future data model; each is synthesized from `docs/design/spec/overview.md` (+ `screens/`):

- **Open shared space, not Signal 1:1.** All chats are visible to everyone; no permissions; anyone can create a chat and write in any chat; there is no "join" flow; chats are never deleted. Signal mechanics tied to a fixed 1:1 audience (delivered/read receipts, membership, per-chat subscriptions) are deliberately dropped or reinterpreted.
- **Two-layer identity.** A technical anonymous **identifier** (shown as `Your ID`, a long key-like string entered by paste or QR — no phone/email) plus a public **label** (display name). Server assigns `User<random>` at first login (a name always exists); label is globally unique case-sensitive, ≤32 chars, charset `[A-Za-z0-9._-]`. One identity per device; switching = Logout (full local wipe) + re-login.
- **Message status is local-only:** `sent` (accepted by server) + `pending`/`error`; **no delivered/read** (no fixed recipient in an open space).
- **Shell:** 3-item bottom bar — `Chats` tab, central docked **`+`** FAB (create chat, visible on both tabs), `Settings` tab. **No profile screen** — profile-like items live in Settings.
- **Theming:** Material Design 3, light + dark via `ColorScheme` (default system), seed = teal extracted from the logo. Two brand-fixed exceptions independent of theme: splash background always dark, QR surface always light.
- **Chat name:** globally unique, ≤64 chars, unrestricted charset. Chat avatars are generated (initials + hash-picked color from a fixed palette).
- Explicitly **out of scope** this iteration: calls, reactions/stickers, voice messages, stories, mentions/threads, profile screen, moderation/permissions/owners, multi-account, delivered/read, per-chat mute/pin, Support section, file content previews (type-icon chips only).

## Flutter architecture blueprint (`docs/blueprints/mobile/`) — unified & adopted

The adopted architecture for NOX's Flutter app (package `nox_app`, app id `com.cyphernetlabs.noxapp`/`.stage`), unified from an advanced cross-project blueprint adopted as the base, then NOX-adapted and reconciled with the scaffolded `lib/` code. Load-bearing decisions: **one Dart package**, Clean Architecture layers as folders (`presentation → domain ← data`, `domain` imports nothing); **BLoC = Freezed** (`@freezed sealed` State/Event, thin `BaseBloc`, computed logic in extension getters, no `*.g.dart` on BLoC types); single **injectable + get_it** DI (`configureDependencies(env)`); `RepositoryResult<T>` (success XOR error) everywhere; **Sembast** cache-first reactive repositories with a **network-only carve-out** for server-owned paginated lists and one-shot POSTs (the open chats list is the first such real feature); `infinite_scroll_pagination` v5 (`PagingState`-in-bloc); design-token-only UI; FVM-pinned Flutter `3.44.1`, line length 140, stock `flutter_lints`; codegen-first (freezed + json_serializable + injectable + flutter_gen, one `build_runner` run).

**Implementation notes (real `lib/`, beyond the blueprint prose):**
- **`BaseBloc.executeLogic` swallows exceptions when no `onError` is passed** (no emit, no rethrow) — always pass `onError` to surface an `Error`/error-paging state. Results are consumed via `RepositoryResult.match(onData, onError)`; paginated loads use `bloc_concurrency` `sequential()`.
- **DI bootstrap order (enforced in `lib/main.dart`):** `configureDependencies(env)` → `getIt.allReady()` → `getIt<AppConfigRepository>().initialize(flavorType:)`. Cross-cutting singletons are reached via top-level getters in `lib/di/global_aliases.dart` (`logRepository`, `itemRepository`), not constructor injection. A per-env Sembast `AppDatabase` + `ItemDao` are registered but **currently unused** (the `Item` slice is network-only).
- **`context.appColors` (`AppColors` ThemeExtension) is a 2-field skeleton** (`surfaceMuted`, `dividerSubtle`); the full token-driven semantic palette lands in US4. For now pull color from the M3 `ColorScheme` (`noxLightScheme`/`noxDarkScheme`) and `NoxBrand`. Raw `Color` literals are permitted **only** inside `lib/design/theme/`.
- **Two shells exist.** The Feature-001 `lib/presentation/app/widgets/app_shell.dart` (width-adaptive rail/bottom-bar) + `lib/presentation/pages/item_list_page/` are the verification skeleton and are **not mounted**. The live shell chrome is the Feature-003 widgets in `lib/presentation/widgets/shell/` (`AppBottomBarWidget`, `AppCreateFabWidget`, `AppWordmarkWidget`, `AppSplashHairlineWidget`).
- **BLoC-per-page has a phase-scoped exception (blueprint `05` §5.1, owner-sanctioned 2026-06-20).** Default 5.1 still holds: a navigable page with a real repository/async/non-trivial mutable state MUST own a Freezed BLoC. **But** during the UI-first phase (backend not chosen yet), a *purely presentational* navigable screen with no repository/async/domain state may be a `StatelessWidget`/local `StatefulWidget` with **no** BLoC — this covers the shipped launcher/gallery (`HomePage`/`UiKitPage`/`ScreensGalleryPage`) and the Feature-004 M1 screens (splash, error, About/Terms/Appearance/Language/Notifications). Each such screen gains its BLoC when real data is wired (backend phase).

> **Rule: at the start of any Flutter/client task, consult the relevant blueprint doc(s) (`README.md` index → layer docs `00`–`17`) and build to them.** If real code ever drifts from the blueprint, bring the blueprint back to a correct state in the same change-set. **Caveat:** NOX's backend/protocol is not chosen yet, so the networking/auth/envelope/endpoint specifics in `04`/`14`/`15`/`16` are explicit **example placeholders marked TBD** — replace them with the real contract once the backend is decided. The app skeleton is already scaffolded (Feature-001) and the blueprint is reconciled against the real `lib/` + `pubspec.yaml`; the `Item` slice is verification-only.

## Build / test / run

The build system is in place: `pubspec.yaml` + a `Makefile` (wraps `fvm`) + FVM-pinned Flutter `3.44.1`. Background/rationale lives in `docs/blueprints/mobile/12-dev-commands.md` — but that doc has **drifted** from the real `Makefile` (missing golden targets, `--exclude-tags golden`, `FILE=`; lists nonexistent `build-android/ios` wrappers); the `Makefile` is the source of truth.

**Daily commands (prefer the `Makefile` targets):**
- `make gate` — the end-of-task gate: `generate` → `format` → `analyze` → `test` (goldens excluded). Run before declaring work done.
- `make deps` (`pub get`); `make generate` (`build_runner build --delete-conflicting-outputs`, single pass); `make analyze` (zero-errors gate).
- `make test` → `flutter test --exclude-tags golden`. **Single test/dir:** `make test FILE=test/path/x_test.dart` (raw form: `fvm flutter test <path>`).
- **Format:** per-task use explicit paths — `fvm dart format -l 140 <changed paths>` (keeps diffs tight). `make format` is a **bulk** `lib test` sweep (CI-style, used by `make gate`) — not for incremental work.
- **Run the app:** `fvm flutter run --dart-define-from-file=config/stage.json` (or `config/prod.json`); desktop needs an explicit device: `-d macos|windows|linux`. Flavor comes only from `config/<flavor>.json` (no native `--flavor`). The only entrypoint is `lib/main.dart`.
- **Builds** wrap `mise`: `mise run build:<platform>:<stage|prod>` for any of android/ios/macos/windows/linux (all `--debug`, no secrets yet). The `Makefile` only wraps `build-macos-stage|prod`, `build-windows-stage`, `build-linux-stage` — use `mise run` directly for the rest.

**Golden tests** are plain-Flutter `matchesGoldenFile`, tagged `@Tags(['golden'])` (declared in `dart_test.yaml`), rendered/verified **locally only on Apple Silicon/macOS** and **excluded from `make test` and CI**. Verify with `make golden-verify`, regenerate baselines with `make golden-update` (both accept `FILE=`). Baseline `goldens/*.png` are committed. See *Testing*.

**CI** (`.github/workflows/`): `ci.yml` (`gate` job, macOS) mirrors `make gate` minus goldens — `pub get` → `build_runner` → `dart format -l 140 --set-exit-if-changed` on tracked `lib`+`test` `.dart` → `analyze` → `flutter test --exclude-tags golden`. `compile-check.yml` runs 5 per-platform `--debug` compile-smoke builds. **CI uses bare `flutter`/`dart` (subosito action), not `fvm`** — locally always use `fvm`.

There is **no l10n yet** (no `l10n.yaml`/`.arb`/`flutter gen-l10n`; UI strings are constants in `lib/general/text_constants.dart` — i18n is future work despite the planned EN+UK UI) and **no `integration_test/` directory** (the dev-dep is wired but unused).

## Testing

Tests deep-mirror `lib/` under `test/` (not flat). The team's test-generation conventions are the slash-command skills **`/bloc-test`, `/golden-test`, `/widget-test`**, sourced from **`.claude/commands/{bloc-test,golden-test,widget-test}.md`** (note: under `.claude/commands/`, **not** `.claude/skills/`, which holds only `speckit-*`). Read the relevant one before writing or updating a test.

- **Shared harness in `test/utils/`:** `pumpApp(tester, child, {themeMode, settle, textScale})` wraps the child in `ScreenUtilInit(Constants.designSize)` + `AppTheme.light()/dark()` + a textScaler clamp — **mandatory**, or `AppSpacingTokens`/`AppTextStyleTokens`/`context.appColors` fail to resolve. `goldenTest(name, build, {settle})` (`test/utils/golden.dart`) runs light+dark on the design surface and matches `goldens/<name>_<mode>.png`; it calls `loadNoxFonts` (`test/utils/fonts.dart`) so glyphs render as real Roboto. Use `settle: false` for animated content (spinner/progress).
- **Naming / tagging:** golden files are `*_golden_test.dart` and **must** carry `@Tags(['golden'])`; widget/unit tests are `*_test.dart` and **must not** carry the tag (tagging silently drops them from CI). Test names are descriptive sentences, not `test_should…_when…`. Cross-widget a11y checks live in `test/presentation/widgets/accessibility_test.dart`.
- **Mocking: `mockito` only — `mocktail` is forbidden** (it is merely transitive). Prefer running against the test-env DI (`configureDependencies(Environment.test)`, which serves mock data); use `mockito` only to force a path (e.g. a repository error) via `@GenerateMocks` + `getIt.allowReassignment` + `registerSingleton`. `*.mocks.dart` are gitignored `build_runner` output. `mockito` is pinned `<5.6.5` (analyzer vs `injectable_generator` conflict).
- **BLoC tests** use `bloc_test` against the test-env DI; assert **bare** substate names (`Initialized`/`Initializing`/`Error`, never page-prefixed); only assert an `Error` emission when the handler passed `onError` to `BaseBloc.executeLogic` (otherwise errors are swallowed by design).
