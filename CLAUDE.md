## Project Overview

**NOX** — secure cross-platform messenger for iOS, Android, Windows, Linux and macOS (web out of scope), built in Flutter (Dart). Design anchor: **Signal**-like — end-to-end encrypted text and file exchange. Product name in UI, wordmarks and prose is `NOX` (all caps); the GitHub repo is `cyphernet-labs/nox-app` (lowercase, technically derived). Russian working name in materials: «Секюрный Мессенджер».

**Status — a complete, self-contained client product running entirely on mock repositories over a real local Sembast DB.** Spec Kit features **001–021** are implemented and merged to `develop` (001–011 via PR #1–#12; 012–021 as local `--no-ff` merges), plus ~20 ad-hoc tracker branches (`p1`–`p14`, `d4`/`d5`/`e1`/`e2`/`n5`/`f3`, `feat-edit-chat-name`, `design-visual-audit`). All 17 screens exist with real reactive business logic: watch-based chats list and thread, unread counters, optimistic send with an offline queue, a real cross-platform file picker, inline image thumbnails + full-screen viewer, real file Save, l10n EN+UK with live switching, persisted settings/session/identity. Goldens are locked in all three categories (216 committed baselines). Gate on `develop`: `make gate` = 732 tests green, `make golden-verify` = 216 goldens green (the client-track branches raise the test count; goldens stay frozen at 216 by design).

**The backend phase is under way (2026-08): server stage 1 is merged, the client track is running.** Server language **Go** + embedded **SQLite** (client crypto core will be **Rust** — dictated by the iOS notification extension), transport **wss on 443 with key pinning**, wire **contract v0** fixed and implemented end to end by the server (`docs/client-backend/protocol/contract-draft.md`, staged: stage 1 has no auth), the authentication model approved (`docs/client-backend/architecture/authentication.md`, stage 2). Still open: E2EE boundary (Q1) — see the register `docs/client-backend/open-questions.md`. **Q11 (public author id) closed 2026-09-02** by feature 030: `author_id` carries a server-minted `u_` id, the person is recognised by a one-way derivation of the login identifier (`login_ref`) and the device by `device_key`, and the server holds `users`/`devices` tables with no verification of either — stage 2 adds only the signature check. The Go server lives in `client_backend/` (own CLAUDE.md + `/go-style`, `/ws-rest-patterns`, `/add-command`, `/migrations` skills). The network seam is fully prepared but **inert**: per-feature `*RemoteDataSource` interfaces, an `Environment`-scoped mock↔real DI flip, `ResponseEntity` + `EntityConverter` wire DTOs, `AppConfig.apiUrl` + auth interceptor + `401 → forced logout`. Flutter `3.44.1` is FVM-pinned; one Dart package `nox_app` under `lib/`. The app boots into the real product flow (`AppRoot` → `Splash` → `Login`/`QR` → `Set username` → `TabBarShell`); the `Item` slice plus the Feature-001 `AppShell`/`ItemListPage` remain verification-only and **not mounted**.

## Language Conventions

The team's working/documentation language is **Russian**; only the code sphere stays **English**. Split:

| Surface | Language |
|---|---|
| Chat with the user | Russian |
| Documentation prose in `docs/` | Russian |
| Spec Kit feature artifacts in `specs/` (`spec.md`, `plan.md`, `tasks.md`, `research.md`, `data-model.md`, `quickstart.md`, `contracts/`, `checklists/`) | Russian |
| Project `README.md` and other repo-root prose docs | Russian |
| Code: identifiers, file/dir names, **code comments**, shell commands | English |
| Git: **commit messages, PR titles & descriptions, branch names** | English (repo artifacts; branch names ASCII — Cyrillic breaks tooling/CI) |
| Spec Kit tool internals (`.specify/templates`, `.claude/skills/speckit-*`) and this `CLAUDE.md` | English (tooling / agent-instruction files) |
| **In-product UI microcopy** (labels, buttons, errors — even quoted inside Russian docs) | **English** |

Do not mix languages within one artifact: code, commit messages and PR text stay English even when referencing Russian docs; docs and specs stay Russian even when quoting English APIs / identifiers. UI nuance: the app's user-facing languages are **English + Ukrainian** (system default, fallback to English); **Russian is never a UI language** — only the language of internal docs, specs and chat. So UI strings stay English even inside otherwise-Russian design docs.

**Chat is always Russian — including command output.** Every assistant chat reply is Russian prose, including Spec Kit command reports (`/speckit-analyze` findings, headings and tables; `/speckit-plan|tasks|implement` completion summaries; coverage/severity tables; "next steps") and interactive-tool prompts (`AskUserQuestion` question text/options/headers). A skill or template that presents English headings does **not** make the reply English — the template language never sets the chat language. Only code identifiers, file paths, shell commands, severity tokens (CRITICAL/HIGH/…) and canonical UI microcopy (`Sign in`, `Your ID`, screen IDs like `5.1`) stay English inline. Known recurring drift: after editing English code/specs the chat silently continues in English — re-check every message is Russian before sending.

## NOX product model — facts that span the design spec

NOX-specific decisions to know before reasoning about any screen or data model; each is synthesized from `docs/design/spec/overview.md` (+ `screens/`):

- **Open shared space, not Signal 1:1.** All chats are visible to everyone; no permissions; anyone can create a chat and write in any chat; there is no "join" flow; chats are never deleted. Signal mechanics tied to a fixed 1:1 audience (delivered/read receipts, membership, per-chat subscriptions) are deliberately dropped or reinterpreted.
- **Two-layer identity.** A technical anonymous **identifier** (shown as `Your ID`, a long key-like string entered by paste or QR — no phone/email) plus a public **label** (display name). Server assigns `User<random>` at first login (a name always exists); label is ≤32 chars, charset `[A-Za-z0-9._-]`. Global case-sensitive uniqueness is a **requirement that stage 1 does not enforce** (owner, 2026-09-02): the server neither checks nor reports it, nothing in the app asks, and it closes at stage 2 where pairing assigns labels — so do not add a client-side uniqueness check for a person's name. One identity per device; switching = Logout (full local wipe) + re-login.
- **Message status is local-only:** `sent` (accepted by server) + `pending`/`error`; **no delivered/read** (no fixed recipient in an open space).
- **Shell:** 3-item bottom bar — `Chats` tab, central docked **`+`** FAB (create chat, visible on both tabs), `Settings` tab. **No profile screen** — profile-like items live in Settings.
- **Theming:** Material Design 3, light + dark via `ColorScheme` (default system), seed = teal extracted from the logo. Two brand-fixed exceptions independent of theme: splash background always dark, QR surface always light.
- **Chat name:** globally unique, ≤64 chars, unrestricted charset. Chat avatars are generated (initials + hash-picked color from a fixed palette).
- Explicitly **out of scope** this iteration: calls, reactions/stickers, voice messages, stories, mentions/threads, profile screen, moderation/permissions/owners, multi-account, delivered/read, per-chat mute/pin, Support section. **File previews are partly IN scope since 2026-07-26** (owner revision, feature 020 / tracker item F4): image attachments with a real local file render an inline thumbnail + tap-to-full-screen; every other type — and images with no local file — keeps the type-icon chip. `overview.md` still carries the un-revised "type-icon chips only" sentence in its out-of-scope list; the revision wins.

## Flutter architecture blueprint (`docs/blueprints/mobile/`) — unified & adopted

The adopted architecture for NOX's Flutter app (package `nox_app`, single app id `com.cyphernetlabs.noxapp` on all five targets — per-flavor native ids/signing are deferred, the flavor is a Dart-define only). Load-bearing decisions: **one Dart package**, Clean Architecture layers as folders (`presentation → domain ← data`, `domain` imports nothing); **BLoC = Freezed** (`@freezed` State/Event, thin `BaseBloc`, computed logic in extension getters or class-body getters, no `*.g.dart` on BLoC types); single **injectable + get_it** DI (`configureDependencies(env)`); `RepositoryResult<T>` (success XOR error) everywhere; mandatory `LogRepository` (no raw `print`); **Sembast** cache-first reactive repositories; `infinite_scroll_pagination` v5 (`PagingState`-in-bloc); design-token-only UI; FVM-pinned Flutter `3.44.1`, line length 140, stock `flutter_lints`; codegen-first (freezed + json_serializable + injectable + flutter_gen, one `build_runner` run).

> **Rule: at the start of any Flutter/client task, consult the relevant blueprint doc(s) (`README.md` index → layer docs `00`–`17`) and build to them.** If real code drifts from the blueprint, bring the blueprint back to a correct state in the same change-set. **Caveat:** the blueprints were reconciled with contract v0 in feature 025 (pagination, envelope, error codes, the file chain), but the parts that depend on **stage-2 authentication**, push delivery and deep links in `13`/`14`/`15` are still explicit placeholders — those questions are genuinely open.

### Implementation notes — data layer & DI (real `lib/`, beyond the blueprint prose)

- **File chain (028).** `FileRemoteDataSource` splits the two transports the contract splits: `file.uploadBegin`/`file.downloadBegin` go over the socket, the BYTES over HTTP through `ApiClient` — the first real consumer of Dio in the project (`initBase()` had never been called from app code before). `FileRepositoryImpl` returns the server's `fileId` **only after the bytes are confirmed**, spends one automatic second chance on a rejected pass itself (a pass is one-shot and 10-minute-lived, and the contract calls a refusal routine), and caches downloads under `getApplicationCacheDirectory()/nox_attachments/<fileId>`. Its failure classification is deliberately NOT the drain's: a `404` on `/files/<token>` means "get a new pass", while the general Dio mapper would make it `notFound` → terminal → a message killed for good. `OutboxEntity.fileId` is the restart guard; `AttachmentPrefetchService` fetches received IMAGES only (the design corpus draws a thumbnail only for an image with a local path) and keys a `_handled` set so writing the path cannot re-trigger the watch that led there. `FileViewPage` owns a `FileViewBloc` since this phase — blueprint 05 ends the BLoC-less carve-out with the client track by name.
- **Live-path truth (031).** Three decisions that used to be taken locally now come from where they belong. **Onboarding** is decided by the server: the greeting carries `identity.created`, and sign-in stores the identifier, greets, takes the outcome, then moves navigation — in that order, because storing first is what makes the greeting state a person rather than going out anonymously. A handshake that does not answer **rolls the session back**; a stored identifier with no settled outcome would strand the next launch in onboarding. The local flag is **monotonic**: a greeting may declare onboarding done and may never send someone back to it, which is what saves a device left on the naming screen while the same person named themselves elsewhere. `LiveIdentityHandshake` owns the wait and its own timer — an outer `.timeout()` does not cancel its source, so the `finally` never runs and sign-in wedges for the process. It also captures `NoxSocketClient.greetingGeneration` BEFORE restarting and accepts only an answer above it: `phase` is a `BehaviorSubject`, so a fresh listener is handed the CURRENT phase, and the app's own boot greeting is anonymous with `created: true` — reading that would route every returning person into onboarding. The greeting-driven onboarding advance is refused while `noteOnboardingStartedHere()` is set (in memory, per process): a reconnect mid-naming reports the person's own brand-new row back as `created: false`, and the mark deliberately dies with the process, because after a restart the naming screen is exactly what a greeting should rescue. **Names:** chat-name availability is the server's answer alone, and a person's name is never refused as taken (labels are not unique, owner 2026-09-02) — `UsernameStatus.taken` and `SettingsNameStatus.taken` no longer exist, and neither does their `checking`: 2.3 and the 7.1 inline edit judge a name the moment it is typed, with no debounce and no suffix spinner, because there is nothing to ask. The two chat-name blocs keep theirs — that check is a real query against the local store, with the server deciding on create. A failed sign-in rolls back through `discardSignIn()`, deliberately narrower than `clear()`: the device id names the install and must not rotate because a greeting never arrived. **Unread** is a recount, never a counter: `ChatEntity.lastOpenedSeq` is the mark (`required int?`, so the compiler forces every construction site to decide; `null` = never opened = no badge, and `-1` not `0` is the DAO's floor so "opened with an empty cache" stays distinguishable). `_withRecountedBadges` is the ONE place a badge is produced and both read paths go through it — the stored `unreadCount` column is vestigial and read by nobody. It counts the whole list in ONE pass (`MessageDao.countUnreadByChat`); a per-chat count decoded the entire message store once per chat, on the UI isolate, on every watch tick. Own messages drop out by excluding the whole set of ids this device could have stamped, because the identity resolver falls back to the login identifier and a single-value comparison fails open there.
- **Pairing (032).** The server checks who connects. `device_key` is an Ed25519 **public key**, `signature` over `"nox/challenge/v1:" ‖ challenge` (RAW bytes, prefix for domain separation) is verified on every greeting, and the person is found by that key — `login_ref` is gone from the wire, the lookup and the schema. A greeting can no longer create anyone: an unknown key gets `unauthenticated`, which the client treats **exactly as a revocation** (forced logout back to the pairing screen), because a revoked device and one facing a rebuilt store are indistinguishable and must behave the same. People come into being only through `pair` (contract §8A), the one command allowed before a greeting. Load-bearing decisions that are easy to undo: the server's private key lives **inside the database file** (case 6 of the model warns a DB-only backup breaks pinning for every device; one artifact makes that impossible); revocation **deletes** the device row rather than flagging it (a third state would have to be checked at every lookup, and deletion buys the indistinguishability above for free); the claim token has **no expiry** (it dies by being used, and an expiring one would leave a forgotten server unclaimable), while device invites live 10 minutes; token burning is a conditional `UPDATE … WHERE used_at IS NULL` whose affected-row count settles a two-device race. The address to connect to comes from the **pairing link**, stored with the session — `AppConfig.apiUrl` is now only a fallback, and the world epoch is keyed on the stored address. `identity.setLabel` replaced the rename-by-reconnect workaround, so `session.label_dirty` is gone. The Ed25519 vector is pinned in contract §3 and tested on **both** sides.
- **Server identity (030).** The greeting resolves a person and a device instead of taking a name at face value. `login_ref` (lowercase-hex SHA-256 over `nox/login-ref/v1:` + the login identifier, formula and test vector pinned in contract §3) names the PERSON, `device_key` names the install; the raw identifier never reaches the wire and the server never hashes anything. `messages.author_id` carries the server-minted `u_` id and `author_label` is a frozen copy of the name at send time. Three rules are load-bearing and easy to undo by accident: (1) the **label is stated only after a rename** (`session.label_dirty`, cleared when the server echoes it) — repeating a cached name on every greeting makes two devices of one person flip-flop; (2) all three own-vs-other sites use the person id together, or the author loses their own `client_message_id` and a restart-interrupted send shows twice; (3) the server names its store with `journal_id` and **any change wipes the local world**, including `session.author_id` — keying on the cursor alone cannot see a store rebuilt past the client's mark. Renaming in Settings calls `LiveSessionStarter.restart()`, because a name only reaches the server in a greeting.
- **Outgoing queue (027).** `OutboxDao` owns a Sembast store `outbox` whose **record key IS the `client_message_id`**, so re-enqueuing the same send cannot create a second row. Order comes from an `ordinal` assigned inside the enqueue transaction — never from `createdAt`, which goldens freeze. `OutboxService` (`lib/data/sync/outbox_service.dart`) is the **only** thing in the app that calls `sendMessage`: passes are serialised on a `Future _queue`, run strictly in `ordinal` order one at a time, and delete a record only **after** the repository persisted the message. Failures are classified — `connection`/`rateLimited`/`internal`/unrecognised retry with `min(30s, 1s × 2^(attempts−1))` ±20% jitter; everything else is terminal (`error`) and the pass continues past it. The record carries **two** counters: `attempts` (any failure, drives the pause) and `refusals` (the server actually answered, and only this one may spend the 10-retry cap — counting a dead channel would strand a healthy message on a flaky link). A manual retry resets both. The pause is keyed to the entry it is waiting out, so discarding or settling that entry releases the queue. `ChatThreadBloc.outgoing` is a **projection** of `watchQueue(chatId:)`, not state it owns; it re-reads the cache only on a tick where the queue SHRANK (the one tick where a message was just persisted). Logout stops the drain, then wipes the store with the chats and messages — the rows hold message texts.
- **Cache-first is real.** `ChatRepositoryImpl` (+ `ChatDao`) and `MessageRepositoryImpl` (+ `MessageDao`) seed the Sembast store **once** from the remote data source when it is empty, then serve and write list/search/pagination/create/rename/send/unread entirely locally. `AppDatabase` is per-env: `app.db` / `app_dev.db` on disk (`databaseFactoryIo`), in-memory `app_test.db` (`databaseFactoryMemory`) under `Environment.test`. `ItemRepositoryImpl` is the **only** remaining network-only repository, and `ItemDao` is referenced only by its own test.
- **Sembast `field_rename: snake` gotcha (real).** `build.yaml` sets json_serializable `field_rename: snake` globally, so records persist camelCase fields as snake_case (`chatId` → `chat_id`). A `Finder`/`Filter` on a camelCase key **silently matches nothing**. Both DAOs work around it by record-key `get`/`onSnapshot` or by filtering in Dart over decoded entities — keep new queries on one of those two paths.
- **Remote seam (016) — the flip already happened, and in the other direction.** Repositories depend on `ChatRemoteDataSource` / `MessageRemoteDataSource` / `FileRemoteDataSource` / `ItemRemoteDataSource`, never on a concrete source. Since feature 026 the **real** impls hold `env: [Environment.dev]` and the **mocks** hold `[Environment.prod, Environment.test]` — so the live server runs on the `stage` flavor (`Environment.dev`) and `prod` is still the mock world until a production address exists. `ItemRemoteDataSource` is the exception, mock in all three. Anyone reasoning from the old description (mock everywhere, real arriving on `prod`) will build the wrong mental model of what talks to the server.
- **Wire envelope (018).** Every remote call returns `ResponseEntity<T>` whose `data` is resolved by the hand-maintained `EntityConverter` registry — a new entity reachable through the envelope MUST be added to **both** the `fromJson` and `toJson` chains or it throws `ArgumentError`. Wire DTOs (`lib/data/entity/chat/wire/`, explicit snake_case `@JsonKey`) are **distinct** from the Sembast storage entities (`ChatEntity`/`MessageEntity`); `*WireMapper` converts wire↔domain, `*Mapper` converts storage↔domain. Repositories unwrap through `BaseRepositoryHelper.unwrapEnvelope` (025): a typed `error {code, message}` becomes `RepositoryException.fromWireCode(code)` (unknown code → `internal`) and passes through `execute()` unchanged via its `on BaseRepositoryException` branch; a `data == null` success still throws `StateError` → `unknown`. `MessageAttachment.localPath` is persisted but deliberately absent from the wire DTO, so `sendMessage` re-attaches it onto the server echo before persisting.
- **Auth seam (019): the URL landed with the transport in 026; the token is still plumbing** (its writer arrives with stage-2 auth). `AppConfig.apiUrl` carries the dev server address, and since 028 `ApiClient.initBase()` IS called from `main.dart` — the file chain's byte transfer is the REST surface Dio was always held in reserve for. Commands still travel the socket; Dio carries only blobs. `AuthInterceptor` adds `Authorization: Bearer <token>` from `AppConfigRepository.getUserAuthIdToken()` (secure key `auth_id_token`, **no writer exists yet**) and on 401 calls `authRepository.logout(forced: true)` through the lazy alias (this breaks the `ApiClient → AuthInterceptor → AuthRepository → repositories` DI cycle), always re-propagating the error.
- **Error semantics.** `BaseRepositoryHelper.execute` catches everything, always logs via `logRepository`, and has **four** branches: `BaseRepositoryException` is re-emitted unchanged (this is how wire codes survive, 025), `SocketUnavailableException` → `connection` (026 — without it a dead channel lands in the catch-all as `unknown` and every cache fallback guarded on `connection` is unreachable code), `DioException` is mapped (timeouts/`connectionError` → `connection`; 401 → `unauthenticated`; 403 → `authentication`; 404 → `notFound`; else `internal`), everything else → `RepositoryException.unknown`. The never-throws guarantee covers **only** methods wrapped in `execute` (those returning `RepositoryResult<T>`); `Future<void>` and `Stream` members bypass it and propagate raw — which is why `ChatRepositoryImpl.createChat` wraps `seedCreatedChat` in its own try/catch and `watchChats()` can surface a failed seed as a stream error. `execute` takes an untyped `Function`, so a wrong-typed return is a runtime `TypeError` silently downgraded to `unknown`.
- **Session/identity storage.** Identifier → `flutter_secure_storage` (`session.identifier`); `session.onboarding_complete` + `session.label` → `SharedPreferences`; nothing session-related in Sembast. `saveIdentifier` writes prefs **first** and the secure identifier **last**, because `readSession()` keys presence on the identifier.
- **Unified identity (015).** `resolveIdentity(SessionModel?)` (`lib/general/identity/identity_resolver.dart`) is the single pure resolver of own-id/label (fallbacks `IdentityMockData.fallbackOwnId` / `Constants.defaultUserLabel` = `User7421`); it feeds own-message authorship, the Settings account row and the chat thread. `SessionRepository.watchLabel()` returns a **fresh single-subscription stream per call** (an `async*` generator over an internal broadcast controller): it yields the cached label on listen, then each rename, then `null` on logout. Call it once per consumer — re-listening to the same instance throws. Today the sole subscriber is `TabBarShell`, which feeds both account avatars. `MessageRepositoryImpl` **refuses to seed** a chat's mock history when `readSession()` errors, because seeded own-author rows are permanent for the life of the local DB.
- **Logout wipe.** `AuthRepositoryImpl.logout({forced})` gates on a successful `SessionRepository.clear()` (secure `deleteAll` + remove the two prefs keys), then wipes — **in this order** — the sync cursor (`SyncRepository.clear()`, first so a crash can never leave a stale high `since` over an emptied store), then the Sembast chats + messages stores, then the outbox, then re-derives app state. `LiveSessionStarter.stop()` and `OutboxService.stop()` both run BEFORE the wipe so nothing in flight repopulates a store being emptied. It does **not** delete the database file; settings prefs (`settings.theme_mode`, `settings.notifications_enabled`, `ui_language`) survive logout.
- **App state.** `AppStateRepositoryImpl` is an rxdart `BehaviorSubject` projection with no DAO; on a session **read** error it preserves the last emitted state (only a cold start falls back to `unauthorized`), so a transient keychain failure never logs a valid user out.
- **DI bootstrap order (enforced in `lib/main.dart`):** `configureDependencies(env)` → `getIt.allReady()` → `getIt<AppConfigRepository>().initialize(flavorType:)`. `RegisterModule` provides `FlutterSecureStorage` (macOS pinned to the legacy keychain via `MacOsOptions(usesDataProtectionKeychain: false)`), `@preResolve`d `SharedPreferences`, and an env-keyed `@Named('isTestEnvironment')` bool. Cross-cutting singletons are reached via top-level getters in `lib/di/global_aliases.dart` — `logRepository`, `itemRepository`, `settingsRepository`, `chatRepository`, `appStateRepository`, `authRepository`, `sessionRepository`, `cameraPermissionService`, `notificationPermissionService`, `qrImageDecodeService` — while BLoCs typically resolve their own dependencies with `getIt<X>()` field initializers. Neither path uses constructor injection. Two abstractions have a genuinely env-split binding: `AppDatabase` and `ConnectivityService` (real `connectivity_plus` for `[dev, prod]`, always-online mock for `[test]`, because the plugin needs a platform channel) — any new plugin-backed service must follow the same split or widget/BLoC tests break.
- **`AppClock.now()`** (`lib/general/app_clock.dart`) is the app-wide clock seam used by the mock generators and by repository writes; tests and goldens pin it with `AppClock.freeze()` / `reset()`.
- Stale doc-comment inside the code: `lib/domain/repository/chat/chat_repository.dart` still describes the chats list as network-only. Trust the impl; fix the docstring when next touching it.

### Implementation notes — presentation layer

- **No router.** `MaterialApp` sets only `home: const SplashPage()`; there is no route table, no `onGenerateRoute`, no router package. Every navigable page exposes `static Route<T> route()` returning a `MaterialPageRoute` with a named `RouteSettings`, and callers push the tear-off; 12 of 21 also expose a `routeDemo()` gallery variant. Adding a screen = adding its `route()` plus, for the gallery, a `_ScreenEntry` row in `ScreensGalleryPage`.
- **Navigation spine.** `AppRoot` swaps the **root** route from `AppRootState.appliedAppState.state`: `unauthorized` → `LoginPage`, `registrationPending` → `SetUsernamePage`, `authorized` → `TabBarShell`, `init` → stay on Splash. The **first** transition uses `pushReplacement`, every later one `pushAndRemoveUntil(route, (_) => false)` — no auth boundary is back-navigable. The first resolved state is deliberately **held**: `AppRootBloc._land` only records it, and `SplashPage` dispatches `ApplyAppState` once its reveal animation finishes and `isReady` is true. `AppRoot` also owns two app-wide transient notices (session-expired snackbar; settings-save-error snackbar driven by the `settingsSaveErrorTick` counter).
- **Responsive convention.** `LayoutBuilder` + `constraints.maxWidth >= Constants.railBreakpoint` (840) selecting `_narrow`/`_mobile` vs `_wide`/`_desktop`. A page hosted as a **shell tab** must instead honour `forceWide` (`widget.forceWide ?? (constraints.maxWidth >= railBreakpoint)`) — the rail narrows the body, so self-measuring lands on the wrong branch in the 840…rail band. Callback-side helpers that cannot use a `LayoutBuilder` (`showAdaptiveLightbox`, `showChatCard`, `ChatsListPage._onOpenCreated`) branch on `MediaQuery` width against the same constant.
- **Desktop replaces push with selection.** 5.1 dispatches `ChatsListEvent.chatSelected(id)` when wide (mobile pushes `ChatThreadPage.route`); 7.1's menu pane sets `_selected` via `setState` (mobile pushes the leaf `*Page.route()`). `AppListDetailWidget` is the shared two-pane container and never touches the Navigator. Overlays follow the same rule: chat card → right side-sheet vs push; file view / image viewer → `showAdaptiveLightbox` (Dialog vs push); create chat → `CreateChatPage.showAsDialog` vs `route()`.
- **The live shell is `TabBarShell`** (`lib/presentation/widgets/shell/tab_bar_shell_widget.dart`). Narrow: `AppBottomBarWidget` + center-docked `AppCreateFabWidget`. Wide: `AppWindowTitlebarWidget` (subtitle tracks the active tab) over `AppNavigationRailWidget` — a **hand-built 80dp rail, explicitly NOT Material's `NavigationRail`**: painted right hairline, rounded-square create FAB, two `Semantics(button, selected)` cells, `Spacer()`, then `_NavRailAccountAvatar`. Both tabs stay mounted in a `Stack` of `IgnorePointer` + `AnimatedOpacity` so tab state survives switching. The shell holds a live `sessionRepository.watchLabel()` subscription feeding **both** account avatars (desktop rail + the mobile Chats app-bar action), and owns three `ValueNotifier` signals into the tabs: `_chatsScrollToTop`, `_settingsJumpToAccount`, `_chatsOpenCreated`.
- **Reactive data flow (014/015).** `ChatsListBloc` and `ChatThreadBloc` each hold a `watchChats()` / `watchMessages(chatId)` subscription with `.skip(1).debounceTime(100ms)`; the stream **value is ignored** — a tick dispatches a `refresh: true` load that re-reads through `getChats`/`getMessages`, so the repository query stays the single projection path and query/selection/scroll/optimistic `outgoing` survive. The re-read differs by path (025): the chats list walks pages 1..`loadedPageCount`; the thread does ONE tail read of `items.length + pageSize` (the cursor has no page numbers). Both also watch `connectivityService.watchOnline()` for the offline banner (the thread flushes its pending send queue on the offline→online edge). `WatchChat` (`widgets/chat/watch_chat.dart`) is the single seam for live single-chat data (thread title, card title/header, desktop thread header) so a rename propagates everywhere without a reload.
- **BLoC discipline.** Repository calls returning `RepositoryResult` never throw, so blocs `await` them bare and use `result.match(onData:, onError:)`. `BaseBloc.executeLogic` is reserved for handlers running raw async work (delays, pickers, multi-step loads) — **never call it without `onError`**: it catches everything and, with no callback, neither emits nor rethrows. Transformers in use: `bloc_concurrency` `sequential()` on paginated loads and on the thread's `ConnectivityChanged`, plus a project-local `debounceRestartable([300ms])` (`lib/presentation/base/bloc_transformers.dart`) on search and name-availability checks.
- **Two Freezed state shapes coexist** — follow the neighbouring page rather than assuming one style. Paginated/loading screens use `@freezed sealed` unions (`Initializing`/`Initialized`/`Error`) with computed logic in an extension on the substate; form screens use a single-factory `@freezed abstract` value state with a private `const X._()` and computed getters in the class body.
- **Pagination.** The chats list uses `infinite_scroll_pagination` v5 (`PagedListView` + `fetchNextPage`); the chat thread does **not** — it renders a `reverse: true` `ListView.builder` and prefetches older history from a `ScrollController` listener at a 200px threshold, while still keeping a `PagingState` in its bloc state. `PagingStateExt.applyPage` (`lib/presentation/pagination/paging_state_ext.dart`) is the only place a v5 `PagingState` page-fold is assembled.
- **Reusable seams — reuse, do not re-roll.** From feature 021: `AppBannerShellWidget` (base of `AppNoticeStripWidget` + `AppInfoBannerWidget`), `showAdaptiveLightbox` (base of `showFileView` + `openImageViewer`), `AppOnboardingScaffoldWidget` + `AppPrimaryButtonWidget`, `AppRingedAvatarWidget`, `AppHairlineDividerWidget`, `WatchChat`, `AppThreadViewWidget._attachmentPreview` (the one attachment renderer shared by bubble and composer draft), the shared `_devMenuRows()`, `AppDevScenarioDropdown`. Predating 021 but equally load-bearing: `AppListDetailWidget`, `AppPanelHeaderWidget`, `AppSideSheetPanel`/`showRightSideSheet`, `AppDetailScaffoldWidget`, `showAppSnackBar`/`showAppBanner`.
- **Settings/legal leaves are split** `*Body` (chrome-less) + `*Page` (`AppDetailScaffoldWidget` wrapper), precisely so the same body fills the desktop Settings detail pane — add a new settings section as a Body first.
- **Dev surfaces.** Settings exposes three `kDebugMode`-only rows, built once by `_devMenuRows()` and appended to **both** the mobile flat list and the desktop menu pane: `Screens gallery (dev)` → `ScreensGalleryPage`, `UI kit (dev)` → `UiKitPage`, `Force logout (dev)`. The old `HomePage` launcher still compiles but is **referenced by no production code**. `AppShell` + `ItemListPage` (feature 001) remain dead verification code.

In the **real** (non-demo) flow `LoginBloc` never emits a `nav*` status — it awaits `authRepository.signIn` and lets the app-state spine navigate; the `navNewId`/`navRegistered` branches only run in gallery demo mode (`SetUsernameBloc` is the same, except a failed `completeOnboarding` does emit `navFatal`).

### Implementation notes — design & theme

- **`lib/design/theme/` holds nine files.** Generated from the DTCG tokens (regenerate, do not hand-edit): `nox_color_scheme.dart` (hand-tuned light+dark `ColorScheme`, seed teal `0xFF12B4B4` — never `ColorScheme.fromSeed`), `nox_text_theme.dart` (9-role `TextTheme`, fixed design px), `nox_tokens.dart` (`NoxSpacing`/`NoxRadius`/`NoxElevation`/`NoxDuration`/`NoxEasing`). **Hand-maintained — never overwrite from the handoff:** `app_theme.dart`, `app_colors.dart`, `nox_component_themes.dart` (18 stock-M3 sub-themes following `nox-handoff-2/spec/components.md`, deliberately diverging from the reference `nox_theme.dart`), `nox_opacity.dart`, `nox_scrims.dart`, and `nox_brand.dart` (generated base **plus the hand-added `noxAccountInitials`** — a blind regeneration deletes it and breaks the account avatars).
- **`AppColors` (ThemeExtension) is still the 2-field skeleton** (`surfaceMuted`, `dividerSubtle`) and is effectively **dead**: `context.appColors` has zero call sites outside its own file and `AppTheme`. Take semantic color from `Theme.of(context).colorScheme`, `NoxBrand`, `NoxScrims` and `NoxOpacity`. A full token-driven palette is unshipped debt with no owner — do not plan around it.
- **Color literals.** Hex `Color(0x…)` literals belong in `lib/design/theme/` (plus `lib/design/app_overlay_style_tokens.dart`); the only other one is the offscreen canvas fill in `qr_image_decode_service_impl.dart`. Named `Colors.transparent` / `Colors.white` remain acceptable in presentation (avatar initials, selection fills).
- **`AppTheme.light()/dark()` are built fresh on every call — never cache them.** The sub-themes read ScreenUtil-dependent tokens, and `Theme.textTheme` deliberately stays the fixed-px `noxTextTheme`; responsive text is opt-in through `AppTextStyleTokens`.
- **Responsive token stack (three layers, all outside `theme/`).** `AppSpacingTokens` is the raw ramp, scaled by the mean of the width/height ScreenUtil factors **clamped to 0.85–1.2**; `AppDimensionTokens` is the semantic layer (every `space`/`radius`/`border`/`icon`/`size` role references a spacing step by name) — prefer the semantic roles. `AppDimensionTokens.layout.*` is the deliberate exception: **unscaled** design-px content-width caps (dialog 460, side sheet 380, settings column 680, thread reading column 980, chats list pane 360, …).
- **Every `ScreenUtilInit` — app and test harness alike — MUST pass `fontSizeResolver: AppTextStyleTokens.fontSizeResolver`.** It clamps `.sp` to 0.90–1.00 (ceiling 1.0, so type never grows on wide windows). Without it, screenutil's unbounded width-only default renders `16.sp` at ~64dp in a 1440-wide window. `AppTextStyleTokens` factories set **no** `height` and no `fontFamily` — text needing the design line-height must come from `Theme.of(context).textTheme.<role>`; the sole exception is `monoBody` (Roboto Mono, for the long identifier string).
- **`NoxOpacity`** (021) tokenizes the *shared* alpha values applied to `ColorScheme` colors: `scrim` 0.5 (all modal barriers), `disabled` 0.38, `ring` 0.06 — 6 call sites. It is not yet exhaustive: a handful of one-off raw alphas survive (`language_body` 0.1, `app_file_chip_widget` 0.12/0.7, `app_message_bubble_widget` 0.7, `app_image_attachment_widget` 0.6, `app_file_glyph_widget` 0.14). **`NoxScrims`** (009) is unrelated: brand-fixed, theme-invariant black scrims used **only** over the live QR camera feed. New code reaches for a token before writing a raw `withValues(alpha:)` number.
- **Assets go through codegen.** `lib/design/gen/assets.gen.dart` is gitignored `build_runner` output, and `test/design/single_channel_guard_test.dart` hard-fails if any `lib/` file outside `design/gen/` carries a raw `'assets/…'` string — always use `NoxIcons` / `Assets.*`.
- **Rules set by the 2026-08 `design-visual-audit`** (22 fixes, `lib/`-only): the segmented control is a full `StadiumBorder` pill; the desktop side sheet is `NoxElevation.level3` + a 1px foreground `outlineVariant` left hairline; `AppPanelHeaderWidget` owns its bottom hairline and switches `titleLarge`/`titleMedium` via `largeTitle`; `AppWordmarkWidget` defaults to `titleLarge`/0.12em with overrides at 28 (splash) and 13 +0.14em (desktop titlebar); `AppSplashHairlineWidget.gradient` is public so the onboarding accent pill reuses the exact brand ramp. **Two findings are deliberately NOT implemented — do not "fix" them:** settings nav rows stay icon-less (locked spec, owner decision), and the ON-switch check glyph is skipped because `thumbIcon` requires a Material `Icon` while NOX is SVG-only (it renders as tofu). Note this branch changed **no** `docs/` file, so `docs/design/spec/` and the screens corpora still carry the pre-audit descriptions — reconciling them is open work under Principle II.

Re-enable by restoring the triggers in both workflow files.

**Daily commands (prefer the `Makefile` targets):**
- `make gate` — the end-of-task gate: `generate` → `format` → `analyze` → `test` (goldens excluded). Run before declaring work done.
- `make deps` (`pub get`); `make generate` = `build_runner build --delete-conflicting-outputs` **then** `fvm flutter gen-l10n` (the generated `AppLocalizations` is gitignored, so it must be regenerated after any ARB change or on a fresh clone — otherwise `analyze`/`test` fail on unresolved `AppLocalizations`); `make analyze` (zero-errors gate).
- `make test` → `flutter test --exclude-tags golden`. **Single test/dir:** `make test FILE=test/path/x_test.dart` (raw form: `fvm flutter test <path>`).
- **Format:** per-task use explicit paths — `fvm dart format -l 140 <changed paths>`. `make format` is a **bulk** `lib test` sweep used by `make gate`. `analysis_options.yaml` sets `formatter: page_width: 140`, so a bare `dart format` / IDE format-on-save already matches.
- **Run the app:** `fvm flutter run --dart-define-from-file=config/stage.json` (or `config/prod.json`); desktop needs an explicit device: `-d macos|windows|linux`. The only entrypoint is `lib/main.dart`.
- **Builds** wrap `mise`: `mise run build:<platform>:<stage|prod>` for android/ios/macos/windows/linux (all `--debug`). The `Makefile` wraps only `build-macos-stage|prod`, `build-windows-stage`, `build-linux-stage`. mise resolves Flutter through `.fvm/flutter_sdk/bin/flutter`, and `.fvm/` is gitignored — **`fvm use 3.44.1` must have run first on a fresh clone**.

**Flavors** are a compile-time Dart define: `--dart-define-from-file=config/<flavor>.json`, each file holding `{"app.flavor": "stage"|"prod"}`, read via `String.fromEnvironment('app.flavor')`. `AppFlavor.getFlavor()` maps empty/unknown → **prod** (safe default), and `main.dart` then picks `Environment.prod` for prod, `Environment.dev` otherwise — so a build with **no** define lands on `Environment.prod`. No native `--flavor`; no per-flavor app id.

**Golden tests** are plain-Flutter `matchesGoldenFile`, tagged `@Tags(['golden'])` (declared in `dart_test.yaml`), rendered/verified **locally only on Apple Silicon/macOS** and **excluded from `make test` and CI**. Verify with `make golden-verify`, regenerate with `make golden-update` (both accept `FILE=`). See *Testing*.

**CI** (`.github/workflows/`): `ci.yml` (`gate` job, macOS) mirrors `make gate` minus goldens — `pub get` → `build_runner` → `dart format -l 140 --set-exit-if-changed $(git ls-files lib test | grep '\.dart$')` → `analyze` → `flutter test --exclude-tags golden`. Because the format step enumerates via `git ls-files`, gitignored generated code can never trip it. `compile-check.yml` runs five per-platform `--debug` smoke builds against `config/stage.json` (the Linux job apt-installs `ninja-build libgtk-3-dev libsecret-1-dev libjsoncpp-dev`). **CI uses bare `flutter`/`dart` (subosito action), not `fvm`** — locally always use `fvm`.

**l10n:** `flutter: generate: true` + `l10n.yaml` (`arb-dir: lib/l10n`, template `app_en.arb`, class `AppLocalizations`, `nullable-getter: false`). UI strings resolve through `context.l10n` with live EN+UK switching (`LocaleController` → `MaterialApp.locale`); supported locales are exactly `en` and `uk`. `app_en.arb` and `app_uk.arb` each hold **140 keys with identical key sets** — a new string must land in **both**. `lib/general/text_constants.dart` no longer exists. ## Testing

Tests deep-mirror `lib/` under `test/` (not flat); BLoC tests live in the page's `bloc/` sub-folder. The team's test-generation conventions are the slash-command skills **`/bloc-test`, `/golden-test`, `/widget-test`**, sourced from **`.claude/commands/*.md`** (note: under `.claude/commands/`, **not** `.claude/skills/`, which holds `speckit-*`, `prepare-preview` and the Go-backend skills `go-style`/`ws-rest-patterns`/`add-command`/`migrations`). Read the relevant one before writing or updating a test.

- **Global bootstrap: `test/flutter_test_config.dart`** is auto-loaded by `flutter test` for the whole suite and installs in-memory mock backends for `SharedPreferences` and `FlutterSecureStorage`. Without it every test that calls `configureDependencies` fails, because the generated `$initGetIt` `@preResolve`s `SharedPreferences` over a platform channel. It does **not** build the DI container — tests do that themselves.
- **`pumpApp(tester, child, {themeMode, settle, textScale})`** is the mandatory canvas: `ScreenUtilInit(Constants.designSize, fontSizeResolver: AppTextStyleTokens.fontSizeResolver)` + `AppTheme.light()/dark()` + a textScaler clamp + a pinned `locale: Locale('en')` with the `AppLocalizations` delegates. Skip it and the spacing/text tokens fail to resolve and localized copy renders non-deterministically.
- **UI copy is asserted through a file-level `final l10nEn = AppLocalizationsEn();`** (`package:nox_app/l10n/app_localizations_en.dart`) — never raw literals, never the deleted `TextConstants`.
- **Golden harness (`test/utils/golden.dart`).** `goldenTest(name, build, {settle})` renders light+dark on the mobile design surface; `goldenTestDesktop(name, build, {settle, size})` does the same pinned to `kDesktopGoldenSize` (1280×800, dpr 2). Both **freeze `AppClock` at `kGoldenClock` = 2026-06-15 21:30** (with a reset tearDown), pin the surface by assigning `tester.view.devicePixelRatio` + `physicalSize` (**not** `setSurfaceSize`, which does not reach the MediaQuery ScreenUtil reads and would scale every token ~1.5×), load real Roboto via `loadNoxFonts`, and precache the brand logo inside `tester.runAsync` on settled screens (`pumpAndSettle` does not await async PNG decode, so a logo screen can otherwise snapshot blank). Use `settle: false` for animated content.
- **Reactive pages need a bespoke harness.** `chat_thread_page`, `chat_card_page` and `tab_bar_shell` cannot use the shared helpers: `watchMessages`/`watchChats` plus mock seed delays keep timers in flight, so `pumpAndSettle` hangs while `settle: false` snapshots the spinner. They mirror `golden.dart` but settle with bounded pumps (`14 × tester.pump(150ms)`) and do `SharedPreferences.setMockInitialValues({})` → `configureDependencies(Environment.test)` → `await getIt<AppDatabase>().clearEntireDatabase()` in `setUp` (the test DB is in-memory but **persists across tests in the same isolate**).
- **Three golden categories (project rule).** (1) **widget** goldens per `App*Widget`; (2) **page — mobile** for every `*Page` via `goldenTest`; (3) **page — desktop** for every *product* `*Page` via `goldenTestDesktop` → `goldens/<name>_desktop_<mode>.png`. Category 3 is **required for every product page** — it locks the desktop `_wide`/master-detail/window-titlebar branch the mobile surface cannot reach. Desktop-exempt today: the dev-only pages (`home_page`, `ui_kit_page`, `screens_gallery_page`), the brand-fixed `splash_page`, and the `theme_showcase` fixture. The desktop variant is **not** page-only — `app_message_bubble_widget_narrow_pane` and `tab_bar_shell_settings` are desktop baselines too. See `.claude/commands/golden-test.md`.
- **Baselines live beside their test** as `test/<mirrored path>/goldens/<name>_<mode>.png` (there is no repo-root `goldens/`); mismatch diffs go to a sibling `failures/` dir, gitignored via `**/failures/`. Current counts: **217 test files, 61 of them `*_golden_test.dart`, 216 committed baseline PNGs (62 of them `_desktop_`)**.
- **Golden coverage of functional states uses production test seams, not mocks:** pages accept `@visibleForTesting initialScenario` (`ChatsListScenario` / `ChatThreadScenario` / `ChatCardScenario`, plus `initialViewMode` / `initialSendText`) which seeds the debug scenario — `ChatCardPage` pins it at construction (`ChatCardBloc(initialScenario:)`, no re-init race), while `ChatsListPage` and `AppThreadViewWidget` queue a `SetScenario` event *after* the initial `Initialize`. That is how the `*_empty` / `*_offline` / `*_inline_error` / `*_fatal` / send-error baselines are produced.
- **Naming / tagging:** golden files are `*_golden_test.dart` and **must** carry `@Tags(['golden'])`; widget/unit tests are `*_test.dart` and **must not** (tagging silently drops them from CI). Test names are descriptive sentences, not `test_should…_when…`. Tagging is currently 100% consistent — keep it that way.
- **Widget tests pick the layout branch with `tester.binding.setSurfaceSize`** (narrow ~420×900, wide ~1200×900) + a tearDown reset — the golden helpers' `tester.view` pinning is not reused there.
- **Mocking: `mockito` only — `mocktail` is forbidden** (it exists solely as a transitive lock entry). Prefer the test-env DI (`configureDependencies(Environment.test)`, which serves mock data); use `mockito` only to force a path via `@GenerateMocks` + `getIt.allowReassignment = true` + `registerSingleton`, with `tearDown(getIt.reset)`. A stub whose return type is a generic `RepositoryResult<T>` needs `provideDummy<RepositoryResult<...>>(...)` in `setUp` before any `when(...)`. Hand-written fakes are an accepted alternative — `test/utils/fake_session_repository.dart` provides `kTestIdentifier`, `kTestSession` and `registerFakeSession()` (it implements only `readSession` + the 015 label channel; every other member throws).
- **BLoC tests** use `bloc_test`. Sealed-union blocs assert **bare** substate names (`isA<Initialized>()`/`Error`, never page-prefixed); single-class-state blocs assert with `predicate<XState>((s) => …)` on fields. Only assert an `Error` emission where the handler passed `onError` to `BaseBloc.executeLogic` (otherwise errors are swallowed by design). Product BLoC tests reset with the three-step `setMockInitialValues` → `configureDependencies(Environment.test)` → `clearEntireDatabase()` sequence.
- **Accessibility (FR-016)** is covered by two files: `test/presentation/widgets/accessibility_test.dart` (cross-widget) and `test/presentation/pages/m1_settings_accessibility_test.dart` (screen-level); both exercise `pumpApp(..., textScale: 2.0)` and assert ≥48×48 tap targets plus tooltips on icon-only actions.
